# 참고 자료 - 공식 문서부터 한국어 학습 자료까지

## 들어가며

Docker는 자료가 넘치지만 **오래된 자료가 특히 많은** 분야입니다. `docker-compose`(하이픈), `version: "3.8"`, `MAINTAINER` 같은 게 그대로 나오는 글이 검색 상단에 있습니다. 그래서 이 문서는

```
1. 공식 문서를 기준으로 삼고
2. 한국어 자료는 작성 시점을 함께 적어
3. 도구·생태계는 실제 유지보수되는 것만
```

정리했습니다. 이 문서의 링크는 모두 접속을 확인했습니다.

# 6. 오래된 자료를 걸러내는 법

검색으로 찾은 글이 지금도 유효한지 빠르게 판단하는 기준입니다.

```
🚩 docker-compose (하이픈)를 쓴다          → v1 시절 자료
🚩 compose 파일 맨 위에 version: "3.x"     → 레거시 (지금은 불필요)
🚩 Dockerfile에 MAINTAINER                 → LABEL maintainer 로 대체됨
🚩 docker build만 설명하고 BuildKit 언급 없음 → 2019년 이전
🚩 링크된 문서가 docs.docker.com/engine/reference/... → 구 URL 체계
🚩 M1/Apple Silicon 언급이 없는 macOS 설치 글 → 2020년 이전

✅ docker compose (공백), compose.yaml
✅ 멀티스테이지 빌드, --mount=type=cache / type=secret
✅ 멀티 플랫폼(buildx), healthcheck + condition
```

개념 설명(이미지·레이어·네트워크·볼륨)은 오래된 글도 여전히 정확합니다. **명령어와 파일 문법만** 공식 문서로 대조하면 됩니다.

## 정리

- 공식 문서(영문)가 기준. 한국어판은 없으므로 개념은 한국어 자료로, 정확한 옵션은 공식 문서로
- 한국어 입문은 subicura 안내서, 44bits 입문편, 생활코딩·얄코 무료 강의가 무난
- 2017년 전후 한국어 글은 개념은 유효하지만 명령어 표기가 옛날 방식임을 감안
- 도구는 dive(이미지 분석), lazydocker(TUI), Trivy(스캔), hadolint(린트)부터
- 다음 단계인 쿠버네티스는 공식 문서 한국어판이 잘 되어 있음
- `docker-compose`, `version:` 키가 보이면 오래된 자료라고 의심하기
