# 네트워크 기초 - 컨테이너끼리 어떻게 통신하는가

## 들어가며

컨테이너를 두 개 이상 띄우면 바로 이런 문제를 만납니다.

```
- 앱 컨테이너에서 DB 컨테이너에 어떻게 접속하지? localhost:5432 는 왜 안 되지?
- -p 8080:80 은 정확히 뭘 하는 걸까?
- 컨테이너에서 내 맥에서 돌고 있는 개발 서버를 부르려면?
- docker network 는 언제 만들어야 하지?
```

핵심 규칙은 하나입니다. **컨테이너 안의 `localhost`는 그 컨테이너 자신**입니다. 호스트도 아니고 옆 컨테이너도 아닙니다.

# 1. 포트 매핑의 원리

```bash
docker run -d --name web -p 18080:80 nginx:1.29-alpine
```

```
-p 호스트포트:컨테이너포트

     호스트(맥/리눅스)              컨테이너
  ┌──────────────────┐        ┌──────────────────┐
  │  localhost:18080 │───────►│  0.0.0.0:80      │
  │  (docker-proxy)  │        │  (nginx)         │
  └──────────────────┘        └──────────────────┘
```

```bash
docker ps --format '{{.Names}} | {{.Ports}}'
# web | 0.0.0.0:18080->80/tcp, [::]:18080->80/tcp

curl -s -o /dev/null -w '%{http_code}\n' http://localhost:18080
# 200
```

## 자주 하는 실수

```bash
# 1. 순서를 거꾸로 씀
-p 80:18080     # 호스트 80 → 컨테이너 18080 (nginx는 18080을 안 듣고 있음)

# 2. 앱이 127.0.0.1에만 바인딩됨
# 컨테이너 안에서 app.listen(3000, "127.0.0.1") 로 띄우면
# 컨테이너 밖에서는 절대 접속 안 됨 → 0.0.0.0 으로 바인딩해야 함

# 3. 포트가 이미 사용 중
docker: Error response from daemon: failed to set up container networking:
driver failed programming external connectivity on endpoint web:
Bind for 0.0.0.0:18080 failed: port is already allocated
```

## 포트 지정 방법들

```bash
-p 8080:80              # 호스트 8080 → 컨테이너 80
-p 127.0.0.1:8080:80    # 로컬에서만 접근 가능 (외부 노출 차단)
-p 8080:80/udp          # UDP
-P                      # EXPOSE된 포트를 랜덤 포트로 전부 매핑
```

> 공용 서버에서 `-p 5432:5432`로 DB를 띄우면 방화벽 설정에 따라 **인터넷에 그대로 열립니다**. 외부에 열 필요가 없으면 `127.0.0.1:5432:5432`처럼 바인딩 주소를 제한하세요.

# 2. 네트워크 드라이버

```bash
docker network ls
```

```
NAME      DRIVER    SCOPE
bridge    bridge    local
host      host      local
none      null      local
```

| 드라이버 | 설명 | 쓰는 곳 |
|---|---|---|
| `bridge` | 기본값. 가상 스위치를 만들어 컨테이너를 연결 | 대부분의 경우 |
| `host` | 호스트 네트워크를 그대로 사용, 격리 없음 | 리눅스에서 성능이 중요한 경우 |
| `none` | 네트워크 없음 (루프백만) | 네트워크가 필요 없는 배치 작업 |
| `overlay` | 여러 호스트에 걸친 네트워크 | Swarm/멀티 노드 |

## none 확인

```bash
docker run --rm --network none alpine:3.22 sh -c 'wget -qO- -T 2 http://example.com'
# wget: bad address 'example.com'
```

외부와 완전히 차단됩니다.

## host의 주의점 (macOS)

리눅스에서 `--network host`는 컨테이너가 호스트의 네트워크 스택을 그대로 쓰기 때문에 `-p` 없이도 포트가 열립니다. 하지만 **macOS/Windows에서는 다릅니다**. 컨테이너가 붙는 "호스트"는 Docker Desktop 내부의 리눅스 VM이라, 맥에서 곧바로 접근되지 않습니다.

```bash
docker run -d --name h --network host nginx:1.29-alpine
curl --max-time 5 http://localhost:80
# 연결 실패 (맥에서는 VM 내부 포트라서 보이지 않음)
```

macOS에서는 `-p`로 포트를 명시적으로 매핑하는 방식을 쓰세요.

# 3. 컨테이너끼리 통신하기

## 기본 bridge에서는 이름으로 못 찾는다

```bash
docker run -d --name api nginx:1.29-alpine
docker run --rm alpine:3.22 wget -qO- -T 3 http://api
# wget: bad address 'api'
```

기본 `bridge` 네트워크에는 **내장 DNS가 없습니다**. IP로는 되지만, 컨테이너 IP는 재시작하면 바뀌므로 쓸 수 없습니다.

## 사용자 정의 네트워크를 만들면 이름이 곧 주소

```bash
docker network create mynet

docker run -d --name api --network mynet nginx:1.29-alpine
docker run --rm --network mynet alpine:3.22 wget -qO- -T 3 http://api
```

```
<!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
```

```bash
docker run --rm --network mynet alpine:3.22 nslookup api
```

```
Name:	api
Address: 172.19.0.2
```

**사용자 정의 네트워크에 붙이면 컨테이너 이름이 DNS 이름이 됩니다.** Docker 내장 DNS(127.0.0.11)가 이름을 IP로 바꿔주고, 컨테이너가 재시작되어 IP가 바뀌어도 이름은 그대로입니다.

이것이 "실무에서는 항상 사용자 정의 네트워크를 쓰라"고 하는 이유입니다. Compose를 쓰면 프로젝트마다 네트워크가 자동으로 만들어져서 서비스 이름으로 통신할 수 있습니다.

## 앱 → DB 연결 예시

```bash
docker network create appnet

docker run -d --name db --network appnet \
  -e POSTGRES_PASSWORD=devpass postgres:17-alpine

docker run -d --name app --network appnet \
  -e DATABASE_URL="postgres://postgres:devpass@db:5432/postgres" \
  -p 3000:3000 myapp
```

```
연결 문자열의 호스트가 "localhost"가 아니라 "db" (컨테이너 이름)
포트도 호스트 매핑 포트가 아니라 컨테이너의 실제 포트(5432)
```

| 어디서 접속하나 | 주소 |
|---|---|
| 같은 네트워크의 다른 컨테이너 | `db:5432` |
| 호스트(맥/PC)의 DB 클라이언트 | `localhost:5432` (단 `-p 5432:5432` 필요) |
| 컨테이너 안에서 자기 자신 | `localhost:5432` |

## 네트워크 들여다보기

```bash
docker network inspect mynet --format '{{.Driver}} | {{range .IPAM.Config}}{{.Subnet}} {{.Gateway}}{{end}}'
# bridge | 172.19.0.0/16 172.19.0.1

docker network inspect mynet --format '{{range $k,$v := .Containers}}{{$v.Name}} {{$v.IPv4Address}}{{end}}'
# api 172.19.0.2/16
```

기존 컨테이너를 네트워크에 붙이거나 뗄 수도 있습니다.

```bash
docker network connect mynet 컨테이너이름
docker network disconnect mynet 컨테이너이름
```

## 네트워크 별칭

```bash
docker run -d --name api --network mynet --network-alias backend nginx:1.29-alpine
# api 로도, backend 로도 접근 가능
```

# 4. 컨테이너에서 호스트로 접근하기

컨테이너 안에서 호스트(내 맥)에서 돌고 있는 서버를 부르고 싶을 때가 있습니다. 컨테이너의 `localhost`는 컨테이너 자신이므로 다른 주소가 필요합니다.

```bash
docker run --rm alpine:3.22 getent hosts host.docker.internal
# 192.168.65.254    host.docker.internal
```

```bash
# 컨테이너 → 맥에서 돌고 있는 3000번 개발 서버
docker run --rm alpine:3.22 wget -qO- http://host.docker.internal:3000
```

| 환경 | 방법 |
|---|---|
| Docker Desktop (macOS/Windows) | `host.docker.internal` 바로 사용 가능 |
| Linux | 기본 제공 안 됨 → `--add-host=host.docker.internal:host-gateway` 추가 |

```bash
# 리눅스에서
docker run --rm --add-host=host.docker.internal:host-gateway alpine:3.22 \
  wget -qO- http://host.docker.internal:3000
```

# 5. 네트워크 설계 패턴

## 서비스별로 네트워크 분리

```
        ┌──────────── frontend 네트워크 ────────────┐
        │   nginx  ←→  web-app                      │
        └───────────────────┬───────────────────────┘
                            │ (web-app은 두 네트워크에 모두 연결)
        ┌───────────────────┴─── backend 네트워크 ──┐
        │   web-app  ←→  postgres, redis            │
        └───────────────────────────────────────────┘
```

```bash
docker network create frontend
docker network create backend

docker run -d --name postgres --network backend postgres:17-alpine
docker run -d --name web-app --network backend myapp
docker network connect frontend web-app        # web-app만 양쪽에 연결
docker run -d --name nginx --network frontend -p 80:80 nginx:1.29-alpine
```

이렇게 하면 **nginx는 DB에 직접 접근할 수 없습니다**. 침해가 발생해도 피해 범위가 줄어듭니다.

## 디버깅용 임시 컨테이너

네트워크 문제를 확인할 때는 같은 네트워크에 일회용 컨테이너를 띄우는 게 빠릅니다.

```bash
docker run --rm -it --network appnet alpine:3.22 sh
# 안에서
#   nslookup db
#   wget -qO- http://api:3000/health
#   nc -zv db 5432
```

## 정리

- 컨테이너 안의 `localhost`는 **그 컨테이너 자신**이다
- `-p 호스트포트:컨테이너포트`로 외부에 노출하고, 앱은 `0.0.0.0`에 바인딩해야 한다
- 외부에 열 필요 없으면 `127.0.0.1:포트:포트`로 바인딩을 제한
- 기본 `bridge`에는 DNS가 없다 → **사용자 정의 네트워크를 만들면 컨테이너 이름으로 통신** 가능
- 앱의 DB 주소는 `localhost`가 아니라 컨테이너 이름(`db:5432`)
- 컨테이너 → 호스트는 `host.docker.internal` (리눅스는 `--add-host ...:host-gateway`)
- `--network host`는 리눅스와 macOS의 동작이 다르다
- 네트워크를 분리해 DB에 직접 접근할 수 있는 컨테이너를 줄이는 게 좋은 설계
