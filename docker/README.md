## Docker

Docker에 관한 TIL입니다.

Docker는 애플리케이션과 실행 환경(OS 라이브러리, 런타임, 설정)을 **이미지** 하나로 묶어서, 내 노트북에서도 CI에서도 서버에서도 똑같이 돌아가게 만드는 컨테이너 도구입니다. 가상 머신과 달리 호스트 커널을 공유하기 때문에 시작이 1초 안에 끝나고 오버헤드가 거의 없습니다. "제 컴퓨터에서는 되는데요" 문제를 없애는 것에서 시작해, 로컬 개발 환경 구성, CI 빌드, 배포까지 이어집니다.

- 작성 기준: Docker Engine 29.1.5 / Compose v5
- 문서 안의 명령어와 출력, 이미지 크기 수치는 실제로 실행해서 확인했습니다.

### 공식 사이트

https://www.docker.com

### 공식 문서

https://docs.docker.com

### Docker Hub

https://hub.docker.com

### 학습 로드맵

```
1. 기본            설치 → 이미지/컨테이너 → 명령어 → 네트워크 → 볼륨
2. 이미지 빌드      Dockerfile → 빌드 캐시 → 멀티스테이지 → 경량화/보안 → 레지스트리
3. Compose와 운영   Compose → 개발 환경 → 로그 → 리소스 → 보안 → CI/CD → 오케스트레이션
4. 프로젝트         내 앱 컨테이너화 → 개발용 스택 → 자동 배포 → 셀프호스팅
```

처음에는 `1-기본`의 **볼륨**과 **네트워크**에서 막히는 경우가 많습니다. 데이터가 왜 사라지는지, 컨테이너끼리 왜 이름으로 통신이 안 되는지 두 가지만 이해하면 나머지는 수월합니다.

### 알아두면 좋을 것

- Compose는 v2부터 `docker-compose`(하이픈)가 아니라 `docker compose`(공백) 하위 명령입니다. 파일 이름도 `compose.yaml`이 공식 권장이고, 맨 위의 `version:` 키는 더 이상 쓰지 않습니다.
- 인터넷의 Docker 자료는 명령어 표기가 바뀌기 전 것이 많습니다. 걸러내는 기준은 [5-참고-자료](./5-참고-자료.md)의 마지막 섹션에 정리해뒀습니다.
