# 구조체와 메서드 - 클래스 없이 객체지향하기

## 들어가며

Go에는 `class`, `extends`, `this`, 생성자가 없습니다. 대신 이렇게 조합합니다.

```
class           → struct (데이터) + method (동작)
constructor     → New로 시작하는 일반 함수 (관례)
extends (상속)  → 임베딩 (조합, composition)
implements      → 인터페이스를 암묵적으로 만족 (인터페이스 문서)
private/public  → 이름의 첫 글자 대소문자
```

"상속보다 조합"을 언어 차원에서 강제하는 셈입니다.

# 1. 구조체 기본

## 정의와 생성

```go
package main

import "fmt"

type User struct {
	ID    int
	Name  string
	Email string
	admin bool // 소문자: 패키지 밖에서 접근 불가
}

func main() {
	// 1) 필드 이름 지정 (권장)
	u1 := User{ID: 1, Name: "alice"}

	// 2) 순서대로 (필드가 추가되면 깨지므로 비권장)
	u2 := User{2, "bob", "bob@example.com", false}

	// 3) 제로값
	var u3 User

	// 4) 포인터로 생성
	u4 := &User{Name: "carol"}

	fmt.Printf("%+v\n%+v\n%+v\n%+v\n", u1, u2, u3, *u4)
	// 출력:
	// {ID:1 Name:alice Email: admin:false}
	// {ID:2 Name:bob Email:bob@example.com admin:false}
	// {ID:0 Name: Email: admin:false}
	// {ID:0 Name:carol Email: admin:false}

	// 필드 접근: 포인터여도 . 으로 접근 (자동 역참조, -> 없음)
	u4.Email = "carol@example.com"
	fmt.Println(u4.Email)
}
```

## 구조체는 값 타입

```go
package main

import "fmt"

type Point struct{ X, Y int }

func main() {
	a := Point{1, 2}
	b := a // 전체 복사
	b.X = 100
	fmt.Println(a, b)
	// 출력: {1 2} {100 2}

	// 모든 필드가 비교 가능하면 == 사용 가능
	fmt.Println(a == Point{1, 2})
	// 출력: true
}
```

JS 객체는 참조로 공유되지만, Go 구조체는 **대입/함수 인자 전달 시 복사**됩니다. 공유하고 싶으면 포인터를 씁니다.

## 익명 구조체

일회성 데이터(테스트 케이스, JSON 응답 등)에 자주 씁니다.

```go
package main

import "fmt"

func main() {
	config := struct {
		Host string
		Port int
	}{
		Host: "localhost",
		Port: 8080,
	}
	fmt.Println(config.Host, config.Port)

	// 테스트 테이블에서 매우 흔한 패턴
	tests := []struct {
		input string
		want  int
	}{
		{"a", 1},
		{"ab", 2},
	}
	for _, tt := range tests {
		fmt.Println(tt.input, tt.want)
	}
}
```

# 2. 생성자 함수

Go에는 생성자 문법이 없어서 `New` 접두사 함수를 관례로 씁니다.

```go
package main

import (
	"errors"
	"fmt"
)

type Account struct {
	owner   string
	balance int
}

// 유효성 검사가 필요하면 에러도 함께 반환
func NewAccount(owner string, initial int) (*Account, error) {
	if owner == "" {
		return nil, errors.New("owner는 필수")
	}
	if initial < 0 {
		return nil, errors.New("초기 잔액은 0 이상")
	}
	return &Account{owner: owner, balance: initial}, nil
}

func main() {
	acc, err := NewAccount("alice", 1000)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Printf("%+v\n", *acc)
	// 출력: {owner:alice balance:1000}

	_, err = NewAccount("", 0)
	fmt.Println(err)
	// 출력: owner는 필수
}
```

```
관례:
- 패키지에 주요 타입이 하나면 New()     예: list.New()
- 여러 개면 NewXxx()                    예: http.NewRequest(), bufio.NewReader()
- 반환 타입은 보통 포인터 (*T)
```

# 3. 메서드

## 값 리시버 vs 포인터 리시버

```go
package main

import "fmt"

type Counter struct {
	count int
}

// 값 리시버: c는 복사본 → 원본 변경 불가
func (c Counter) Value() int {
	return c.count
}

// 포인터 리시버: 원본 변경 가능
func (c *Counter) Increment() {
	c.count++
}

// 값 리시버로 변경하려고 하면? → 복사본만 바뀜
func (c Counter) BrokenIncrement() {
	c.count++
}

func main() {
	c := Counter{}
	c.Increment() // Go가 자동으로 (&c).Increment() 로 바꿔줌
	c.Increment()
	c.BrokenIncrement()
	fmt.Println(c.Value())
	// 출력: 2
}
```

리시버 이름은 `this`/`self` 대신 **타입 이름의 첫 글자**(`c`, `u`, `s`)를 쓰는 것이 관례입니다.

## 어떤 리시버를 써야 할까?

```
포인터 리시버 (*T)를 쓰는 경우:
✅ 메서드가 필드를 수정할 때
✅ 구조체가 커서 복사 비용이 클 때
✅ sync.Mutex 같은 복사하면 안 되는 필드가 있을 때
✅ 타입의 다른 메서드가 포인터 리시버일 때 (일관성)

값 리시버 (T)를 쓰는 경우:
✅ 작고 불변인 값 (time.Time, Point 같은 것)
✅ 맵, 슬라이스, 함수, 채널 기반 타입

헷갈리면 → 포인터 리시버
```

> 한 타입 안에서는 **리시버 종류를 섞지 않는 것**이 좋습니다. 인터페이스 구현 여부에도 영향을 줍니다 (인터페이스 문서 참고).

## 어떤 타입에든 메서드를 붙일 수 있다

같은 패키지에서 정의한 타입이라면 구조체가 아니어도 됩니다.

```go
package main

import (
	"fmt"
	"strings"
)

type Celsius float64

func (c Celsius) Fahrenheit() float64 {
	return float64(c)*9/5 + 32
}

type Tags []string

func (t Tags) String() string {
	return "#" + strings.Join(t, " #")
}

func main() {
	fmt.Println(Celsius(100).Fahrenheit())
	// 출력: 212

	fmt.Println(Tags{"go", "backend"})
	// 출력: #go #backend
}
```

`int`, `string` 같은 내장 타입이나 다른 패키지 타입에는 직접 메서드를 붙일 수 없어서, 위처럼 새 타입을 정의합니다.

## 메서드 값과 메서드 표현식

```go
package main

import "fmt"

type Greeter struct{ name string }

func (g Greeter) Hello(to string) string {
	return g.name + " → " + to
}

func main() {
	g := Greeter{name: "alice"}

	// 메서드 값: 리시버가 묶인 함수 (JS의 bind 와 비슷)
	f := g.Hello
	fmt.Println(f("bob"))
	// 출력: alice → bob

	// 메서드 표현식: 리시버를 첫 번째 인자로 받는 함수
	h := Greeter.Hello
	fmt.Println(h(g, "carol"))
	// 출력: alice → carol
}
```

# 4. 임베딩 (Embedding)

## 필드와 메서드 승격

```go
package main

import "fmt"

type Animal struct {
	Name string
}

func (a Animal) Speak() string {
	return a.Name + "이(가) 소리를 냅니다"
}

type Dog struct {
	Animal // 타입 이름만 적으면 임베딩 (필드 이름 = Animal)
	Breed  string
}

func main() {
	d := Dog{
		Animal: Animal{Name: "바둑이"},
		Breed:  "진돗개",
	}

	// Animal의 필드와 메서드가 Dog로 "승격"됨
	fmt.Println(d.Name)    // d.Animal.Name 과 같음
	fmt.Println(d.Speak()) // d.Animal.Speak() 와 같음
	// 출력:
	// 바둑이
	// 바둑이이(가) 소리를 냅니다
}
```

## 상속이 아니다

```go
package main

import "fmt"

type Base struct{}

func (Base) Name() string { return "Base" }
func (b Base) Describe() string {
	return "나는 " + b.Name() // 항상 Base.Name 을 호출
}

type Derived struct {
	Base
}

func (Derived) Name() string { return "Derived" } // Base.Name을 "가림"

func main() {
	d := Derived{}
	fmt.Println(d.Name())     // Derived
	fmt.Println(d.Describe()) // 나는 Base  ← 가상 함수(오버라이딩)처럼 동작하지 않음!
}
```

```
Java/TS 상속: Describe() 안의 this.Name() → 자식 메서드 호출 (다형성)
Go 임베딩:    Describe() 의 리시버는 여전히 Base → Base.Name() 호출
```

임베딩은 **"코드를 가져와 붙이는 편의 기능"** 이지 is-a 관계가 아닙니다. 다형성이 필요하면 인터페이스를 씁니다.

## 실무 활용: 뮤텍스 임베딩, 인터페이스 부분 구현

```go
package main

import (
	"fmt"
	"sync"
)

type SafeCounter struct {
	sync.Mutex // Lock, Unlock 메서드가 승격됨
	counts     map[string]int
}

func main() {
	c := SafeCounter{counts: map[string]int{}}
	c.Lock()
	c.counts["a"]++
	c.Unlock()
	fmt.Println(c.counts)
	// 출력: map[a:1]
}
```

> 다만 `sync.Mutex`를 임베딩하면 `Lock`/`Unlock`이 **외부에 공개**되어 버립니다. 캡슐화가 필요하면 `mu sync.Mutex` 같은 이름 있는 필드로 두는 것이 더 안전합니다.

# 5. 구조체 태그

필드 뒤에 붙는 메타데이터 문자열로, `reflect`를 통해 라이브러리가 읽습니다.

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Product struct {
	ID       int      `json:"id"`
	Name     string   `json:"name"`
	Price    int      `json:"price,omitempty"` // 제로값이면 생략
	Tags     []string `json:"tags,omitzero"`   // Go 1.24+: 제로값(nil)이면 생략
	Internal string   `json:"-"`               // JSON에서 제외
}

func main() {
	p := Product{ID: 1, Name: "키보드", Internal: "비밀"}
	b, _ := json.Marshal(p)
	fmt.Println(string(b))
	// 출력: {"id":1,"name":"키보드"}
}
```

자주 보는 태그들:

```go
type User struct {
	ID    int64  `json:"id" db:"id"`                          // JSON, DB 매핑(sqlx 등)
	Email string `json:"email" validate:"required,email"`     // go-playground/validator
	Name  string `gorm:"size:100;not null" json:"name"`       // GORM
}
```

> 태그 문법이 틀려도 컴파일 에러가 나지 않습니다. `go vet`이 잘못된 태그 형식을 잡아주니 꼭 돌리기.

# 6. 구조체 설계 팁

## 제로값을 쓸모 있게

```go
// bytes.Buffer, sync.Mutex, sync.WaitGroup 등은 초기화 없이 바로 사용 가능
var buf bytes.Buffer
buf.WriteString("hello")
```

직접 만드는 타입도 제로값이 의미 있는 상태가 되도록 설계하면 `New` 함수 없이도 안전하게 쓸 수 있습니다.

## 필드 순서와 메모리 정렬

```go
package main

import (
	"fmt"
	"unsafe"
)

type Bad struct {
	a bool  // 1바이트 + 7바이트 패딩
	b int64 // 8바이트
	c bool  // 1바이트 + 7바이트 패딩
}

type Good struct {
	b int64 // 8바이트
	a bool  // 1바이트
	c bool  // 1바이트 + 6바이트 패딩
}

func main() {
	fmt.Println(unsafe.Sizeof(Bad{}), unsafe.Sizeof(Good{}))
	// 출력: 24 16
}
```

수백만 개를 메모리에 올리는 경우에만 신경 쓰면 됩니다. `fieldalignment` 린터가 자동으로 알려줍니다.

## 복사하면 안 되는 구조체

`sync.Mutex`를 포함한 구조체를 값으로 복사하면 락 상태가 같이 복사되어 버그가 납니다. `go vet`의 `copylocks` 검사가 이를 잡아줍니다.

## 정리

- 구조체는 값 타입이라 대입/전달 시 복사되고, 공유하려면 포인터 사용
- 생성자는 `NewXxx` 함수 관례, 필요하면 `(*T, error)` 반환
- 필드를 수정하거나 구조체가 크면 포인터 리시버, 작고 불변이면 값 리시버
- 임베딩은 필드/메서드 승격일 뿐 상속(다형성)이 아님, 다형성은 인터페이스로
- 구조체 태그로 JSON/DB/검증 메타데이터 지정, Go 1.24+ `omitzero` 지원
- 대문자 필드는 공개, 소문자 필드는 패키지 내부 전용
