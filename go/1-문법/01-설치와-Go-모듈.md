# 설치와 Go 모듈 - Go 개발 환경 세팅부터 의존성 관리까지

## 들어가며

Go를 처음 시작하면 이런 질문이 생깁니다.

```
질문 1: GOPATH가 뭐지? 아직도 설정해야 하나?
질문 2: npm의 package.json 같은 건 어디 있지?
질문 3: 외부 라이브러리는 어떻게 설치하지?
질문 4: 빌드하면 뭐가 나오지? 런타임이 따로 필요한가?
```

결론부터 말하면 **지금은 GOPATH를 신경 쓸 필요가 거의 없고**, `go.mod` 파일 하나로 프로젝트와 의존성을 관리합니다. 빌드 결과물은 **런타임 없이 실행되는 단일 바이너리**입니다.

## 공식 사이트

https://go.dev

# 1. 설치

## macOS

```bash
# Homebrew
brew install go

# 확인
go version
# go version go1.27.1 darwin/arm64
```

## Linux

```bash
# 공식 바이너리 설치 (버전은 https://go.dev/dl 에서 최신으로)
wget https://go.dev/dl/go1.27.1.linux-amd64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.27.1.linux-amd64.tar.gz

# ~/.bashrc 또는 ~/.zshrc
export PATH=$PATH:/usr/local/go/bin
```

## Windows

https://go.dev/dl 에서 `.msi` 설치 파일을 받아 실행하면 PATH까지 자동으로 설정됩니다.

## 환경 변수 확인

```bash
go env              # 전체 환경 변수
go env GOPATH       # 기본값: ~/go
go env GOROOT       # Go가 설치된 경로
go env GOPROXY      # 모듈 프록시 (기본: https://proxy.golang.org,direct)
```

```
GOROOT  = Go 자체(컴파일러, 표준 라이브러리)가 설치된 곳
GOPATH  = 다운로드한 모듈 캐시(~/go/pkg/mod)와 go install 바이너리(~/go/bin)가 저장되는 곳
GOBIN   = go install 결과물 위치 (기본: $GOPATH/bin)
```

`go install`로 설치한 CLI 도구를 바로 쓰려면 `~/go/bin`을 PATH에 추가해 둡니다.

```bash
export PATH=$PATH:$(go env GOPATH)/bin
```

# 2. Hello, World

## 프로젝트 만들기

```bash
mkdir hello && cd hello
go mod init github.com/username/hello
```

```
go: creating new go.mod: module github.com/username/hello
```

모듈 경로는 보통 **코드가 올라갈 저장소 주소**로 짓습니다. 외부에 공개하지 않을 거라면 `hello` 같은 짧은 이름도 괜찮습니다.

## main.go

```go
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go!")
}
```

```
규칙:
✅ 실행 가능한 프로그램은 반드시 package main
✅ 진입점은 func main() (인자, 반환값 없음)
✅ 사용하지 않는 import, 사용하지 않는 지역 변수는 컴파일 에러
```

## 실행과 빌드

```bash
go run .              # 컴파일 후 바로 실행 (임시 바이너리)
go build              # 현재 폴더에 실행 파일 생성 (./hello)
go build -o bin/app . # 출력 경로 지정
./hello
```

## 크로스 컴파일

Go의 큰 장점 중 하나입니다. 추가 도구 없이 환경 변수만 바꾸면 다른 OS용 바이너리가 나옵니다.

```bash
GOOS=linux   GOARCH=amd64 go build -o app-linux .
GOOS=windows GOARCH=amd64 go build -o app.exe .
GOOS=darwin  GOARCH=arm64 go build -o app-mac .

# 지원 목록
go tool dist list
```

# 3. Go 모듈 (go.mod)

## go.mod 구조

```
module github.com/username/hello   // 모듈 경로

go 1.27.1                          // 이 모듈이 요구하는 최소 Go 버전

require (
	github.com/gin-gonic/gin v1.10.0          // 직접 의존성
	golang.org/x/sync v0.10.0 // indirect     // 간접 의존성
)

tool golang.org/x/tools/cmd/stringer       // Go 1.24+ 도구 의존성
```

> `go` 줄의 버전은 단순 표기가 아니라 **언어 기능의 기준**입니다. 예를 들어 `go 1.21` 이하로 두면 Go 1.22의 루프 변수 스코프 변경이 적용되지 않습니다.

## package.json과 비교

```
npm                          Go
package.json          ↔     go.mod
package-lock.json     ↔     go.sum (체크섬 목록)
node_modules/         ↔     $GOPATH/pkg/mod (전역 캐시, 프로젝트마다 복사하지 않음)
npm install lib       ↔     go get lib
npm prune             ↔     go mod tidy
npx tool              ↔     go run pkg@version / go tool
```

## 의존성 추가/정리

```bash
# 최신 버전 추가
go get github.com/google/go-cmp/cmp

# 특정 버전
go get github.com/gin-gonic/gin@v1.10.0

# 최신 마이너/패치로 업데이트
go get -u ./...

# 제거 (@none)
go get github.com/gin-gonic/gin@none

# 코드에서 import 한 것과 go.mod를 동기화 (가장 자주 씀)
go mod tidy
```

코드에 `import "github.com/google/go-cmp/cmp"`를 먼저 쓰고 `go mod tidy`를 돌려도 됩니다.

## go.sum

```
github.com/google/go-cmp v0.7.0 h1:wk8382ETsv4JYUZwIsn6YpYiWiBsYLSJiTsyBybVuN8=
github.com/google/go-cmp v0.7.0/go.mod h1:pXiqmnSA92OHEEa9HXL2W4E7lf9JzCmGVUdgjX3N/iU=
```

- 다운로드한 모듈의 해시값입니다. **반드시 git에 커밋합니다.**
- 누군가 같은 버전의 내용을 바꿔치기하면 체크섬이 달라져 빌드가 실패합니다 (`sum.golang.org` 체크섬 DB로도 검증).

## 시맨틱 버전과 v2 이상

```
v1.2.3  = 메이저.마이너.패치

v0.x.x  → 불안정, 언제든 깨질 수 있음
v1.x.x  → 하위 호환 보장
v2.0.0+ → import 경로 자체가 바뀜 (Semantic Import Versioning)
```

```go
import "github.com/jackc/pgx/v5" // v5를 쓰려면 경로에 /v5 가 붙는다
```

Go는 같은 모듈의 v1과 v2를 **다른 모듈**로 취급하기 때문에 한 프로젝트에서 동시에 쓸 수도 있습니다.

## 버전 선택 방식: MVS

npm은 범위(`^1.2.0`) 안에서 최신을 고르지만, Go는 **Minimal Version Selection**을 씁니다.

```
A가 C v1.2 를 요구
B가 C v1.4 를 요구
→ 선택되는 버전: C v1.4 (요구사항을 모두 만족하는 "최소" 버전)
→ v1.5가 새로 나와도 누가 요구하지 않으면 올라가지 않음
```

그래서 lock 파일 없이도 빌드가 재현 가능합니다.

## replace: 로컬 모듈 연결

```
// go.mod
replace github.com/username/mylib => ../mylib
```

라이브러리를 수정하면서 바로 테스트할 때 씁니다. 배포 전에 지우는 것을 잊지 말기.

## 워크스페이스 (go.work, Go 1.18+)

여러 모듈을 동시에 개발할 때 `replace`를 대신합니다.

```bash
go work init ./api ./shared
```

```
// go.work
go 1.27.1

use (
	./api
	./shared
)
```

`go.work`는 개인 개발 환경용이라 보통 커밋하지 않습니다.

# 4. 도구 의존성 (Go 1.24+)

예전에는 `tools.go` 파일에 빈 import를 적는 편법을 썼지만, Go 1.24부터 `tool` 지시어를 공식 지원합니다.

```bash
# 도구 추가 → go.mod에 tool 줄이 생김
go get -tool golang.org/x/tools/cmd/stringer

# 실행
go tool stringer -type=Color

# 모듈의 모든 도구 업데이트
go get tool
```

# 5. 자주 쓰는 go 명령어

```bash
go run .            # 실행
go build            # 빌드
go install pkg@ver  # 바이너리를 $GOBIN에 설치 (예: go install golang.org/x/tools/gopls@latest)
go test ./...       # 모든 패키지 테스트 (./... = 하위 폴더 전부)
go vet ./...        # 정적 분석 (의심스러운 코드 탐지)
go fmt ./...        # 코드 포맷팅 (gofmt -l -w .)
go mod tidy         # 의존성 정리
go doc fmt.Println  # 문서 보기
go doc -http        # 로컬 문서 서버 (Go 1.25+)
go fix ./...        # 최신 문법/API로 자동 수정 (Go 1.26부터 modernizer 탑재)
go clean -modcache  # 모듈 캐시 삭제
```

## gofmt

Go에는 **포맷 논쟁이 없습니다.** 탭 들여쓰기, 중괄호 위치 등 모든 스타일이 `gofmt`로 통일되어 있어서 Prettier 설정 같은 게 필요 없습니다.

```go
// 이렇게 쓰면 컴파일 에러: 여는 중괄호는 반드시 같은 줄에
func main()
{
}
```

```
syntax error: unexpected semicolon or newline before {
```

Go 컴파일러가 줄 끝에 세미콜론을 자동 삽입하기 때문입니다.

# 7. 프로젝트 구조 예시

```
myapp/
├── go.mod
├── go.sum
├── main.go                 # 작은 프로젝트는 루트에 main
├── cmd/
│   └── server/
│       └── main.go         # 실행 파일이 여러 개면 cmd/이름/main.go
├── internal/               # 외부 모듈이 import 할 수 없는 패키지
│   ├── handler/
│   └── store/
└── pkg/                    # (선택) 외부 공개용 패키지
```

> 처음부터 폴더를 잘게 나누지 말고, **main.go 하나로 시작해서 필요할 때 나누는 것**이 Go 공식 가이드의 권장 방식입니다.

## 정리

- Go 설치 후 `go mod init 모듈경로`로 프로젝트 시작, GOPATH는 거의 신경 쓸 필요 없음
- `go.mod`(의존성 선언) + `go.sum`(체크섬)은 둘 다 커밋
- `go get`으로 추가, `go mod tidy`로 정리, v2 이상은 import 경로에 `/v2`
- 빌드 결과는 런타임이 필요 없는 단일 바이너리, `GOOS`/`GOARCH`로 크로스 컴파일
- `gofmt`로 스타일 통일, `go vet`/`golangci-lint`로 정적 분석
- Go 1.24+는 `go get -tool`로 개발 도구도 go.mod로 관리
