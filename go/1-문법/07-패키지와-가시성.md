# 패키지와 가시성 - 대문자 하나로 끝나는 접근 제어

## 들어가며

JS/TS에서는 `export`, `import { a } from './a'`, `public/private` 키워드로 공개 범위를 정합니다. Go는 훨씬 단순합니다.

```
✅ 폴더 하나 = 패키지 하나
✅ 이름이 대문자로 시작하면 공개 (Exported), 소문자면 패키지 내부 전용
✅ import 는 파일이 아니라 "패키지 경로" 단위
✅ internal/ 폴더로 모듈 내부 전용 패키지 만들기
```

# 1. 패키지 기본

## 폴더 = 패키지

```
shop/
├── go.mod                      # module github.com/username/shop
├── cmd/
│   └── app/
│       └── main.go             # package main
├── mathx/
│   └── mathx.go                # package mathx
└── internal/
    └── greeting/
        └── greeting.go         # package greeting
```

```
규칙:
- 같은 폴더의 .go 파일은 모두 같은 package 이름을 써야 함 (_test 패키지 제외)
- 같은 패키지 안의 파일끼리는 import 없이 서로의 이름을 바로 사용
- 패키지 이름은 보통 폴더 이름과 같게 (소문자, 짧게, 언더스코어/카멜케이스 X)
- import 경로 = 모듈 경로 + 폴더 경로
```

## 공개/비공개

```go
// mathx/mathx.go

// Package mathx는 간단한 수학 유틸리티를 제공한다.
package mathx

// Pi는 원주율 근삿값이다. (대문자 → 외부 공개)
const Pi = 3.14

var callCount int // 소문자 → 패키지 내부 전용

// Add는 두 정수의 합을 반환한다.
func Add(a, b int) int {
	callCount++
	return a + b
}

// CallCount는 Add가 호출된 횟수를 반환한다.
func CallCount() int {
	return callCount
}
```

```go
// cmd/app/main.go
package main

import (
	"fmt"

	"github.com/username/shop/internal/greeting"
	"github.com/username/shop/mathx"
)

func main() {
	fmt.Println(greeting.Hello("gopher"))
	fmt.Println(mathx.Add(1, 2), mathx.Pi, mathx.CallCount())
	// fmt.Println(mathx.callCount) // 컴파일 에러
}
```

```bash
go run ./cmd/app
# 안녕, gopher!
# 3 3.14 1
```

소문자 이름에 접근하면 이런 에러가 납니다.

```
name callCount not exported by package mathx
```

가시성 규칙은 **구조체 필드와 메서드에도 똑같이** 적용됩니다.

```go
type User struct {
	Name     string // 외부에서 접근 가능, JSON 인코딩 가능
	password string // 패키지 내부 전용, encoding/json도 무시함
}
```

> `encoding/json`이 소문자 필드를 무시하는 이유도 이것입니다. 외부 패키지인 json은 소문자 필드에 접근할 수 없습니다.

# 2. import

## 기본 형태

```go
import "fmt"

import (
	"fmt"
	"net/http"

	"github.com/gin-gonic/gin" // 표준 라이브러리와 외부 패키지는 빈 줄로 구분 (goimports가 자동 정렬)
)
```

사용할 때는 **경로의 마지막 요소가 아니라 package 선언의 이름**으로 접근합니다. 대부분 둘이 같습니다.

```go
import "math/rand/v2"      // 패키지 이름: rand
import "github.com/jackc/pgx/v5" // 패키지 이름: pgx
```

## 별칭, 빈 import, 점 import

```go
import (
	crand "crypto/rand"  // 별칭: 이름 충돌 피하기
	mrand "math/rand/v2"

	_ "github.com/lib/pq" // 빈 import: init()만 실행 (DB 드라이버 등록 등)
	_ "embed"             // //go:embed 를 쓸 때

	. "fmt" // 점 import: Println 처럼 패키지 이름 없이 사용 → 가독성이 나빠 비권장
)
```

## 사용하지 않는 import는 컴파일 에러

```
"os" imported and not used
```

`goimports`(VS Code Go 확장이 저장 시 자동 실행)가 import를 자동으로 추가/삭제해 주므로 실제로는 거의 신경 쓰지 않습니다.

## 순환 import 금지

```
package github.com/username/shop/a
	imports github.com/username/shop/b from a.go
	imports github.com/username/shop/a from b.go: import cycle not allowed
```

Go는 패키지 간 순환 참조를 **컴파일 단계에서 금지**합니다. 이 에러가 나면 보통 이렇게 해결합니다.

```
1. 공통으로 필요한 타입을 제3의 패키지로 분리 (예: domain, model)
2. 한쪽이 인터페이스에 의존하도록 변경 (의존성 역전)
3. 두 패키지가 사실상 하나라면 합치기
```

# 3. internal 패키지

`internal/` 아래 패키지는 **internal의 부모 디렉터리 트리 안에서만** import 할 수 있습니다.

```
github.com/username/shop/internal/greeting

✅ github.com/username/shop/cmd/app       → import 가능
✅ github.com/username/shop/mathx         → import 가능
❌ github.com/someone/other               → import 불가
```

다른 모듈에서 import 하면 컴파일러가 막습니다.

```
use of internal package github.com/username/shop/internal/greeting not allowed
```

라이브러리를 공개하더라도 **API로 약속하고 싶지 않은 코드는 internal에** 두면, 나중에 마음대로 바꿀 수 있습니다.

# 4. init 과 패키지 초기화 순서

```
1. import 된 패키지부터 (의존성 깊은 순서로) 초기화
2. 각 패키지에서: 패키지 변수 초기화 → init() 함수들 실행
3. 마지막으로 main 패키지의 main()
```

```go
package db

var drivers = map[string]bool{}

func init() {
	drivers["postgres"] = true
}
```

한 패키지에 `init`이 여러 개 있어도 되고, 여러 번 import 되어도 **딱 한 번만** 실행됩니다.

# 5. 문서 주석 (godoc)

공개된 이름 바로 위에 **그 이름으로 시작하는 주석**을 달면 `go doc`과 pkg.go.dev에 문서로 표시됩니다.

```go
// Package mathx는 간단한 수학 유틸리티를 제공한다.
package mathx

// Add는 두 정수의 합을 반환한다.
//
// 오버플로는 검사하지 않는다.
func Add(a, b int) int { return a + b }

// Deprecated: AddAll을 사용하세요.
func Sum(nums []int) int { return 0 }
```

```bash
go doc github.com/username/shop/mathx
go doc mathx.Add
go doc -http   # 브라우저로 로컬 문서 보기 (Go 1.25+)
```

`Deprecated:`로 시작하는 문단은 에디터와 린터가 인식해서 사용 시 경고를 띄웁니다.

## Example 함수

테스트 파일에 `Example` 함수를 쓰면 **문서에 예제로 표시되고, 출력까지 테스트**됩니다.

```go
// mathx_test.go
package mathx_test

import (
	"fmt"

	"github.com/username/shop/mathx"
)

func ExampleAdd() {
	fmt.Println(mathx.Add(1, 2))
	// Output: 3
}
```

# 6. 파일 임베드 (embed, Go 1.16+)

정적 파일을 바이너리 안에 넣어서 **단일 실행 파일로 배포**할 수 있습니다.

```go
package main

import (
	"embed"
	"fmt"
	"io/fs"
)

//go:embed version.txt
var version string

//go:embed static
var staticFiles embed.FS

func main() {
	fmt.Print("version: ", version)
	data, _ := staticFiles.ReadFile("static/index.html")
	fmt.Print(string(data))
	fs.WalkDir(staticFiles, ".", func(path string, d fs.DirEntry, err error) error {
		fmt.Println(path)
		return nil
	})
}
```

```
version: v1.2.3
<h1>hi</h1>
.
static
static/index.html
```

웹 서버에서 `http.FileServerFS(staticFiles)`와 함께 쓰면 프론트엔드 빌드 결과물을 Go 바이너리 하나에 담아 배포할 수 있습니다.

# 7. 빌드 태그 (Build Constraints)

파일 맨 위에 조건을 적어서 특정 OS/아키텍처/태그에서만 컴파일되게 합니다.

```go
//go:build linux && amd64

package sysinfo
```

```go
//go:build integration

package store_test // go test -tags=integration ./... 일 때만 포함
```

파일 이름으로도 가능합니다.

```
file_linux.go      → Linux에서만
file_windows.go    → Windows에서만
file_darwin_arm64.go
file_test.go       → go test 에서만
```

# 8. 패키지 설계 가이드

## 이름 짓기

```
✅ 짧고 소문자 한 단어: http, json, user, store
❌ util, common, helpers, base → 뭐든 들어가는 쓰레기통이 됨
❌ user_service, userService   → 언더스코어/카멜케이스 X
```

## 이름 반복 피하기 (stutter)

패키지 이름이 사용할 때 항상 앞에 붙기 때문에 반복하지 않습니다.

```
❌ user.UserService, http.HTTPServer
✅ user.Service,     http.Server
✅ bytes.Buffer, strings.Builder, context.Context (Context는 예외적으로 반복)
```

## 레이아웃

```
작은 프로젝트:   main.go 하나 + 필요할 때 파일 분리
라이브러리:     루트에 핵심 패키지, 세부 구현은 internal/
서버 프로젝트:  cmd/서버이름/main.go + internal/도메인별 패키지
```

> 흔히 보이는 `golang-standards/project-layout`은 **Go 팀의 공식 표준이 아닙니다.** 공식 가이드는 go.dev/doc/modules/layout 을 참고하세요.

## 정리

- 폴더 하나가 패키지 하나, import는 `모듈경로/폴더경로`
- 대문자로 시작하면 공개, 소문자는 패키지 내부 전용 (필드/메서드 포함)
- 사용하지 않는 import, 순환 import는 컴파일 에러
- `internal/` 패키지는 부모 트리 안에서만 import 가능
- 초기화 순서: 의존 패키지 → 패키지 변수 → `init()` → `main()`
- 이름으로 시작하는 주석이 godoc 문서가 됨, `Example` 함수는 문서 겸 테스트
- `//go:embed`로 정적 파일을 바이너리에 포함, `//go:build`로 조건부 컴파일
