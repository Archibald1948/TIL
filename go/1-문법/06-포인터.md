# 포인터 - C보다 안전하고 JS보다 명시적인 참조

## 들어가며

JS/TS만 해봤다면 포인터가 낯설 수 있습니다. 하지만 JS에도 이미 비슷한 개념이 있습니다.

```
JS:
  let a = 1;  let b = a;  b = 2;          // a는 그대로 1 (원시값 복사)
  let o = {x: 1};  let p = o;  p.x = 2;   // o.x도 2 (참조 공유)

Go:
  모든 대입과 함수 인자 전달은 "복사"
  → 공유하고 싶으면 "주소(포인터)"를 복사해서 넘긴다
```

Go 포인터는 C와 달리 **포인터 연산이 없고, GC가 메모리를 관리**하기 때문에 훨씬 안전합니다.

# 1. 기본 문법

```go
package main

import "fmt"

func main() {
	x := 10
	p := &x // & : 주소 가져오기, p의 타입은 *int

	fmt.Println(*p) // * : 역참조 (주소가 가리키는 값)
	// 출력: 10

	*p = 20 // 포인터를 통해 원본 수정
	fmt.Println(x)
	// 출력: 20

	fmt.Printf("%T %v\n", p, p != nil)
	// 출력: *int true
}
```

```
&변수   → 변수의 주소
*T      → T를 가리키는 포인터 타입
*포인터 → 포인터가 가리키는 값
```

## 제로값은 nil

```go
package main

import "fmt"

func main() {
	var p *int
	fmt.Println(p == nil)
	// 출력: true

	fmt.Println(*p) // panic: runtime error: invalid memory address or nil pointer dereference
}
```

nil 포인터 역참조는 Go에서 가장 흔한 런타임 panic입니다.

# 2. 왜 포인터를 쓰나

## 1) 함수에서 원본 수정

```go
package main

import "fmt"

func resetValue(n int) {
	n = 0 // 복사본 수정 → 효과 없음
}

func resetPointer(n *int) {
	*n = 0
}

func main() {
	a, b := 5, 5
	resetValue(a)
	resetPointer(&b)
	fmt.Println(a, b)
	// 출력: 5 0
}
```

## 2) 큰 구조체 복사 비용 절약

```go
type BigData struct {
	Buffer [1 << 20]byte // 1MB
}

func processValue(d BigData)    {} // 호출할 때마다 1MB 복사
func processPointer(d *BigData) {} // 8바이트(주소)만 복사
```

## 3) "값이 없음"을 표현

```go
package main

import (
	"encoding/json"
	"fmt"
)

type UpdateUserRequest struct {
	Name *string `json:"name"` // nil = 요청에 없음, "" = 빈 문자열로 변경
	Age  *int    `json:"age"`
}

func main() {
	var req UpdateUserRequest
	_ = json.Unmarshal([]byte(`{"age": 0}`), &req)

	fmt.Println(req.Name == nil) // true  → 이름은 안 바꿈
	fmt.Println(*req.Age)        // 0     → 나이를 0으로 바꾸라는 뜻
}
```

PATCH API처럼 "안 보냄"과 "제로값을 보냄"을 구분해야 할 때 씁니다.

# 3. 구조체와 포인터

## 자동 역참조

```go
package main

import "fmt"

type User struct {
	Name string
}

func main() {
	u := &User{Name: "alice"}

	// C: u->Name,  Go: 그냥 u.Name
	u.Name = "bob" // (*u).Name 과 동일
	fmt.Println(u.Name)
	// 출력: bob
}
```

## 생성 방법

```go
u1 := &User{Name: "alice"} // 가장 흔한 방식
u2 := new(User)            // 제로값 User를 할당하고 포인터 반환
```

## new에 초깃값 넣기 (Go 1.26+)

예전에는 리터럴 값의 포인터를 바로 만들 수 없어서 헬퍼 함수를 만들곤 했습니다.

```go
// Go 1.25 까지: &"hello", &30 같은 문법이 불가능해서 헬퍼가 필요
func ptr[T any](v T) *T { return &v }
```

Go 1.26부터 `new`에 표현식을 넘길 수 있습니다.

```go
package main

import "fmt"

type Profile struct {
	Nickname *string
	Age      *int
}

func main() {
	p := Profile{
		Nickname: new("gopher"), // *string
		Age:      new(30),       // *int
	}
	fmt.Println(*p.Nickname, *p.Age)
	// 출력: gopher 30
}
```

# 4. 로컬 변수의 주소를 반환해도 된다

C에서는 스택 변수의 주소를 반환하면 댕글링 포인터가 되지만, Go에서는 안전합니다.

```go
package main

import "fmt"

type Node struct {
	Value int
}

func newNode(v int) *Node {
	n := Node{Value: v}
	return &n // OK: 컴파일러가 n을 힙으로 옮김 (escape analysis)
}

func main() {
	fmt.Println(newNode(42).Value)
	// 출력: 42
}
```

변수를 스택에 둘지 힙에 둘지는 **컴파일러가 결정**합니다. 개발자는 신경 쓰지 않아도 되고, 성능 튜닝이 필요할 때만 확인합니다 (메모리 관리 문서 참고).

```bash
go build -gcflags='-m' .
# ./main.go:10:2: moved to heap: n
```

# 5. 포인터가 필요 없는 타입

슬라이스, 맵, 채널, 함수, 인터페이스는 **내부에 이미 포인터를 들고 있는 작은 헤더**라서 포인터로 넘길 필요가 거의 없습니다.

```go
package main

import "fmt"

func addKey(m map[string]int) {
	m["new"] = 1 // 포인터 없이도 원본 맵이 바뀜
}

func main() {
	m := map[string]int{}
	addKey(m)
	fmt.Println(m)
	// 출력: map[new:1]
}
```

```
❌ func f(m *map[string]int)   // 불필요
❌ func f(s *[]int)            // append 결과를 반영하려는 게 아니면 불필요
✅ func f(m map[string]int)
✅ func f(s []int) []int        // append 한다면 반환
```

# 6. 포인터 사용 시 주의점

## 루프에서 원소 주소 가져오기

```go
package main

import "fmt"

type Item struct{ N int }

func main() {
	items := []Item{{1}, {2}, {3}}

	// range 의 v 는 복사본 → v를 수정해도 원본은 그대로
	for _, v := range items {
		v.N *= 10
	}
	fmt.Println(items)
	// 출력: [{1} {2} {3}]

	// 원본을 수정하려면 인덱스로 접근
	for i := range items {
		items[i].N *= 10
	}
	fmt.Println(items)
	// 출력: [{10} {20} {30}]

	// 원소 포인터를 모으려면 &items[i]
	var ptrs []*Item
	for i := range items {
		ptrs = append(ptrs, &items[i])
	}
	ptrs[0].N = 999
	fmt.Println(items[0])
	// 출력: {999}
}
```

## 슬라이스 원소 포인터와 append

```go
package main

import "fmt"

func main() {
	s := make([]int, 1, 1)
	p := &s[0]

	s = append(s, 2) // cap 초과 → 새 배열로 이사
	*p = 100         // 옛날 배열을 수정함

	fmt.Println(s[0])
	// 출력: 0
}
```

append 이후에는 이전에 얻은 원소 포인터를 믿으면 안 됩니다.

## nil 체크는 호출하는 쪽 or 받는 쪽?

```go
package main

import "fmt"

type Tree struct {
	Left, Right *Tree
	Value       int
}

// 포인터 리시버 메서드는 nil 리시버로도 호출 가능 → 재귀 구조에서 유용
func (t *Tree) Sum() int {
	if t == nil {
		return 0
	}
	return t.Value + t.Left.Sum() + t.Right.Sum()
}

func main() {
	t := &Tree{Value: 1, Left: &Tree{Value: 2}}
	fmt.Println(t.Sum())
	// 출력: 3

	var empty *Tree
	fmt.Println(empty.Sum())
	// 출력: 0
}
```

# 7. 포인터 연산이 없다

```go
arr := [3]int{1, 2, 3}
p := &arr[0]
// p++          // 컴파일 에러: 포인터 연산 불가
// p + 1        // 컴파일 에러
```

정말 필요하면 `unsafe` 패키지(`unsafe.Add`, `unsafe.Pointer`)를 쓸 수 있지만, 이름 그대로 안전하지 않고 GC와 호환성 보장을 포기하는 것이라 일반 코드에서는 쓰지 않습니다.

# 8. 값 vs 포인터 선택 가이드

```
포인터를 쓰자:
✅ 함수가 인자를 수정해야 할 때
✅ 구조체가 크거나(대략 수십 바이트 이상), 복사되면 안 되는 필드(Mutex)가 있을 때
✅ nil로 "없음"을 표현해야 할 때
✅ 여러 곳에서 같은 인스턴스를 공유해야 할 때

값을 쓰자:
✅ 작은 구조체, 기본 타입
✅ 불변 데이터 (동시성에서 안전)
✅ 슬라이스/맵/채널 (이미 참조처럼 동작)

주의:
⚠️ 포인터가 많을수록 힙 할당과 GC 부담이 늘 수 있음
⚠️ "성능 때문에 무조건 포인터"는 오히려 느릴 수 있음 → 벤치마크로 확인
```

## 정리

- `&`로 주소, `*`로 역참조, 포인터 제로값은 `nil`
- Go의 모든 전달은 복사이므로 원본 수정/공유가 필요하면 포인터 사용
- 구조체 포인터는 `.`으로 자동 역참조, 로컬 변수 주소 반환도 안전 (escape analysis)
- 슬라이스/맵/채널은 포인터로 넘길 필요가 거의 없음
- range 변수는 복사본, append 후 원소 포인터는 무효화될 수 있음
- Go 1.26+ `new(값)`으로 리터럴 값의 포인터를 바로 생성
- 포인터 연산은 불가 (unsafe 제외)
