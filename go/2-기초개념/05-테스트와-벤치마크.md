# 테스트와 벤치마크 - Jest 없이 표준 도구만으로

## 들어가며

JS 프로젝트에서 테스트를 하려면 이런 선택부터 해야 합니다.

```
테스트 러너: Jest? Vitest? Mocha?
단언 라이브러리: expect? chai?
커버리지: istanbul? c8?
벤치마크: benchmark.js? tinybench?
```

Go는 **전부 표준 도구에 들어 있습니다.**

```
go test              → 테스트 실행
go test -cover       → 커버리지
go test -bench       → 벤치마크
go test -fuzz        → 퍼징 (Go 1.18+)
go test -race        → 데이터 레이스 탐지
testing/synctest     → 시간/동시성 테스트 (Go 1.25+)
net/http/httptest    → HTTP 핸들러/서버 테스트
```

# 1. 테스트 기본

## 파일과 함수 규칙

```
calc/
├── calc.go        # 코드
└── calc_test.go   # 테스트 (파일 이름이 _test.go 로 끝나야 함)
```

```
규칙:
✅ 함수 이름은 Test 로 시작 + 대문자: TestAdd, TestUser_Create
✅ 시그니처는 func TestXxx(t *testing.T)
✅ _test.go 파일은 go build 에 포함되지 않음
```

## 첫 테스트

```go
// calc.go
package calc

import "errors"

var ErrDivideByZero = errors.New("divide by zero")

func Add(a, b int) int { return a + b }

func Divide(a, b int) (int, error) {
	if b == 0 {
		return 0, ErrDivideByZero
	}
	return a / b, nil
}
```

```go
// calc_test.go
package calc

import "testing"

func TestAdd(t *testing.T) {
	got := Add(2, 3)
	want := 5
	if got != want {
		t.Errorf("Add(2, 3) = %d; want %d", got, want)
	}
}
```

Go 표준 테스트에는 `expect(x).toBe(y)` 같은 단언 함수가 없습니다. **그냥 if문으로 비교하고 `t.Errorf`로 실패를 알립니다.**

## 실행

```bash
go test              # 현재 패키지
go test ./...        # 모든 하위 패키지
go test -v ./...     # 상세 출력 (각 테스트 이름과 결과)
go test -run TestAdd # 이름이 정규식과 일치하는 테스트만
go test -run 'TestDivide/0으로' # 서브테스트 선택
go test -count=1 ./... # 캐시 무시하고 다시 실행
```

실패하면 이렇게 나옵니다.

```
--- FAIL: TestAddFail (0.00s)
    fail_test.go:7: Add(2, 2) = 4; want 5
FAIL
FAIL	github.com/username/calc	0.454s
```

## 실패 함수 종류

```
t.Error / t.Errorf  → 실패 기록 후 "계속 진행"
t.Fatal / t.Fatalf  → 실패 기록 후 "즉시 중단" (이후 코드 실행 안 됨)
t.Log / t.Logf      → 로그 (-v 이거나 실패했을 때만 출력)
t.Skip("이유")      → 테스트 건너뛰기
```

```
언제 Fatal?
→ 이후 검사가 의미 없을 때 (예: err != nil 이면 결과값 검사는 무의미)
```

# 2. 테이블 주도 테스트 (Table-Driven Test)

Go에서 **가장 표준적인 테스트 패턴**입니다.

```go
package calc

import (
	"errors"
	"testing"
)

func TestDivide(t *testing.T) {
	tests := []struct {
		name    string
		a, b    int
		want    int
		wantErr error
	}{
		{name: "정상 나눗셈", a: 10, b: 2, want: 5},
		{name: "나머지 버림", a: 7, b: 2, want: 3},
		{name: "0으로 나누기", a: 1, b: 0, wantErr: ErrDivideByZero},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) { // 서브테스트
			got, err := Divide(tt.a, tt.b)
			if !errors.Is(err, tt.wantErr) {
				t.Fatalf("err = %v; want %v", err, tt.wantErr)
			}
			if got != tt.want {
				t.Errorf("Divide(%d, %d) = %d; want %d", tt.a, tt.b, got, tt.want)
			}
		})
	}
}
```

```
=== RUN   TestDivide
=== RUN   TestDivide/정상_나눗셈
=== RUN   TestDivide/나머지_버림
=== RUN   TestDivide/0으로_나누기
--- PASS: TestDivide (0.00s)
    --- PASS: TestDivide/정상_나눗셈 (0.00s)
    --- PASS: TestDivide/나머지_버림 (0.00s)
    --- PASS: TestDivide/0으로_나누기 (0.00s)
PASS
```

```
장점:
✅ 케이스 추가 = 한 줄 추가
✅ t.Run 으로 케이스별 이름이 붙어서 어떤 케이스가 실패했는지 바로 보임
✅ 하나가 실패해도 나머지 케이스는 계속 실행
```

# 3. 테스트 헬퍼 기능

```go
package calc

import (
	"os"
	"path/filepath"
	"testing"
)

// t.Helper(): 실패 시 이 함수가 아니라 "호출한 줄"을 에러 위치로 표시
func assertEqual[T comparable](t *testing.T, got, want T) {
	t.Helper()
	if got != want {
		t.Errorf("got %v; want %v", got, want)
	}
}

func TestHelpers(t *testing.T) {
	// 테스트 끝나면 자동 삭제되는 임시 디렉터리
	dir := t.TempDir()
	path := filepath.Join(dir, "data.txt")
	os.WriteFile(path, []byte("hi"), 0o644)

	// 테스트가 끝날 때 실행 (defer와 비슷하지만 헬퍼 함수 안에서도 등록 가능)
	t.Cleanup(func() {
		t.Log("테스트 끝나고 정리")
	})

	data, _ := os.ReadFile(path)
	assertEqual(t, string(data), "hi")

	// Go 1.24+: 테스트 종료 직전에 취소되는 context
	ctx := t.Context()
	_ = ctx

	// Go 1.24+: 테스트 동안만 작업 디렉터리 변경
	// t.Chdir(dir)

	// 테스트 동안만 환경 변수 설정 (끝나면 원복)
	t.Setenv("APP_ENV", "test")
}
```

## 병렬 테스트

## TestMain: 패키지 전체 준비/정리

```go
func TestMain(m *testing.M) {
	// 모든 테스트 전에 한 번 (예: 테스트 DB 컨테이너 띄우기)
	setup()

	code := m.Run() // 테스트 실행

	// 모든 테스트 후에 한 번
	teardown()
	os.Exit(code)
}
```

# 5. HTTP 테스트 (httptest)

## 핸들러 단위 테스트

```go
package calc

import (
	"encoding/json"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func helloHandler(w http.ResponseWriter, r *http.Request) {
	name := r.URL.Query().Get("name")
	if name == "" {
		http.Error(w, "name is required", http.StatusBadRequest)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]string{"message": "hello " + name})
}

func TestHelloHandler(t *testing.T) {
	req := httptest.NewRequest(http.MethodGet, "/hello?name=gopher", nil)
	rec := httptest.NewRecorder() // ResponseWriter 가짜 구현

	helloHandler(rec, req)

	if rec.Code != http.StatusOK {
		t.Fatalf("status = %d; want 200", rec.Code)
	}
	want := `{"message":"hello gopher"}`
	if got := strings.TrimSpace(rec.Body.String()); got != want {
		t.Errorf("body = %s; want %s", got, want)
	}
}
```

## 실제 서버 띄워서 테스트

```go
func TestWithServer(t *testing.T) {
	srv := httptest.NewServer(http.HandlerFunc(helloHandler)) // 랜덤 포트로 실제 서버 실행
	defer srv.Close()

	resp, err := http.Get(srv.URL + "/hello")
	if err != nil {
		t.Fatal(err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusBadRequest {
		t.Errorf("status = %d", resp.StatusCode)
	}
}
```

외부 API를 호출하는 클라이언트 코드를 테스트할 때, `httptest.NewServer`로 **가짜 외부 API**를 만들어 URL만 바꿔 끼우는 방식이 많이 쓰입니다.

# 7. 벤치마크

## 작성과 실행

```go
package calc

import (
	"strings"
	"testing"
)

var parts = strings.Split(strings.Repeat("go,", 100), ",")

func ConcatPlus(parts []string) string {
	s := ""
	for _, p := range parts {
		s += p
	}
	return s
}

func ConcatBuilder(parts []string) string {
	var sb strings.Builder
	for _, p := range parts {
		sb.WriteString(p)
	}
	return sb.String()
}

func BenchmarkConcatPlus(b *testing.B) {
	for b.Loop() { // Go 1.24+
		ConcatPlus(parts)
	}
}

func BenchmarkConcatBuilder(b *testing.B) {
	for b.Loop() {
		ConcatBuilder(parts)
	}
}
```

## b.Loop vs b.N

```go
// Go 1.23 까지의 방식
func BenchmarkOld(b *testing.B) {
	data := setup()    // 준비 비용이 측정에 포함될 수 있음
	b.ResetTimer()     // 그래서 타이머를 리셋해야 했음
	for i := 0; i < b.N; i++ {
		process(data)
	}
}

// Go 1.24+ 방식
func BenchmarkNew(b *testing.B) {
	data := setup()    // b.Loop 이전 코드는 자동으로 측정 제외
	for b.Loop() {
		process(data)  // 결과를 안 써도 컴파일러가 최적화로 없애버리지 않음
	}
}
```

# 8. 퍼징 (Fuzzing, Go 1.18+)

사람이 생각하지 못한 입력을 **자동으로 생성해서** 버그를 찾습니다.

```go
package calc

import (
	"testing"
	"unicode/utf8"
)

func Reverse(s string) string {
	r := []rune(s)
	for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
		r[i], r[j] = r[j], r[i]
	}
	return string(r)
}

func FuzzReverse(f *testing.F) {
	// 시드 입력
	f.Add("hello")
	f.Add("안녕하세요")

	f.Fuzz(func(t *testing.T, s string) {
		rev := Reverse(s)
		doubleRev := Reverse(rev)
		// 속성(property) 검사: 두 번 뒤집으면 원래대로
		if utf8.ValidString(s) && s != doubleRev {
			t.Errorf("Reverse(Reverse(%q)) = %q", s, doubleRev)
		}
		if utf8.ValidString(s) && !utf8.ValidString(rev) {
			t.Errorf("Reverse(%q)가 유효하지 않은 UTF-8: %q", s, rev)
		}
	})
}
```

```bash
go test -run '^$' -fuzz FuzzReverse -fuzztime 30s
```

```
fuzz: elapsed: 3s, execs: 537837 (179217/sec), new interesting: 31 (total: 33)
...
PASS
```

실패하는 입력을 찾으면 `testdata/fuzz/FuzzReverse/` 아래에 저장되고, 이후 일반 `go test`에서도 **회귀 테스트로 자동 실행**됩니다.

> 만약 `Reverse`를 `[]rune`이 아니라 바이트 단위로 구현했다면, 퍼저가 한글 같은 멀티바이트 입력으로 곧바로 버그를 찾아냅니다.

# 11. 시간과 동시성 테스트: testing/synctest (Go 1.25+)

타임아웃, 재시도, 캐시 만료처럼 **시간에 의존하는 코드**는 테스트가 느리거나 불안정(flaky)해지기 쉽습니다. `synctest`는 가짜 시계가 있는 격리된 "버블" 안에서 테스트를 실행합니다.

```go
package calc

import (
	"context"
	"testing"
	"testing/synctest"
	"time"
)

func waitOrTimeout(ctx context.Context, d time.Duration) error {
	ctx, cancel := context.WithTimeout(ctx, d)
	defer cancel()
	<-ctx.Done()
	return ctx.Err()
}

func TestTimeoutWithSynctest(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		start := time.Now()

		// 10분 타임아웃이지만 실제로는 즉시 끝남
		err := waitOrTimeout(t.Context(), 10*time.Minute)

		if err != context.DeadlineExceeded {
			t.Fatalf("err = %v", err)
		}
		// 버블 안의 시계는 정확히 10분 흐름
		if elapsed := time.Since(start); elapsed != 10*time.Minute {
			t.Errorf("elapsed = %v", elapsed)
		}
	})
}
```

```
--- PASS: TestTimeoutWithSynctest (0.00s)
```

```
동작 원리:
- 버블 안의 모든 고루틴이 블록되면 가짜 시계를 다음 타이머 시점으로 점프
- synctest.Wait(): 버블 안 고루틴들이 모두 블록될 때까지 대기
- Go 1.27+: synctest.Sleep() 헬퍼 추가
```

# 12. testify (인기 서드파티)

표준 방식이 장황하게 느껴지면 `testify`를 많이 씁니다.

```go
package calc

import (
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

func TestWithTestify(t *testing.T) {
	got, err := Divide(10, 2)
	require.NoError(t, err) // require: 실패 시 즉시 중단 (Fatal)
	assert.Equal(t, 5, got) // assert: 실패 기록 후 계속 (Error)

	_, err = Divide(1, 0)
	assert.ErrorIs(t, err, ErrDivideByZero)
}
```

```
표준 라이브러리만: Go 팀과 많은 오픈소스 프로젝트의 방식, 의존성 없음
testify:          코드가 짧아지고 실패 메시지가 친절함
go-cmp:           구조체/슬라이스 깊은 비교 + diff 출력 (cmp.Diff)
```

## 정리

- `_test.go` 파일의 `TestXxx(t *testing.T)` 함수, `go test ./...`로 실행
- 단언 함수 대신 if + `t.Errorf`/`t.Fatalf`, 헬퍼는 `t.Helper()`
- 테이블 주도 테스트 + `t.Run` 서브테스트가 표준 패턴
- `t.TempDir`, `t.Cleanup`, `t.Setenv`, `t.Context`(1.24+)로 준비/정리
- HTTP는 `httptest.NewRecorder`(핸들러) / `httptest.NewServer`(실제 서버)
- 벤치마크는 `BenchmarkXxx` + `for b.Loop()`(1.24+), `-benchmem`, `benchstat`
- 퍼징 `FuzzXxx`(1.18+), 커버리지 `-cover`, 레이스 `-race`
- 시간 의존 코드는 `testing/synctest`(1.25+)로 빠르고 결정적으로 테스트
