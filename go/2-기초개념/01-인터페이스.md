# 인터페이스 - implements 없이 동작하는 덕 타이핑

## 들어가며

TypeScript에서 인터페이스를 쓰면 이런 식입니다.

```ts
interface Speaker { speak(): string }
class Dog implements Speaker { speak() { return "멍" } }
```

Go에는 `implements` 키워드가 없습니다. **메서드만 맞으면 자동으로 그 인터페이스를 만족**합니다.

```
"오리처럼 걷고 오리처럼 꽥꽥거리면 오리다" (덕 타이핑)
→ 단, Go는 이걸 "컴파일 타임"에 검사한다 (구조적 타이핑)
```

이 덕분에 **인터페이스를 쓰는 쪽에서 정의**할 수 있고, 외부 라이브러리 타입도 내가 만든 인터페이스에 끼워 넣을 수 있습니다. Go 설계에서 가장 중요한 개념 중 하나입니다.

# 1. 인터페이스 기본

## 정의와 암묵적 구현

```go
package main

import (
	"fmt"
	"math"
)

type Shape interface {
	Area() float64
	Perimeter() float64
}

type Rect struct{ W, H float64 }

func (r Rect) Area() float64      { return r.W * r.H }
func (r Rect) Perimeter() float64 { return 2 * (r.W + r.H) }

type Circle struct{ R float64 }

func (c Circle) Area() float64      { return math.Pi * c.R * c.R }
func (c Circle) Perimeter() float64 { return 2 * math.Pi * c.R }

// Shape 인터페이스만 알면 된다
func describe(s Shape) {
	fmt.Printf("%T 넓이=%.2f 둘레=%.2f\n", s, s.Area(), s.Perimeter())
}

func main() {
	shapes := []Shape{Rect{3, 4}, Circle{1}}
	for _, s := range shapes {
		describe(s)
	}
	// 출력:
	// main.Rect 넓이=12.00 둘레=14.00
	// main.Circle 넓이=3.14 둘레=6.28
}
```

`Rect`와 `Circle` 어디에도 `Shape`라는 단어가 없습니다.

## 컴파일 타임 구현 확인

암묵적이라 "이 타입이 인터페이스를 구현하는지" 명시하고 싶을 때 이런 관용구를 씁니다.

```go
var _ Shape = Rect{}       // Rect가 Shape를 구현하지 않으면 컴파일 에러
var _ Shape = (*Circle)(nil) // 포인터 타입 확인 (메모리 할당 없음)
```

# 2. 작은 인터페이스

## 표준 라이브러리의 핵심 인터페이스

```go
// io 패키지
type Reader interface {
	Read(p []byte) (n int, err error)
}

type Writer interface {
	Write(p []byte) (n int, err error)
}

// fmt 패키지
type Stringer interface {
	String() string
}

// error 내장 타입
type error interface {
	Error() string
}
```

메서드가 **1개**뿐입니다. Go 속담 중에 이런 말이 있습니다.

> "The bigger the interface, the weaker the abstraction." (인터페이스가 클수록 추상화는 약해진다)

## io.Reader 하나로 모든 입력을 다루기

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"os"
	"strings"
)

// 입력이 파일이든, 문자열이든, 네트워크든 상관없음
func countBytes(r io.Reader) (int64, error) {
	return io.Copy(io.Discard, r)
}

func main() {
	n1, _ := countBytes(strings.NewReader("hello"))
	n2, _ := countBytes(bytes.NewBufferString("안녕"))

	f, err := os.Open("/etc/hosts")
	if err == nil {
		defer f.Close()
		n3, _ := countBytes(f)
		fmt.Println("파일 바이트 수 > 0:", n3 > 0)
	}

	fmt.Println(n1, n2)
	// 출력: 5 6
}
```

`*os.File`, `*strings.Reader`, `*bytes.Buffer`, `net.Conn`, `http.Request.Body`, `gzip.Reader` 모두 `io.Reader`입니다. 그래서 이들을 **레고처럼 조합**할 수 있습니다.

## 인터페이스 임베딩

```go
type ReadWriter interface {
	Reader
	Writer
}

type ReadWriteCloser interface {
	Reader
	Writer
	Closer
}
```

작은 인터페이스를 조합해서 큰 인터페이스를 만듭니다.

## Stringer 구현하기

```go
package main

import "fmt"

type Money struct {
	Amount   int
	Currency string
}

func (m Money) String() string {
	return fmt.Sprintf("%d %s", m.Amount, m.Currency)
}

func main() {
	m := Money{15000, "KRW"}
	fmt.Println(m) // fmt가 Stringer인지 확인하고 String()을 호출
	// 출력: 15000 KRW
}
```

# 3. 빈 인터페이스 any

```go
package main

import "fmt"

func main() {
	// any 는 interface{} 의 별칭 (Go 1.18+)
	var v any

	v = 42
	v = "hello"
	v = []int{1, 2}
	fmt.Println(v)

	// JSON처럼 구조를 모르는 데이터
	data := map[string]any{
		"name": "gopher",
		"age":  10,
		"tags": []string{"go"},
	}
	fmt.Println(data["name"])
}
```

메서드가 0개라서 **모든 타입이 만족**합니다. TS의 `unknown`과 비슷합니다 (값을 쓰려면 타입 단언 필요). 타입 안정성을 잃으므로 제네릭으로 해결할 수 있으면 제네릭을 우선 고려합니다.

# 4. 타입 단언과 타입 스위치

## 타입 단언 (Type Assertion)

```go
package main

import "fmt"

func main() {
	var v any = "hello"

	s := v.(string) // 실제 타입이 string 이라고 단언
	fmt.Println(s)

	// comma ok: 실패해도 panic 안 남
	n, ok := v.(int)
	fmt.Println(n, ok)
	// 출력: 0 false

	// 단일 반환 형태에서 실패하면 panic
	// _ = v.(int) // panic: interface conversion: interface {} is string, not int
}
```

## 타입 스위치

```go
package main

import "fmt"

func toString(v any) string {
	switch x := v.(type) {
	case string:
		return x
	case int, int64:
		return fmt.Sprintf("정수:%v", x) // 여러 타입이면 x 는 any
	case fmt.Stringer: // 인터페이스로도 분기 가능
		return x.String()
	case nil:
		return "<nil>"
	default:
		return fmt.Sprintf("%v", x)
	}
}

type ID int

func (id ID) String() string { return fmt.Sprintf("ID#%d", int(id)) }

func main() {
	fmt.Println(toString("a"), toString(1), toString(ID(7)), toString(nil), toString(1.5))
	// 출력: a 정수:1 ID#7 <nil> 1.5
}
```

## 선택적 기능 확인 (Optional Interface)

"이 값이 추가 기능도 지원하나?"를 런타임에 확인하는 패턴입니다. 표준 라이브러리에서 매우 흔합니다.

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

func closeIfPossible(r io.Reader) {
	if c, ok := r.(io.Closer); ok {
		c.Close()
		fmt.Println("닫음")
		return
	}
	fmt.Println("Close 메서드 없음")
}

func main() {
	closeIfPossible(strings.NewReader("x"))
	closeIfPossible(io.NopCloser(strings.NewReader("x")))
	// 출력:
	// Close 메서드 없음
	// 닫음
}
```

`io.Copy`도 내부에서 `WriterTo`/`ReaderFrom`을 구현했는지 확인해서 더 빠른 경로를 씁니다.

# 5. 메서드 집합과 포인터 리시버

## 포인터 리시버면 포인터만 인터페이스를 만족

```go
package main

import "fmt"

type Speaker interface {
	Speak() string
}

type Dog struct{ name string }

func (d *Dog) Speak() string { return d.name + ": 멍" } // 포인터 리시버

func main() {
	var s Speaker

	s = &Dog{"바둑이"} // OK
	fmt.Println(s.Speak())

	s = Dog{"바둑이"} // 컴파일 에러
}
```

```
cannot use Dog{…} (value of struct type Dog) as Speaker value in assignment: Dog does not implement Speaker (method Speak has pointer receiver)
```

```
메서드 집합 (Method Set):
- T  타입의 메서드 집합: 값 리시버 메서드만
- *T 타입의 메서드 집합: 값 리시버 + 포인터 리시버 메서드 전부

변수에서 d.Speak() 는 Go가 &d 로 자동 변환해주지만,
인터페이스에 담긴 값은 주소를 가져올 수 없어서 자동 변환이 안 됨
```

# 6. nil 인터페이스 함정

Go에서 가장 유명한 함정 중 하나입니다.

## 인터페이스 값의 내부 구조

```
인터페이스 값 = (타입, 값) 쌍

var err error            → (nil, nil)       → err == nil 은 true
var p *MyErr = nil
var err error = p        → (*MyErr, nil)    → err == nil 은 false!
```

## 버그 예시

```go
package main

import "fmt"

type MyError struct{}

func (e *MyError) Error() string { return "my error" }

func doSomething(fail bool) error {
	var err *MyError // nil 포인터
	if fail {
		err = &MyError{}
	}
	return err // ❌ 타입 정보(*MyError)가 담긴 인터페이스가 반환됨
}

func doSomethingFixed(fail bool) error {
	if fail {
		return &MyError{}
	}
	return nil // ✅ 명시적으로 nil 반환
}

func main() {
	err := doSomething(false)
	fmt.Println(err == nil)
	// 출력: false  (실패하지 않았는데도!)

	fmt.Println(doSomethingFixed(false) == nil)
	// 출력: true
}
```

> 규칙: **에러가 없으면 구체 타입 변수를 거치지 말고 `return nil`을 직접 쓴다.**

# 7. 인터페이스 설계 원칙

## 인터페이스는 사용하는 쪽에서 정의

```go
// ❌ Java 스타일: 구현하는 패키지가 인터페이스를 먼저 정의
package store

type UserStore interface {
	Get(id int) (*User, error)
	Create(u *User) error
	Update(u *User) error
	Delete(id int) error
	List() ([]*User, error)
}

type PostgresUserStore struct{ /* ... */ }
```

```go
// ✅ Go 스타일: 구현 패키지는 구체 타입만 제공
package store

type UserStore struct{ /* ... */ }

func (s *UserStore) Get(id int) (*User, error) { /* ... */ }
func (s *UserStore) Create(u *User) error      { /* ... */ }
```

```go
// 사용하는 쪽에서 필요한 메서드만 골라 인터페이스 정의
package notification

type userGetter interface {
	Get(id int) (*store.User, error)
}

type Service struct {
	users userGetter // 테스트에서는 가짜 구현을 끼워 넣기 쉬움
}
```

## Accept interfaces, return structs

```
✅ 함수 파라미터는 인터페이스로 받기 → 유연성
✅ 반환 타입은 구체 타입(구조체 포인터)으로 → 호출자가 모든 기능 사용 가능
```

```go
func NewService(users userGetter) *Service // 좋은 시그니처
```

## 테스트에서 가짜 구현 끼우기

```go
package main

import (
	"errors"
	"fmt"
)

type User struct {
	ID   int
	Name string
}

type userGetter interface {
	Get(id int) (*User, error)
}

type Greeter struct {
	users userGetter
}

func (g *Greeter) Greet(id int) string {
	u, err := g.users.Get(id)
	if err != nil {
		return "누구세요?"
	}
	return "안녕하세요, " + u.Name
}

// 테스트용 가짜 저장소 (mock 라이브러리 없이도 충분)
type fakeUsers map[int]*User

func (f fakeUsers) Get(id int) (*User, error) {
	if u, ok := f[id]; ok {
		return u, nil
	}
	return nil, errors.New("not found")
}

func main() {
	g := &Greeter{users: fakeUsers{1: {ID: 1, Name: "alice"}}}
	fmt.Println(g.Greet(1))
	fmt.Println(g.Greet(2))
	// 출력:
	// 안녕하세요, alice
	// 누구세요?
}
```

## 함수를 인터페이스로: HandlerFunc 패턴

```go
package main

import "fmt"

type Handler interface {
	Serve(req string) string
}

// 함수 타입에 메서드를 달아 인터페이스를 만족시킴
type HandlerFunc func(req string) string

func (f HandlerFunc) Serve(req string) string { return f(req) }

func run(h Handler) {
	fmt.Println(h.Serve("ping"))
}

func main() {
	run(HandlerFunc(func(req string) string {
		return req + " → pong"
	}))
	// 출력: ping → pong
}
```

`net/http`의 `http.Handler`와 `http.HandlerFunc`가 정확히 이 구조입니다.

# 8. 인터페이스 비교와 비용

```
- 인터페이스 값은 == 로 비교 가능 (동적 타입과 값이 모두 같을 때 true)
- 단, 동적 타입이 비교 불가(슬라이스, 맵)면 == 에서 runtime panic
- 인터페이스를 통한 메서드 호출은 간접 호출이라 inline 최적화가 어려움
  → 대부분 무시해도 되는 수준, 핫 루프에서만 신경 쓰기
```

## 정리

- 인터페이스는 메서드 집합이며, 메서드만 맞으면 자동으로 구현 (implements 없음)
- `io.Reader`, `io.Writer`, `fmt.Stringer`, `error`처럼 작은 인터페이스가 Go 스타일
- `any`는 모든 타입, 값을 꺼낼 때는 타입 단언 `v.(T)` 또는 타입 스위치
- 포인터 리시버 메서드는 `*T`만 인터페이스를 만족
- 인터페이스 값은 (타입, 값) 쌍이라 nil 포인터를 담으면 `!= nil`
- 인터페이스는 사용하는 쪽에서 작게 정의, "Accept interfaces, return structs"
- `var _ I = (*T)(nil)`로 구현 여부를 컴파일 타임에 확인
