# 제네릭 - Go 1.18에 들어온 타입 파라미터

## 들어가며

Go는 오랫동안 제네릭이 없는 언어로 유명했습니다. 그래서 이런 코드를 써야 했습니다.

```go
func SumInts(nums []int) int { ... }
func SumFloats(nums []float64) float64 { ... } // 로직은 똑같은데 타입만 다름

func Contains(items []interface{}, target interface{}) bool { ... } // 타입 안정성 포기
```

Go 1.18(2022년 3월)부터 **타입 파라미터**가 들어왔고, 이후 버전마다 조금씩 확장되고 있습니다.

```
Go 1.18  타입 파라미터, 제약(constraint), any, comparable
Go 1.21  slices, maps, cmp 패키지 (제네릭 기반 표준 라이브러리), min/max 내장 함수
Go 1.24  제네릭 타입 별칭 (type A[T any] = B[T])
Go 1.26  자기 자신을 참조하는 제네릭 타입 제약 허용
Go 1.27  제네릭 메서드 (메서드에 자체 타입 파라미터 선언)
```

TypeScript 제네릭과 비슷하지만, **Go는 타입 파라미터가 무엇을 할 수 있는지 제약(constraint)으로 명확히 정의**해야 합니다.

# 1. 제네릭 함수

## 기본 문법

```go
package main

import "fmt"

// [T any]: 타입 파라미터 T, 제약은 any (아무 타입)
func Map[T, U any](items []T, f func(T) U) []U {
	result := make([]U, 0, len(items))
	for _, item := range items {
		result = append(result, f(item))
	}
	return result
}

func Filter[T any](items []T, pred func(T) bool) []T {
	var result []T
	for _, item := range items {
		if pred(item) {
			result = append(result, item)
		}
	}
	return result
}

func main() {
	nums := []int{1, 2, 3, 4}

	// 타입 인자를 명시
	strs := Map[int, string](nums, func(n int) string { return fmt.Sprint(n * 10) })

	// 대부분은 추론됨
	evens := Filter(nums, func(n int) bool { return n%2 == 0 })

	fmt.Println(strs, evens)
	// 출력: [10 20 30 40] [2 4]
}
```

```
TypeScript: function map<T, U>(items: T[], f: (t: T) => U): U[]
Go:         func Map[T, U any](items []T, f func(T) U) []U
```

# 2. 제약 (Constraints)

## 제약이 필요한 이유

```go
package main

func Sum[T any](nums []T) T {
	var total T
	for _, n := range nums {
		total += n // 컴파일 에러
	}
	return total
}
```

```
invalid operation: operator + not defined on total (variable of type T constrained by any)
```

`any`는 "아무 타입"이라서 `+` 연산이 가능하다는 보장이 없습니다. **T로 무엇을 할 수 있는지 제약으로 알려줘야** 합니다.

## 타입 집합으로 제약 만들기

```go
package main

import "fmt"

// 인터페이스를 "타입 집합"으로 사용
type Number interface {
	~int | ~int8 | ~int16 | ~int32 | ~int64 |
		~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 |
		~float32 | ~float64
}

func Sum[T Number](nums []T) T {
	var total T
	for _, n := range nums {
		total += n
	}
	return total
}

type Score int // 기반 타입이 int 인 새 타입

func main() {
	fmt.Println(Sum([]int{1, 2, 3}))
	fmt.Println(Sum([]float64{1.5, 2.5}))
	fmt.Println(Sum([]Score{90, 80})) // ~int 덕분에 가능
	// 출력:
	// 6
	// 4
	// 170
}
```

```
int   → 정확히 int 타입만
~int  → 기반 타입(underlying type)이 int 인 모든 타입 (type Score int 포함)
A | B → A 또는 B
```

## 표준 제약

```go
package main

import (
	"cmp"
	"fmt"
)

// comparable: == , != 가 가능한 타입 (맵 키로 쓸 수 있는 타입)
func IndexOf[T comparable](items []T, target T) int {
	for i, v := range items {
		if v == target {
			return i
		}
	}
	return -1
}

// cmp.Ordered: < <= > >= 가 가능한 타입 (정수, 실수, 문자열)
func MaxOf[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func main() {
	fmt.Println(IndexOf([]string{"a", "b", "c"}, "c"))
	fmt.Println(MaxOf(3, 7), MaxOf("apple", "banana"))
	// 출력:
	// 2
	// 7 banana
}
```

```
any           → 모든 타입 (interface{} 별칭)
comparable    → == 비교 가능 (내장)
cmp.Ordered   → 크기 비교 가능 (Go 1.21+)
```

## 메서드 제약

```go
package main

import (
	"fmt"
	"strconv"
)

// String() 메서드를 가진 타입만
type Stringer interface {
	String() string
}

func JoinAll[T Stringer](items []T, sep string) string {
	result := ""
	for i, item := range items {
		if i > 0 {
			result += sep
		}
		result += item.String()
	}
	return result
}

type UserID int

func (id UserID) String() string { return "user-" + strconv.Itoa(int(id)) }

// 타입 집합 + 메서드 조합도 가능
type IntStringer interface {
	~int
	String() string
}

func Double[T IntStringer](v T) string {
	return (v * 2).String()
}

func main() {
	fmt.Println(JoinAll([]UserID{1, 2, 3}, ", "))
	fmt.Println(Double(UserID(21)))
	// 출력:
	// user-1, user-2, user-3
	// user-42
}
```

> `~int | ~string` 같은 타입 집합이 들어간 인터페이스는 **제약으로만** 쓸 수 있고, 일반 변수 타입으로는 쓸 수 없습니다.

# 3. 제네릭 타입

## 제네릭 구조체

```go
package main

import (
	"errors"
	"fmt"
)

type Stack[T any] struct {
	items []T
}

func (s *Stack[T]) Push(v T) {
	s.items = append(s.items, v)
}

func (s *Stack[T]) Pop() (T, error) {
	var zero T // 타입 파라미터의 제로값
	if len(s.items) == 0 {
		return zero, errors.New("빈 스택")
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, nil
}

func (s *Stack[T]) Len() int { return len(s.items) }

func main() {
	var s Stack[string] // 타입 인자 명시 필요
	s.Push("a")
	s.Push("b")

	v, _ := s.Pop()
	fmt.Println(v, s.Len())
	// 출력: b 1

	var nums Stack[int]
	_, err := nums.Pop()
	fmt.Println(err)
	// 출력: 빈 스택
}
```

## 제네릭 맵 기반 캐시

```go
package main

import (
	"fmt"
	"sync"
)

type Cache[K comparable, V any] struct {
	mu   sync.RWMutex
	data map[K]V
}

func NewCache[K comparable, V any]() *Cache[K, V] {
	return &Cache[K, V]{data: make(map[K]V)}
}

func (c *Cache[K, V]) Set(key K, val V) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.data[key] = val
}

func (c *Cache[K, V]) Get(key K) (V, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()
	v, ok := c.data[key]
	return v, ok
}

type User struct{ Name string }

func main() {
	c := NewCache[int, User]()
	c.Set(1, User{"alice"})

	u, ok := c.Get(1)
	fmt.Println(u.Name, ok)
	// 출력: alice true
}
```

## 제네릭 타입 별칭 (Go 1.24+)

```go
type Set[T comparable] = map[T]struct{} // 별칭에도 타입 파라미터 사용 가능
```

# 4. 제네릭 메서드 (Go 1.27+)

Go 1.26까지는 **메서드가 자체 타입 파라미터를 가질 수 없었습니다.** 그래서 `Stack[T]`에서 `Map`을 만들려면 메서드 대신 함수로 빼야 했습니다.

```go
// Go 1.26 까지의 방식
func MapStack[T, U any](s *Stack[T], f func(T) U) *Stack[U]
```

Go 1.27부터는 메서드에도 타입 파라미터를 선언할 수 있어서 **메서드 체이닝**이 가능해졌습니다.

```go
package main

import (
	"fmt"
	"strings"
)

type List[T any] struct {
	items []T
}

func (l *List[T]) Push(v T) *List[T] {
	l.items = append(l.items, v)
	return l
}

// 메서드 자체의 타입 파라미터 U
func (l *List[T]) Map[U any](f func(T) U) *List[U] {
	out := &List[U]{}
	for _, v := range l.items {
		out.Push(f(v))
	}
	return out
}

func main() {
	l := &List[string]{}
	l.Push("go").Push("rust")

	lengths := l.Map(func(s string) int { return len(s) })
	upper := l.Map(strings.ToUpper)

	fmt.Println(lengths.items, upper.items)
	// 출력: [2 4] [GO RUST]
}
```

```
제약사항:
- 인터페이스에는 제네릭 메서드를 선언할 수 없음
  (interface method must have no type parameters)
- 표준 라이브러리 예: math/rand/v2 의 (*Rand).N[Int intType](n Int) Int
```

# 5. 자기 참조 제약 (Go 1.26+)

"자기 자신과 연산할 수 있는 타입" 같은 제약을 직접 표현할 수 있게 되었습니다.

```go
package main

import "fmt"

// A는 자기 자신(A)을 받아 A를 반환하는 Add 메서드를 가져야 함
type Adder[A Adder[A]] interface {
	Add(A) A
}

func SumAll[A Adder[A]](items []A) A {
	var total A
	for _, v := range items {
		total = total.Add(v)
	}
	return total
}

type Vec struct{ X, Y int }

func (v Vec) Add(o Vec) Vec { return Vec{v.X + o.X, v.Y + o.Y} }

func main() {
	fmt.Println(SumAll([]Vec{{1, 2}, {3, 4}, {5, 6}}))
	// 출력: {9 12}
}
```

# 6. 표준 라이브러리의 제네릭

제네릭을 직접 짤 일보다 **이미 만들어진 것을 쓸 일이 훨씬 많습니다.**

```go
package main

import (
	"cmp"
	"fmt"
	"maps"
	"slices"
	"sync/atomic"
)

type Person struct {
	Name string
	Age  int
}

func main() {
	people := []Person{{"bob", 30}, {"alice", 25}, {"carol", 30}}

	// 여러 기준 정렬: 나이 → 이름
	slices.SortFunc(people, func(a, b Person) int {
		return cmp.Or(
			cmp.Compare(a.Age, b.Age),
			cmp.Compare(a.Name, b.Name),
		)
	})
	fmt.Println(people)
	// 출력: [{alice 25} {bob 30} {carol 30}]

	oldest := slices.MaxFunc(people, func(a, b Person) int { return cmp.Compare(a.Age, b.Age) })
	fmt.Println(oldest.Name)
	// 출력: bob

	m := map[string]int{"b": 2, "a": 1}
	fmt.Println(slices.Sorted(maps.Keys(m)))
	// 출력: [a b]

	// min, max 내장 함수 (Go 1.21+)
	fmt.Println(min(3, 1, 2), max(2.5, 1.0))
	// 출력: 1 2.5

	// 타입 안전한 atomic
	var p atomic.Pointer[Person]
	p.Store(&people[0])
	fmt.Println(p.Load().Name)
	// 출력: alice
}
```

# 7. 제네릭은 언제 쓸까

## 쓰면 좋은 경우

```
✅ 슬라이스, 맵, 채널에 대한 범용 연산 (Map, Filter, Chunk ...)
✅ 범용 자료구조 (Stack, Queue, LinkedList, Tree, Cache, Set)
✅ 여러 타입에 대해 "완전히 같은" 로직이 반복될 때
✅ any + 타입 단언을 쓰던 코드를 타입 안전하게 바꿀 때
```

## 쓰지 않는 게 나은 경우

```
❌ 메서드 호출만 필요하면 → 그냥 인터페이스 파라미터로 충분
   func Print[T fmt.Stringer](v T)  보다  func Print(v fmt.Stringer)

❌ 타입마다 구현이 다르면 → 인터페이스 + 메서드

❌ "나중에 쓸지도 몰라서" 미리 제네릭화 → 코드만 복잡해짐
```

> Go 팀의 가이드: **"타입 파라미터가 필요하다는 게 명확할 때만 쓰고, 처음에는 구체 타입으로 작성하라."**

## 인터페이스 vs 제네릭

```go
// 인터페이스: 런타임에 다양한 타입을 한 슬라이스에 섞을 수 있음
shapes := []Shape{Rect{}, Circle{}}

// 제네릭: 컴파일 타임에 하나의 타입으로 고정됨
var s Stack[Rect] // Rect 만 들어감
```

# 8. 동작 방식 (참고)

```
Go 제네릭 구현 = GC Shape Stenciling + 딕셔너리

- 메모리 모양(GC shape)이 같은 타입끼리 코드를 공유
  예: 모든 포인터 타입은 하나의 구현을 공유
- 타입별 정보는 숨겨진 딕셔너리 인자로 전달

→ C++ 템플릿처럼 타입마다 코드를 전부 복사하지 않아서 바이너리가 덜 커짐
→ 대신 경우에 따라 인터페이스보다 느릴 수도 있음 (핫 경로면 벤치마크로 확인)
```

## 정리

- `func F[T 제약](...)`, `type S[T 제약] struct{}` 형태로 타입 파라미터 선언
- 제약은 인터페이스로 정의: 메서드 집합 + 타입 집합(`~int | ~float64`)
- 표준 제약 `any`, `comparable`, `cmp.Ordered`
- 대부분 타입 인자는 추론되지만 제네릭 타입을 선언할 때는 명시
- Go 1.24 제네릭 타입 별칭, 1.26 자기 참조 제약, 1.27 제네릭 메서드 추가
- `slices`, `maps`, `cmp`, `sync/atomic`의 제네릭 API를 먼저 활용
- 메서드 호출만 필요하면 인터페이스, 같은 로직이 타입만 달리 반복되면 제네릭
