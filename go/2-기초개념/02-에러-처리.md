# 에러 처리 - try/catch 없이 값으로 다루는 에러

## 들어가며

Go 코드를 처음 보면 가장 눈에 띄는 게 이 패턴입니다.

```go
result, err := doSomething()
if err != nil {
	return err
}
```

"왜 이렇게 번거롭게 하지?" 싶지만 이유가 있습니다.

```
try/catch (JS, Java):
- 어떤 함수가 에러를 던지는지 시그니처만 보고 알 수 없음
- 에러가 어디서 튀어나와서 어디까지 전파될지 추적하기 어려움

Go:
- 에러는 그냥 "반환값" → 함수 시그니처에 에러 가능성이 드러남
- 호출한 바로 그 자리에서 처리 방법을 결정해야 함
- 제어 흐름이 눈에 보임
```

Go 블로그의 유명한 글 제목처럼 **"Errors are values"** 입니다.

# 1. error 타입

```go
// 내장 인터페이스
type error interface {
	Error() string
}
```

`Error() string` 메서드만 있으면 무엇이든 에러가 될 수 있습니다.

## 에러 만들기

```go
package main

import (
	"errors"
	"fmt"
)

func main() {
	err1 := errors.New("파일을 찾을 수 없음")
	err2 := fmt.Errorf("사용자 %d를 찾을 수 없음", 42)

	fmt.Println(err1)
	fmt.Println(err2)
	// 출력:
	// 파일을 찾을 수 없음
	// 사용자 42를 찾을 수 없음
}
```

```
에러 메시지 관례:
✅ 소문자로 시작, 마침표 없음 → 다른 에러에 이어 붙여지기 때문
   "open config: no such file or directory"
❌ "Failed to open config."
```

# 2. 에러 처리의 기본 흐름

```go
package main

import (
	"fmt"
	"os"
	"strconv"
	"strings"
)

func readPort(path string) (int, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return 0, fmt.Errorf("설정 파일 읽기: %w", err)
	}

	port, err := strconv.Atoi(strings.TrimSpace(string(data)))
	if err != nil {
		return 0, fmt.Errorf("포트 파싱: %w", err)
	}

	if port < 1 || port > 65535 {
		return 0, fmt.Errorf("잘못된 포트 번호: %d", port)
	}
	return port, nil
}

func main() {
	port, err := readPort("/없는/경로/port.txt")
	if err != nil {
		fmt.Println("에러:", err)
		return
	}
	fmt.Println(port)
	// 출력: 에러: 설정 파일 읽기: open /없는/경로/port.txt: no such file or directory
}
```

에러가 위로 올라갈 때마다 **맥락(context)이 앞에 붙어서** 최종 메시지만 봐도 어디서 무슨 일이 있었는지 알 수 있습니다. 스택 트레이스 대신 사람이 읽는 경로를 만드는 셈입니다.

# 3. 에러 래핑 (Wrapping, Go 1.13+)

## %w 로 감싸기

```go
package main

import (
	"errors"
	"fmt"
	"io/fs"
	"os"
)

func loadConfig() error {
	_, err := os.Open("config.yaml")
	if err != nil {
		return fmt.Errorf("loadConfig: %w", err) // %w: 원본 에러를 감쌈
	}
	return nil
}

func main() {
	err := loadConfig()

	fmt.Println(err)
	// 출력: loadConfig: open config.yaml: no such file or directory

	// 감싸져 있어도 원본 에러를 찾을 수 있음
	fmt.Println(errors.Is(err, fs.ErrNotExist))
	// 출력: true

	// 한 겹 벗기기
	fmt.Println(errors.Unwrap(err))
	// 출력: open config.yaml: no such file or directory
}
```

```
%w → 에러를 감쌈 (errors.Is / errors.As 로 원본 확인 가능)
%v → 문자열로만 합침 (원본 에러와의 연결이 끊김)
```

> 내부 구현 에러를 외부에 노출하고 싶지 않으면(예: DB 드라이버 에러를 API 사용자에게 숨기기) 의도적으로 `%v`를 쓰기도 합니다.

# 4. 센티널 에러 (Sentinel Error)

미리 정의해 둔 에러 값으로, `errors.Is`로 비교합니다.

```go
package main

import (
	"errors"
	"fmt"
)

// 관례: Err 로 시작하는 패키지 변수
var (
	ErrNotFound     = errors.New("not found")
	ErrUnauthorized = errors.New("unauthorized")
)

func findUser(id int) (string, error) {
	if id != 1 {
		return "", fmt.Errorf("findUser(%d): %w", id, ErrNotFound)
	}
	return "alice", nil
}

func main() {
	_, err := findUser(2)

	// ❌ err == ErrNotFound → 래핑되어 있으면 false
	fmt.Println(err == ErrNotFound)

	// ✅ errors.Is 는 래핑 체인을 따라가며 비교
	if errors.Is(err, ErrNotFound) {
		fmt.Println("404 응답")
	}
	// 출력:
	// false
	// 404 응답
}
```

표준 라이브러리의 센티널 에러 예시:

```
io.EOF              → 읽을 데이터가 더 없음 (정상 종료 신호)
sql.ErrNoRows       → 조회 결과 없음
fs.ErrNotExist      → 파일 없음
context.Canceled    → 컨텍스트 취소됨
http.ErrServerClosed → 서버가 정상 종료됨
```

# 5. 커스텀 에러 타입

에러에 추가 정보(상태 코드, 필드 이름 등)를 담고 싶을 때 씁니다.

```go
package main

import (
	"errors"
	"fmt"
)

type ValidationError struct {
	Field   string
	Message string
}

func (e *ValidationError) Error() string {
	return fmt.Sprintf("%s: %s", e.Field, e.Message)
}

func validateAge(age int) error {
	if age < 0 {
		return &ValidationError{Field: "age", Message: "0 이상이어야 함"}
	}
	return nil
}

func register(age int) error {
	if err := validateAge(age); err != nil {
		return fmt.Errorf("register: %w", err)
	}
	return nil
}

func main() {
	err := register(-1)

	// errors.As: 체인에서 특정 "타입"의 에러를 찾아 꺼냄
	var ve *ValidationError
	if errors.As(err, &ve) {
		fmt.Println("필드:", ve.Field, "/ 메시지:", ve.Message)
	}

	// Go 1.26+: 제네릭 버전 errors.AsType (변수 선언이 필요 없음)
	if ve, ok := errors.AsType[*ValidationError](err); ok {
		fmt.Println("AsType:", ve.Field)
	}
	// 출력:
	// 필드: age / 메시지: 0 이상이어야 함
	// AsType: age
}
```

```
errors.Is(err, target)       → "이 값"과 같은 에러가 체인에 있나? (센티널 에러)
errors.As(err, &target)      → "이 타입"의 에러가 체인에 있나? 있으면 꺼내줌
errors.AsType[T](err)        → As의 제네릭 버전 (Go 1.26+)
```

## Is 메서드로 비교 규칙 커스터마이징

```go
package main

import (
	"errors"
	"fmt"
)

type HTTPError struct {
	Code int
}

func (e *HTTPError) Error() string { return fmt.Sprintf("http %d", e.Code) }

// 코드만 같으면 같은 에러로 취급
func (e *HTTPError) Is(target error) bool {
	t, ok := target.(*HTTPError)
	return ok && t.Code == e.Code
}

var ErrNotFound = &HTTPError{Code: 404}

func main() {
	err := fmt.Errorf("fetch: %w", &HTTPError{Code: 404})
	fmt.Println(errors.Is(err, ErrNotFound))
	// 출력: true
}
```

# 6. 여러 에러 합치기 (Go 1.20+)

## errors.Join

```go
package main

import (
	"errors"
	"fmt"
)

var ErrEmptyName = errors.New("이름이 비어 있음")
var ErrInvalidAge = errors.New("나이가 잘못됨")

func validate(name string, age int) error {
	var errs []error
	if name == "" {
		errs = append(errs, ErrEmptyName)
	}
	if age < 0 {
		errs = append(errs, ErrInvalidAge)
	}
	return errors.Join(errs...) // errs가 비어 있으면 nil 반환
}

func main() {
	err := validate("", -1)
	fmt.Println(err)
	// 출력:
	// 이름이 비어 있음
	// 나이가 잘못됨

	fmt.Println(errors.Is(err, ErrInvalidAge))
	// 출력: true

	fmt.Println(validate("go", 1) == nil)
	// 출력: true
}
```

## %w 여러 개

```go
err := fmt.Errorf("저장 실패: %w, 롤백 실패: %w", saveErr, rollbackErr)
// errors.Is(err, saveErr) 와 errors.Is(err, rollbackErr) 모두 true
```

# 7. 에러를 어떻게 처리할까

## 처리 전략

```
1. 그대로 반환 (맥락 추가)       → 가장 흔함: return fmt.Errorf("...: %w", err)
2. 재시도                        → 네트워크 일시 오류 등
3. 기본값으로 대체               → 설정 파일이 없으면 기본 설정 사용
4. 로그 남기고 계속 진행          → 부가 기능 실패 (예: 캐시 저장 실패)
5. 프로그램 종료                  → main 에서만 (log.Fatal, os.Exit)
```

## 에러는 한 번만 처리한다

```go
// ❌ 로그도 찍고 반환도 함 → 같은 에러 로그가 여러 번 찍힘
if err != nil {
	log.Printf("유저 조회 실패: %v", err)
	return err
}

// ✅ 맥락만 붙여서 반환하고, 최상위(핸들러, main)에서 한 번 로그
if err != nil {
	return fmt.Errorf("유저 조회: %w", err)
}
```

## 에러를 무시할 때는 명시적으로

```go
_ = file.Close() // "일부러 무시함"을 드러냄
```

`errcheck` 린터(golangci-lint 기본 포함)가 처리하지 않은 에러를 찾아줍니다.

## HTTP 핸들러에서 에러 → 상태 코드 매핑

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
)

var ErrNotFound = errors.New("not found")
var ErrForbidden = errors.New("forbidden")

func getPost(id string) (string, error) {
	switch id {
	case "1":
		return "첫 글", nil
	case "2":
		return "", fmt.Errorf("getPost(%s): %w", id, ErrForbidden)
	default:
		return "", fmt.Errorf("getPost(%s): %w", id, ErrNotFound)
	}
}

func handler(w http.ResponseWriter, r *http.Request) {
	post, err := getPost(r.PathValue("id"))
	switch {
	case errors.Is(err, ErrNotFound):
		http.Error(w, "게시글 없음", http.StatusNotFound)
	case errors.Is(err, ErrForbidden):
		http.Error(w, "권한 없음", http.StatusForbidden)
	case err != nil:
		http.Error(w, "서버 에러", http.StatusInternalServerError)
	default:
		fmt.Fprint(w, post)
	}
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /posts/{id}", handler)

	for _, id := range []string{"1", "2", "3"} {
		rec := httptest.NewRecorder()
		mux.ServeHTTP(rec, httptest.NewRequest("GET", "/posts/"+id, nil))
		fmt.Println(id, rec.Code)
	}
	// 출력:
	// 1 200
	// 2 403
	// 3 404
}
```

# 8. error vs panic

```
error 를 쓰는 경우 (거의 모든 경우):
✅ 파일 없음, 네트워크 실패, 잘못된 입력 등 "예상 가능한" 실패

panic 을 쓰는 경우 (드묾):
✅ 프로그래머의 실수로 절대 일어나면 안 되는 상황 (인덱스 범위 초과, nil 역참조)
✅ 초기화 단계에서 계속 진행이 불가능할 때 (regexp.MustCompile 같은 Must 함수)
```

```go
// Must 패턴: 실패하면 panic → 패키지 변수 초기화처럼 "상수에 가까운" 입력에만 사용
var emailRe = regexp.MustCompile(`^[^@]+@[^@]+$`)
```

panic과 recover는 다음 문서에서 자세히 다룹니다.

# 9. 에러 처리 코드 줄이기 팁

`if err != nil`이 반복되는 게 싫다면 이런 기법이 있습니다.

## 에러를 상태로 들고 있기 (bufio.Scanner 스타일)

```go
package main

import (
	"bytes"
	"encoding/binary"
	"fmt"
)

type writer struct {
	buf bytes.Buffer
	err error // 첫 에러를 기억
}

func (w *writer) write(v any) {
	if w.err != nil {
		return // 이미 실패했으면 아무것도 안 함
	}
	w.err = binary.Write(&w.buf, binary.BigEndian, v)
}

func main() {
	w := &writer{}
	w.write(int32(1))
	w.write(int64(2))
	w.write("문자열은 binary.Write 불가") // 여기서 실패
	w.write(int32(3))               // 무시됨

	if w.err != nil {
		fmt.Println("에러:", w.err)
	}
	fmt.Println(w.buf.Len())
	// 출력:
	// 에러: binary.Write: some values are not fixed-sized in type string
	// 12
}
```

`bufio.Scanner`의 `Scan()` 후 `Err()`, `sql.Rows`의 `Next()` 후 `Err()`가 이 방식입니다.

## 정리

- 에러는 반환값이며, 호출 직후 `if err != nil`로 처리
- `fmt.Errorf("맥락: %w", err)`로 감싸서 위로 전달, 메시지는 소문자·마침표 없이
- 특정 에러 값 확인은 `errors.Is`, 특정 타입 꺼내기는 `errors.As` / `errors.AsType`(1.26+)
- 센티널 에러는 `var ErrXxx = errors.New(...)`, 추가 정보가 필요하면 커스텀 에러 타입
- 여러 에러는 `errors.Join` 또는 `%w` 여러 개 (1.20+)
- 에러는 한 번만 처리 (로그 + 반환 동시에 하지 않기)
- panic은 프로그래머 실수나 초기화 실패처럼 복구 불가능한 상황에만
