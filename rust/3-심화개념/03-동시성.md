# 동시성 (Concurrency) - 겁 없는 동시성

## 들어가며

멀티스레드 프로그래밍은 어렵습니다. 데이터 경쟁, 교착 상태(deadlock), 락을 깜빡하는 실수는 재현도 어렵고 디버깅도 고통스럽습니다.

Rust는 소유권과 타입 시스템으로 **데이터 경쟁을 컴파일 타임에** 막습니다. 이것을 Rust 커뮤니티는 "Fearless Concurrency(겁 없는 동시성)"라고 부릅니다.

```
JS (Node.js)
- 기본은 싱글 스레드 이벤트 루프
- 병렬 처리는 Worker Threads, 메모리 공유는 SharedArrayBuffer 로 제한적

Go
- 고루틴 + 채널, 공유 메모리 버그는 런타임 race detector 로 검출

Rust
- OS 스레드 + 채널 + Mutex/Arc
- 공유 데이터를 락 없이 수정하는 코드는 아예 컴파일되지 않음
- 비동기(async)는 별도 문서 → 04-async-await
```

> Rust가 막아주는 것은 **데이터 경쟁**입니다. 교착 상태나 논리적인 경쟁 조건(race condition)은 여전히 개발자가 주의해야 합니다.

# 1. 스레드

## spawn과 join

```rust
use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..=3 {
            println!("스레드: {i}");
            thread::sleep(Duration::from_millis(1));
        }
        "스레드 작업 완료" // 반환값
    });

    for i in 1..=2 {
        println!("메인: {i}");
        thread::sleep(Duration::from_millis(1));
    }

    // join: 스레드가 끝날 때까지 기다리고 반환값 받기
    // join 하지 않으면 메인 스레드가 끝날 때 다른 스레드도 강제 종료됨
    let result = handle.join().unwrap();
    println!("{result}");
}
```

## move 클로저

```rust
// ❌ 컴파일 에러 예제
use std::thread;

fn main() {
    let v = vec![1, 2, 3];
    let handle = thread::spawn(|| {
        println!("{v:?}"); // v 를 빌리려 함
    });
    handle.join().unwrap();
}
```

```
error[E0373]: closure may outlive the current function, but it borrows `v`, which is owned by the current function
```

새 스레드는 `main`보다 오래 살 수도 있으므로 `v`의 참조를 넘길 수 없습니다. `move`로 소유권을 넘깁니다.

```rust
use std::thread;

fn main() {
    let v = vec![1, 2, 3];
    let handle = thread::spawn(move || {
        println!("{v:?}");
        v.len()
    });
    // println!("{v:?}"); // ❌ v 는 이동됨
    println!("길이 {}", handle.join().unwrap());
}
```

## 스코프 스레드 (Rust 1.63+)

스코프가 끝나기 전에 모든 스레드가 join되는 것이 보장되면 **지역 변수를 빌려줄 수 있습니다.**

```rust
use std::thread;

fn main() {
    let mut numbers = vec![1, 2, 3, 4, 5, 6, 7, 8];
    let label = String::from("합계");

    let (left, right) = numbers.split_at_mut(4);

    thread::scope(|s| {
        s.spawn(|| {
            for n in left.iter_mut() {
                *n *= 10; // 왼쪽 절반을 가변 빌림
            }
        });
        s.spawn(|| {
            for n in right.iter_mut() {
                *n *= 100; // 오른쪽 절반을 가변 빌림 (겹치지 않으므로 OK)
            }
        });
        s.spawn(|| println!("{label} 계산 중")); // 불변 빌림
    }); // 여기서 모든 스레드 자동 join

    let total: i32 = numbers.iter().sum();
    println!("{numbers:?} {label}={total}");
}
```

# 2. 메시지 전달 - 채널

> "메모리를 공유해서 통신하지 말고, 통신해서 메모리를 공유하라" (Go 언어의 슬로건)

```rust
use std::sync::mpsc; // multiple producer, single consumer
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel();

    // 생산자 여러 개: Sender 를 clone
    for id in 0..3 {
        let tx = tx.clone();
        thread::spawn(move || {
            for j in 0..2 {
                tx.send(format!("worker {id}: 메시지 {j}")).unwrap();
                thread::sleep(Duration::from_millis(1));
            }
            // tx drop
        });
    }
    drop(tx); // 원본 Sender 도 drop 해야 모든 송신자가 사라졌을 때 수신 루프가 끝남

    // 수신: 모든 Sender 가 drop 되면 반복 종료
    for msg in rx {
        println!("받음: {msg}");
    }
    println!("모든 작업자 종료");
}
```

## 소유권이 채널을 따라 이동

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();
    thread::spawn(move || {
        let val = String::from("hi");
        tx.send(val).unwrap();
        // println!("{val}"); // ❌ val 은 채널로 이동됨 → 보낸 뒤 수정하는 버그를 원천 차단
    });
    println!("{}", rx.recv().unwrap());
}
```

## 동기 채널 (bounded)

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    // 버퍼 크기 2: 가득 차면 send 가 블로킹 (백프레셔)
    let (tx, rx) = mpsc::sync_channel::<u32>(2);

    let producer = thread::spawn(move || {
        for i in 0..5 {
            tx.send(i).unwrap();
            println!("보냄 {i}");
        }
    });

    for v in rx.iter() {
        println!("  처리 {v}");
    }
    producer.join().unwrap();
}
```

- `recv()`: 블로킹 대기, `try_recv()`: 즉시 반환, `recv_timeout()`: 시간 제한
- 여러 소비자(MPMC)나 `select`가 필요하면 `crossbeam-channel` 크레이트, 비동기에서는 `tokio::sync::mpsc`

# 3. 공유 상태 - Mutex와 Arc

## Mutex<T>

```rust
use std::sync::Mutex;

fn main() {
    let m = Mutex::new(5);

    {
        let mut num = m.lock().unwrap(); // MutexGuard<i32> 획득 (다른 스레드는 대기)
        *num = 6;
    } // guard drop → 자동 unlock (unlock 을 깜빡할 수 없음)

    println!("m = {:?}", m);
}
```

Rust의 `Mutex<T>`는 **데이터를 락 안에 넣는** 구조라서 락을 잡지 않고는 데이터에 접근할 방법 자체가 없습니다.

## 여러 스레드에서 공유: Arc<Mutex<T>>

```rust
// ❌ 컴파일 에러 예제
use std::rc::Rc;
use std::sync::Mutex;
use std::thread;

fn main() {
    let counter = Rc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Rc::clone(&counter);
        let handle = thread::spawn(move || {
            *counter.lock().unwrap() += 1;
        });
        handles.push(handle);
    }
    for h in handles {
        h.join().unwrap();
    }
}
```

```
error[E0277]: `Rc<std::sync::Mutex<i32>>` cannot be sent between threads safely
```

`Rc`의 참조 카운트 증감은 원자적이지 않아서 스레드 간에 보낼 수 없습니다. 컴파일러가 이를 막아줍니다. **`Arc`(Atomically Reference Counted)**를 씁니다.

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            for _ in 0..1000 {
                *counter.lock().unwrap() += 1;
            }
        }));
    }

    for h in handles {
        h.join().unwrap();
    }
    println!("결과: {}", *counter.lock().unwrap()); // 항상 10000
}
```

## RwLock - 읽기가 많을 때

```rust
use std::collections::HashMap;
use std::sync::{Arc, RwLock};
use std::thread;

fn main() {
    let cache = Arc::new(RwLock::new(HashMap::from([("a", 1)])));

    let readers: Vec<_> = (0..4)
        .map(|i| {
            let cache = Arc::clone(&cache);
            thread::spawn(move || {
                let map = cache.read().unwrap(); // 읽기 락은 여러 스레드가 동시에
                println!("reader {i}: {:?}", map.get("a"));
            })
        })
        .collect();

    {
        let mut map = cache.write().unwrap(); // 쓰기 락은 단독
        map.insert("b", 2);
    }

    for r in readers {
        r.join().unwrap();
    }
    println!("{:?}", cache.read().unwrap().len());
}
```

## 원자적 타입 (Atomics)

카운터나 플래그처럼 단순한 값은 락 없이 원자적 연산으로 처리하는 것이 더 빠릅니다.

```rust
use std::sync::Arc;
use std::sync::atomic::{AtomicBool, AtomicUsize, Ordering};
use std::thread;

fn main() {
    let hits = Arc::new(AtomicUsize::new(0));
    let stop = Arc::new(AtomicBool::new(false));

    let handles: Vec<_> = (0..4)
        .map(|_| {
            let hits = Arc::clone(&hits);
            thread::spawn(move || {
                for _ in 0..1000 {
                    hits.fetch_add(1, Ordering::Relaxed);
                }
            })
        })
        .collect();

    for h in handles {
        h.join().unwrap();
    }
    stop.store(true, Ordering::SeqCst);
    println!("hits={} stop={}", hits.load(Ordering::Relaxed), stop.load(Ordering::SeqCst));
}
```

## 교착 상태 주의

```rust
use std::sync::Mutex;

fn main() {
    let a = Mutex::new(1);

    let guard = a.lock().unwrap();
    // let again = a.lock().unwrap(); // 같은 스레드에서 다시 lock → 교착 상태 또는 panic (재진입 불가)
    println!("{}", *guard);
    drop(guard);

    // 여러 락을 잡을 땐 모든 코드에서 "항상 같은 순서"로 잡기
    let b = Mutex::new(2);
    let (ga, gb) = (a.lock().unwrap(), b.lock().unwrap());
    println!("{}", *ga + *gb);
}
```

- 락은 **최대한 짧게** 잡습니다. 가드를 들고 무거운 작업이나 I/O를 하지 마세요.
- 락을 잡은 스레드가 panic하면 Mutex는 **poisoned** 상태가 되어 `lock()`이 `Err`를 반환합니다.

# 4. Send와 Sync

스레드 안전성은 두 개의 **마커 트레이트**로 표현됩니다. 컴파일러가 자동으로 구현합니다.

```
Send → 이 타입의 값을 다른 스레드로 "이동"해도 안전하다
Sync → 이 타입의 참조(&T)를 여러 스레드가 "공유"해도 안전하다
       (T: Sync  ⟺  &T: Send)
```

| 타입 | Send | Sync | 이유 |
|---|---|---|---|
| `i32`, `String`, `Vec<T>` | ✅ | ✅ | |
| `Rc<T>` | ❌ | ❌ | 카운트 증감이 원자적이지 않음 |
| `Arc<T>` | ✅ (T: Send+Sync) | ✅ | 원자적 카운트 |
| `RefCell<T>`, `Cell<T>` | ✅ | ❌ | 런타임 빌림 카운트가 원자적이지 않음 |
| `Mutex<T>` | ✅ (T: Send) | ✅ (T: Send) | 락으로 보호 |
| `*const T`, `*mut T` | ❌ | ❌ | 원시 포인터는 보장 불가 |
| `MutexGuard<T>` | ❌ | ✅ | 락을 잡은 스레드에서 해제해야 함 |

`thread::spawn`의 시그니처가 이 규칙을 강제합니다.

```rust
// (컴파일 검증 제외) - 표준 라이브러리 시그니처
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T + Send + 'static,
    T: Send + 'static,
```

```
                  싱글 스레드         멀티 스레드
공유 소유권         Rc<T>              Arc<T>
내부 가변성         RefCell<T>         Mutex<T> / RwLock<T>
단순 카운터         Cell<usize>        AtomicUsize
```

# 5. 데이터 병렬 처리: rayon

CPU 작업을 병렬화할 때는 스레드를 직접 다루기보다 `rayon`이 편합니다.

```bash
cargo add rayon
```

```rust
// 외부 크레이트 rayon 필요
use rayon::prelude::*;

fn is_prime(n: u64) -> bool {
    n >= 2 && (2..).take_while(|i| i * i <= n).all(|i| n % i != 0)
}

fn main() {
    // iter() → par_iter() 만 바꾸면 스레드 풀에서 병렬 실행
    let count = (1..200_000u64).into_par_iter().filter(|&n| is_prime(n)).count();
    println!("소수 개수: {count}");

    let mut data: Vec<i32> = (0..1_000).rev().collect();
    data.par_sort();
    let sum: i64 = data.par_iter().map(|&x| x as i64 * 2).sum();
    println!("{} {sum}", data[0]);
}
```

데이터 경쟁이 생길 코드(`par_iter` 안에서 외부 `Vec`에 push 등)는 역시 컴파일되지 않습니다.

# 6. 예제: 간단한 스레드 풀

```rust
use std::sync::{Arc, Mutex, mpsc};
use std::thread;

type Job = Box<dyn FnOnce() + Send + 'static>;

struct ThreadPool {
    workers: Vec<thread::JoinHandle<()>>,
    sender: Option<mpsc::Sender<Job>>,
}

impl ThreadPool {
    fn new(size: usize) -> Self {
        let (sender, receiver) = mpsc::channel::<Job>();
        let receiver = Arc::new(Mutex::new(receiver)); // 여러 워커가 하나의 수신자를 공유

        let workers = (0..size)
            .map(|id| {
                let receiver = Arc::clone(&receiver);
                thread::spawn(move || loop {
                    // lock 은 recv 하는 동안만 잡고, 작업 실행 전에 해제됨
                    let job = receiver.lock().unwrap().recv();
                    match job {
                        Ok(job) => {
                            println!("worker {id} 작업 시작");
                            job();
                        }
                        Err(_) => break, // 송신자가 drop 되면 종료
                    }
                })
            })
            .collect();

        ThreadPool { workers, sender: Some(sender) }
    }

    fn execute<F: FnOnce() + Send + 'static>(&self, f: F) {
        self.sender.as_ref().unwrap().send(Box::new(f)).unwrap();
    }
}

impl Drop for ThreadPool {
    fn drop(&mut self) {
        drop(self.sender.take()); // 채널 닫기 → 워커 루프 종료
        for w in self.workers.drain(..) {
            w.join().unwrap();
        }
        println!("스레드 풀 종료");
    }
}

fn main() {
    let pool = ThreadPool::new(3);
    let results = Arc::new(Mutex::new(Vec::new()));

    for i in 0..6 {
        let results = Arc::clone(&results);
        pool.execute(move || {
            results.lock().unwrap().push(i * i);
        });
    }

    drop(pool); // 모든 작업 완료 대기
    let mut r = results.lock().unwrap().clone();
    r.sort();
    println!("{r:?}");
}
```

러스트 북의 마지막 장(멀티스레드 웹 서버)이 이 구조를 단계별로 만들어 봅니다.

## 정리

- `thread::spawn` + `move` 클로저로 스레드 생성, `join`으로 대기
- `thread::scope`를 쓰면 지역 변수를 스레드에 빌려줄 수 있다
- 채널(`mpsc`)로 메시지를 보내면 소유권도 함께 이동한다
- 공유 상태는 `Arc<Mutex<T>>` / `Arc<RwLock<T>>`, 단순 카운터는 Atomic
- `Send`/`Sync` 마커 트레이트가 스레드 안전하지 않은 타입(`Rc`, `RefCell`)의 사용을 컴파일 타임에 막는다
- CPU 병렬 처리는 `rayon`의 `par_iter()`가 가장 간단하다
- 데이터 경쟁은 막아주지만 교착 상태는 스스로 조심해야 한다
