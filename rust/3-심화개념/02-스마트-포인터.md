# 스마트 포인터 - Box, Rc, RefCell, Weak, Cow

## 들어가며

**스마트 포인터**는 포인터처럼 동작하면서 추가 기능(소유권, 참조 카운팅, 런타임 빌림 검사 등)을 가진 구조체입니다. 사실 `String`과 `Vec<T>`도 스마트 포인터입니다.

일반 참조 `&T`는 데이터를 빌리기만 하지만, 스마트 포인터는 대부분 **데이터를 소유**합니다. 두 개의 트레이트가 핵심입니다.

```
Deref → *ptr 역참조, 메서드 자동 위임 (ptr.len())
Drop  → 스코프를 벗어날 때 정리 작업
```

| 타입 | 한 줄 요약 | 스레드 안전 |
|---|---|---|
| `Box<T>` | 힙에 값 하나를 단독 소유 | T에 따라 |
| `Rc<T>` | 참조 카운팅으로 여러 소유자가 공유 (읽기 전용) | ❌ |
| `Arc<T>` | Rc의 원자적(atomic) 버전 | ✅ |
| `Cell<T>` / `RefCell<T>` | 불변 참조로도 내부 값 수정 (내부 가변성) | ❌ |
| `Mutex<T>` / `RwLock<T>` | 스레드 간 내부 가변성 | ✅ |
| `Weak<T>` | 소유권 없는 약한 참조 (순환 참조 방지) | Rc/Arc 따라 |
| `Cow<'a, T>` | 필요할 때만 복사 (Clone on Write) | |

# 1. Box<T> - 힙에 저장하기

## 기본

```rust
fn main() {
    let b = Box::new(5); // 5 를 힙에 저장, b(포인터)는 스택에
    println!("b = {b}");
    println!("{}", *b + 1); // 역참조
} // b drop → 힙 메모리 해제
```

단순한 값을 Box에 넣을 이유는 거의 없습니다. Box가 필요한 대표 상황은 세 가지입니다.

```
1. 컴파일 타임에 크기를 알 수 없는 타입 (재귀 타입)
2. 큰 데이터를 복사 없이 소유권만 이동하고 싶을 때
3. 트레이트 객체: Box<dyn Trait>
```

## 재귀 타입

```rust
// ❌ 컴파일 에러 예제
enum List {
    Cons(i32, List), // List 안에 List → 크기가 무한
    Nil,
}

fn main() {}
```

```
error[E0072]: recursive type `List` has infinite size
```

```rust
#[derive(Debug)]
enum List {
    Cons(i32, Box<List>), // Box 는 포인터 크기로 고정
    Nil,
}

use List::{Cons, Nil};

fn sum(list: &List) -> i32 {
    match list {
        Cons(v, rest) => v + sum(rest),
        Nil => 0,
    }
}

fn main() {
    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
    println!("{list:?} 합계 {}", sum(&list));
}
```

## 이진 트리

```rust
#[derive(Debug)]
struct Node {
    value: i32,
    left: Option<Box<Node>>,
    right: Option<Box<Node>>,
}

impl Node {
    fn new(value: i32) -> Self {
        Node { value, left: None, right: None }
    }

    fn insert(&mut self, value: i32) {
        let slot = if value < self.value { &mut self.left } else { &mut self.right };
        match slot {
            Some(node) => node.insert(value),
            None => *slot = Some(Box::new(Node::new(value))),
        }
    }

    fn in_order(&self, out: &mut Vec<i32>) {
        if let Some(l) = &self.left {
            l.in_order(out);
        }
        out.push(self.value);
        if let Some(r) = &self.right {
            r.in_order(out);
        }
    }
}

fn main() {
    let mut root = Node::new(50);
    for v in [30, 70, 20, 40, 60, 80] {
        root.insert(v);
    }
    let mut sorted = vec![];
    root.in_order(&mut sorted);
    println!("{sorted:?}");
}
```

# 2. Deref와 Drop

## Deref: 스마트 포인터를 참조처럼

```rust
use std::ops::Deref;

struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(x: T) -> MyBox<T> {
        MyBox(x)
    }
}

impl<T> Deref for MyBox<T> {
    type Target = T;
    fn deref(&self) -> &T {
        &self.0
    }
}

fn hello(name: &str) {
    println!("Hello, {name}!");
}

fn main() {
    let x = 5;
    let y = MyBox::new(x);
    assert_eq!(5, *y); // *y 는 *(y.deref()) 로 변환됨

    let m = MyBox::new(String::from("Rust"));
    // 역참조 강제 변환(deref coercion): &MyBox<String> → &String → &str
    hello(&m);
    println!("{}", m.len()); // String 의 메서드를 바로 호출
}
```

> `Deref`는 스마트 포인터용입니다. 상속 흉내를 내려고 일반 구조체에 `Deref`를 구현하는 것은 안티패턴입니다.

## Drop: 정리 작업

```rust
struct Connection {
    name: String,
}

impl Drop for Connection {
    fn drop(&mut self) {
        println!("[{}] 연결 종료", self.name);
    }
}

fn main() {
    let _a = Connection { name: "db".into() };
    let b = Connection { name: "cache".into() };
    // b.drop(); // ❌ 직접 호출 불가 (이중 해제 방지)
    drop(b);     // std::mem::drop 으로 조기 해제
    println!("main 끝");
}
```

# 3. Rc<T> - 여러 소유자

하나의 값을 **여러 곳에서 소유**해야 할 때 씁니다. 예) 그래프에서 여러 간선이 같은 노드를 가리킴. 마지막 소유자가 사라질 때 해제됩니다.

```rust
use std::rc::Rc;

#[derive(Debug)]
struct Image {
    name: String,
    bytes: Vec<u8>,
}

struct Post {
    title: String,
    thumbnail: Rc<Image>,
}

fn main() {
    let img = Rc::new(Image { name: "cat.png".into(), bytes: vec![0; 1024] });
    println!("카운트: {}", Rc::strong_count(&img)); // 1

    let p1 = Post { title: "글1".into(), thumbnail: Rc::clone(&img) }; // 깊은 복사 아님! 카운트만 +1
    let p2 = Post { title: "글2".into(), thumbnail: img.clone() };    // 같은 의미
    println!("카운트: {}", Rc::strong_count(&img)); // 3

    {
        let _p3 = Post { title: "글3".into(), thumbnail: Rc::clone(&img) };
        println!("카운트: {}", Rc::strong_count(&img)); // 4
    }
    println!("카운트: {}", Rc::strong_count(&img)); // 3

    println!("{} {} {} {}", p1.title, p2.title, p1.thumbnail.name, p2.thumbnail.bytes.len());
    println!("같은 이미지? {}", Rc::ptr_eq(&p1.thumbnail, &p2.thumbnail));
}
```

- `Rc::clone`은 힙 데이터를 복사하지 않고 **참조 카운트만 증가**시킵니다. 관례상 `Rc::clone(&x)`로 써서 깊은 복사가 아님을 드러냅니다.
- `Rc<T>`는 **불변 공유**만 가능합니다. 수정하려면 `RefCell`과 조합합니다.
- `Rc`는 싱글 스레드 전용입니다. 스레드 간에는 `Arc`를 씁니다.

# 4. RefCell<T> - 내부 가변성

## 컴파일 타임 대신 런타임에 빌림 검사

```
Box<T>, 일반 참조  → 빌림 규칙을 컴파일 타임에 검사 (위반 시 컴파일 에러)
RefCell<T>        → 빌림 규칙을 런타임에 검사 (위반 시 panic)
```

컴파일러가 안전하다고 증명하지 못하지만 개발자는 안전함을 아는 경우에 씁니다.

```rust
use std::cell::RefCell;

fn main() {
    let data = RefCell::new(vec![1, 2, 3]);

    // data 자체는 불변인데 내부를 수정할 수 있음
    data.borrow_mut().push(4);

    {
        let r1 = data.borrow();     // Ref<Vec<i32>> (불변 빌림)
        let r2 = data.borrow();     // 불변 빌림 여러 개 OK
        println!("{:?} {:?}", *r1, *r2);
    } // r1, r2 해제

    let result = data.try_borrow_mut(); // 이미 빌려져 있으면 Err (panic 대신)
    println!("가변 빌림 가능? {}", result.is_ok());
    drop(result);

    // 런타임 규칙 위반 → panic
    // let _a = data.borrow_mut();
    // let _b = data.borrow_mut(); // panic: RefCell already borrowed
}
```

## 활용: 목(mock) 객체

```rust
use std::cell::RefCell;

trait Messenger {
    fn send(&self, msg: &str); // &self: 트레이트 설계상 불변
}

struct MockMessenger {
    sent: RefCell<Vec<String>>, // 불변 &self 안에서도 기록하기 위해
}

impl Messenger for MockMessenger {
    fn send(&self, msg: &str) {
        self.sent.borrow_mut().push(msg.to_string());
    }
}

fn notify_quota(m: &dyn Messenger, used: u32, max: u32) {
    if used * 100 / max >= 90 {
        m.send("경고: 할당량의 90% 이상 사용");
    }
}

fn main() {
    let mock = MockMessenger { sent: RefCell::new(vec![]) };
    notify_quota(&mock, 95, 100);
    assert_eq!(mock.sent.borrow().len(), 1);
    println!("{:?}", mock.sent.borrow());
}
```

## Cell<T> - Copy 타입용 가벼운 버전

```rust
use std::cell::Cell;

struct Counter {
    hits: Cell<u32>,
}

impl Counter {
    fn hit(&self) {
        self.hits.set(self.hits.get() + 1); // 참조를 빌려주지 않고 값을 통째로 get/set
    }
}

fn main() {
    let c = Counter { hits: Cell::new(0) };
    c.hit();
    c.hit();
    println!("{}", c.hits.get());
}
```

# 5. Rc<RefCell<T>> - 공유 + 수정

```rust
use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Account {
    owner: String,
    balance: i64,
}

fn main() {
    let shared = Rc::new(RefCell::new(Account { owner: "kim".into(), balance: 0 }));

    let wallet_app = Rc::clone(&shared);
    let bank_app = Rc::clone(&shared);

    wallet_app.borrow_mut().balance += 1000;
    bank_app.borrow_mut().balance -= 300;

    println!("{:?}", shared.borrow());
    println!("{}", shared.borrow().owner);
}
```

```
싱글 스레드: Rc<RefCell<T>>
멀티 스레드: Arc<Mutex<T>> 또는 Arc<RwLock<T>>   → 03-동시성 문서
```

> `Rc<RefCell<T>>`가 코드 곳곳에 보인다면 설계를 다시 생각해볼 신호일 수 있습니다. 소유권이 명확한 구조(트리는 부모가 자식을 소유, ID/인덱스로 참조 등)가 가능한지 먼저 검토하세요.

# 6. Weak<T> - 순환 참조 끊기

`Rc`끼리 서로를 가리키면 카운트가 0이 되지 않아 **메모리 누수**가 생깁니다. Rust의 메모리 안전성은 누수까지 막아주지는 않습니다.

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

#[derive(Debug)]
struct TreeNode {
    value: i32,
    parent: RefCell<Weak<TreeNode>>,       // 부모는 약한 참조 (소유하지 않음)
    children: RefCell<Vec<Rc<TreeNode>>>,  // 자식은 강한 참조 (소유)
}

fn main() {
    let leaf = Rc::new(TreeNode {
        value: 3,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![]),
    });

    println!("leaf 부모 = {:?}", leaf.parent.borrow().upgrade().map(|p| p.value)); // None

    {
        let branch = Rc::new(TreeNode {
            value: 5,
            parent: RefCell::new(Weak::new()),
            children: RefCell::new(vec![Rc::clone(&leaf)]),
        });

        *leaf.parent.borrow_mut() = Rc::downgrade(&branch);

        println!("leaf 부모 = {:?}", leaf.parent.borrow().upgrade().map(|p| p.value)); // Some(5)
        println!(
            "branch strong={} weak={}",
            Rc::strong_count(&branch), // 1
            Rc::weak_count(&branch)    // 1
        );
    } // branch drop (strong 이 0 이 되므로 해제됨)

    // 부모가 사라졌으므로 upgrade 는 None
    println!("leaf 부모 = {:?}", leaf.parent.borrow().upgrade().map(|p| p.value)); // None
    println!("leaf strong={}", Rc::strong_count(&leaf)); // 1
}
```

```
Rc::clone     → strong_count +1 (소유)
Rc::downgrade → weak_count +1 (소유 안 함)
weak.upgrade() → Option<Rc<T>> (이미 해제됐으면 None)
```

# 7. Cow - 필요할 때만 복사

```rust
use std::borrow::Cow;

// 대부분은 입력을 그대로 돌려주고, 수정이 필요할 때만 새 String 할당
fn normalize_spaces(input: &str) -> Cow<'_, str> {
    if input.contains('\t') {
        Cow::Owned(input.replace('\t', "    "))
    } else {
        Cow::Borrowed(input)
    }
}

fn main() {
    let a = normalize_spaces("no tabs here");
    let b = normalize_spaces("has\ttab");

    for s in [&a, &b] {
        match s {
            Cow::Borrowed(_) => println!("빌림(할당 없음): {s}"),
            Cow::Owned(_) => println!("새로 할당: {s}"),
        }
    }

    let owned: String = b.into_owned();
    println!("{owned}");
}
```

# 8. 지연 초기화: OnceLock / LazyLock

```rust
use std::collections::HashMap;
use std::sync::{LazyLock, OnceLock};

// 처음 접근할 때 한 번만 초기화되는 전역 값 (LazyLock: Rust 1.80+)
static COUNTRY_CODES: LazyLock<HashMap<&'static str, &'static str>> = LazyLock::new(|| {
    println!("초기화 실행 (한 번만)");
    HashMap::from([("KR", "대한민국"), ("JP", "일본")])
});

static CONFIG: OnceLock<String> = OnceLock::new();

fn main() {
    println!("{:?}", COUNTRY_CODES.get("KR"));
    println!("{:?}", COUNTRY_CODES.get("JP"));

    CONFIG.set("production".to_string()).unwrap();
    println!("{}", CONFIG.get().unwrap());
    println!("{:?}", CONFIG.set("dev".into()).is_err()); // 이미 설정됨
}
```

예전에는 `lazy_static`, `once_cell` 크레이트를 썼지만 이제 표준 라이브러리로 충분합니다.

## 정리

- `Box<T>`: 힙에 단독 소유. 재귀 타입, 트레이트 객체, 큰 값 이동에 사용
- `Deref`로 참조처럼, `Drop`으로 자동 정리
- `Rc<T>`: 참조 카운팅으로 여러 소유자 (싱글 스레드, 불변)
- `RefCell<T>` / `Cell<T>`: 불변 참조로도 내부 수정, 빌림 검사는 런타임에
- `Rc<RefCell<T>>`로 공유+수정, 멀티스레드는 `Arc<Mutex<T>>`
- 순환 참조는 `Weak<T>`로 끊는다 (부모 → 자식은 Rc, 자식 → 부모는 Weak)
- `Cow`로 불필요한 할당 회피, `LazyLock`/`OnceLock`으로 전역 지연 초기화
