# 구조체와 열거형 - 데이터를 모델링하는 두 가지 도구

## 들어가며

Rust에는 클래스가 없습니다. 대신 데이터를 표현하는 두 가지 도구가 있습니다.

```
struct (구조체) → "A 그리고 B 그리고 C"   (AND, 곱 타입)
enum   (열거형) → "A 이거나 B 이거나 C"   (OR, 합 타입)
impl   블록     → 여기에 메서드를 붙임
trait  (트레이트) → 공통 동작(인터페이스)을 정의
```

TypeScript와 비교하면:

```ts
// TS
interface User { name: string; age: number }            // → struct
type Shape = { kind: "circle"; r: number }
           | { kind: "rect"; w: number; h: number };    // → enum
```

특히 Rust의 `enum`은 TS의 **판별 유니온(discriminated union)**과 거의 같고, 컴파일러가 모든 경우를 처리했는지 검사해 줍니다.

# 1. 구조체 (struct)

## 정의와 생성

```rust
#[derive(Debug)]
struct User {
    username: String,
    email: String,
    active: bool,
    sign_in_count: u64,
}

fn main() {
    let mut user1 = User {
        email: String::from("a@example.com"),
        username: String::from("alice"),
        active: true,
        sign_in_count: 1,
    };

    user1.email = String::from("alice@example.com"); // 인스턴스 전체가 mut 이어야 수정 가능
    println!("{user1:#?}");
}
```

- 일부 필드만 `mut`으로 만들 수는 없습니다. 인스턴스 전체가 가변/불변입니다.
- 필드 이름은 `snake_case`, 타입 이름은 `PascalCase`가 관례입니다.

## 필드 초기화 축약과 구조체 갱신 문법

```rust
#[derive(Debug)]
struct User {
    username: String,
    email: String,
    active: bool,
}

fn build_user(email: String, username: String) -> User {
    User {
        email,     // email: email 축약 (JS 객체 축약과 동일)
        username,
        active: true,
    }
}

fn main() {
    let user1 = build_user("a@x.com".to_string(), "alice".to_string());

    // ..user1 : 나머지 필드는 user1에서 가져옴 (JS 스프레드와 비슷, 단 맨 마지막에만)
    let user2 = User {
        email: String::from("b@x.com"),
        ..user1
    };

    // user1.username(String)이 user2로 "이동"했으므로 user1 전체는 더 이상 못 씀
    // println!("{:?}", user1); // ❌ 컴파일 에러: borrow of partially moved value
    println!("{}", user1.email); // 이동하지 않은 필드는 사용 가능
    println!("{user2:?}");
}
```

"이동(move)"은 [기초개념/01-소유권](../2-기초개념/01-소유권.md)에서 다룹니다.

## 튜플 구조체와 유닛 구조체

```rust
struct Color(u8, u8, u8);       // 튜플 구조체: 필드 이름 없음
struct Meters(f64);             // 뉴타입(newtype) 패턴: 단위 혼동 방지
struct AlwaysEqual;             // 유닛 구조체: 필드 없음 (트레이트 구현용 마커)

fn main() {
    let black = Color(0, 0, 0);
    let Color(r, g, b) = black;       // 구조 분해
    let distance = Meters(5.5);

    println!("{r} {g} {b} {}", distance.0);
    let _marker = AlwaysEqual;
}
```

뉴타입 패턴은 `Meters(f64)`와 `Feet(f64)`를 컴파일러가 서로 다른 타입으로 취급하게 만들어 실수를 막아줍니다. 런타임 비용은 0입니다.

# 2. 메서드 (impl)

## 메서드와 연관 함수

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    // 연관 함수(associated function): self가 없음. 생성자 역할로 자주 사용
    // 호출: Rectangle::new(...)
    fn new(width: u32, height: u32) -> Self {
        Self { width, height }
    }

    fn square(size: u32) -> Self {
        Self::new(size, size)
    }

    // &self: 읽기만 함 (가장 흔함)
    fn area(&self) -> u32 {
        self.width * self.height
    }

    // &mut self: 자신을 수정
    fn scale(&mut self, factor: u32) {
        self.width *= factor;
        self.height *= factor;
    }

    // self: 소유권을 가져감 (변환 후 원본을 못 쓰게 할 때)
    fn into_tuple(self) -> (u32, u32) {
        (self.width, self.height)
    }

    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

fn main() {
    let mut rect = Rectangle::new(30, 50);
    println!("넓이: {}", rect.area());

    rect.scale(2);
    println!("{rect:?}");

    let small = Rectangle::square(10);
    println!("포함 가능? {}", rect.can_hold(&small));

    let (w, h) = rect.into_tuple();
    // rect.area(); // ❌ rect는 into_tuple(self)로 소비됨
    println!("{w} x {h}");
}
```

```
self 형태      의미                   JS/TS로 치면
&self         불변 빌림으로 읽기         일반 메서드
&mut self     가변 빌림으로 수정         this.x = ... 하는 메서드
self          소유권을 가져가 소비       호출 후 객체를 못 쓰게 됨 (JS엔 없음)
Self          impl 대상 타입 자체        클래스 이름
```

- Rust는 `rect.area()` 호출 시 필요한 `&`, `&mut`, `*`를 **자동으로 붙여줍니다** (자동 참조/역참조).
- `impl` 블록은 여러 개로 나눠 써도 됩니다.
- 생성자라는 특별한 문법은 없고 `new`라는 이름의 연관 함수를 만드는 것이 **관례**입니다.

## getter 관례

```rust
pub struct Account {
    balance: i64, // 비공개 필드
}

impl Account {
    pub fn new() -> Self {
        Self { balance: 0 }
    }
    // getter는 get_ 접두사 없이 필드 이름 그대로
    pub fn balance(&self) -> i64 {
        self.balance
    }
    pub fn deposit(&mut self, amount: i64) {
        self.balance += amount;
    }
}
```

# 3. 열거형 (enum)

## 기본 열거형

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
enum Direction {
    Up,
    Down,
    Left,
    Right,
}

fn main() {
    let d = Direction::Up;
    if d == Direction::Up {
        println!("{d:?}");
    }
    println!("{}", Direction::Right as i32); // 3 - C 스타일 정수 값
}
```

## 데이터를 가지는 열거형 (Rust enum의 진짜 힘)

각 variant가 **서로 다른 형태의 데이터**를 가질 수 있습니다.

```rust
#[derive(Debug)]
enum Message {
    Quit,                          // 데이터 없음
    Move { x: i32, y: i32 },       // 이름 있는 필드 (구조체처럼)
    Write(String),                 // 튜플처럼
    ChangeColor(u8, u8, u8),
}

impl Message {
    fn describe(&self) -> String {
        match self {
            Message::Quit => "종료".to_string(),
            Message::Move { x, y } => format!("({x}, {y})로 이동"),
            Message::Write(text) => format!("쓰기: {text}"),
            Message::ChangeColor(r, g, b) => format!("색 변경 #{r:02x}{g:02x}{b:02x}"),
        }
    }
}

fn main() {
    let messages = vec![
        Message::Move { x: 10, y: 20 },
        Message::Write(String::from("hello")),
        Message::ChangeColor(255, 128, 0),
        Message::Quit,
    ];

    for m in &messages {
        println!("{}", m.describe());
    }
}
```

`match`에서 variant 하나라도 빠뜨리면 **컴파일 에러**(`non-exhaustive patterns`)가 납니다. 나중에 variant를 추가했을 때 처리하지 않은 모든 곳을 컴파일러가 찾아줍니다.

## 상태 모델링 예시

```rust
#[derive(Debug)]
enum RequestState {
    Idle,
    Loading { started_at: u64 },
    Success { body: String },
    Failed { code: u16, reason: String },
}

fn render(state: &RequestState) -> String {
    match state {
        RequestState::Idle => "대기 중".into(),
        RequestState::Loading { started_at } => format!("{started_at}부터 로딩 중..."),
        RequestState::Success { body } => format!("완료: {body}"),
        RequestState::Failed { code, reason } => format!("실패 {code}: {reason}"),
    }
}

fn main() {
    let states = [
        RequestState::Idle,
        RequestState::Loading { started_at: 1000 },
        RequestState::Success { body: "ok".into() },
        RequestState::Failed { code: 500, reason: "server".into() },
    ];
    for s in &states {
        println!("{}", render(s));
    }
}
```

`isLoading`, `isError`, `data` 같은 플래그를 따로 두면 "로딩 중인데 에러도 있음" 같은 **불가능한 상태**가 생길 수 있지만, enum으로 모델링하면 그런 상태 자체를 표현할 수 없습니다.

# 4. Option - null이 없는 언어

Rust에는 `null`/`undefined`가 없습니다. 값이 없을 수 있으면 표준 라이브러리의 `Option<T>`를 씁니다.

```rust
// 표준 라이브러리 정의 (prelude에 포함되어 바로 사용 가능)
// enum Option<T> {
//     None,
//     Some(T),
// }

fn find_user(id: u32) -> Option<&'static str> {
    match id {
        1 => Some("alice"),
        2 => Some("bob"),
        _ => None,
    }
}

fn main() {
    let user = find_user(1);

    // let len = user.len(); // ❌ Option<&str>은 &str이 아니므로 바로 못 씀

    match user {
        Some(name) => println!("찾음: {name}"),
        None => println!("없음"),
    }

    // 자주 쓰는 메서드
    println!("{}", find_user(3).unwrap_or("guest"));
    println!("{:?}", find_user(2).map(|n| n.len()));   // Some(3)
    println!("{}", find_user(2).is_some());
    if let Some(name) = find_user(2) {
        println!("if let: {name}");
    }
}
```

```
TypeScript: string | undefined   → 체크 안 해도 (strict 아니면) 컴파일됨
Rust:       Option<String>       → Some/None 처리 없이는 안의 값을 꺼낼 수 없음
```

에러를 표현하는 `Result<T, E>`도 같은 방식의 enum입니다. ([기초개념/03-에러-처리](../2-기초개념/03-에러-처리.md))

# 5. derive로 자주 붙이는 트레이트

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, Default, PartialOrd, Ord)]
struct Version {
    major: u32,
    minor: u32,
}

fn main() {
    let v1 = Version { major: 1, minor: 2 };
    let v2 = v1.clone();
    let v0 = Version::default(); // 모든 필드가 기본값 (0)

    println!("{v1:?} == {v2:?} ? {}", v1 == v2);
    println!("{}", v0 < v1); // 필드 선언 순서대로 사전식 비교
}
```

| derive | 가능해지는 것 |
|---|---|
| `Debug` | `{:?}` 출력 |
| `Clone` | `.clone()`으로 깊은 복사 |
| `Copy` | 대입 시 이동 대신 복사 (모든 필드가 Copy일 때만) |
| `PartialEq`, `Eq` | `==`, `!=` |
| `PartialOrd`, `Ord` | `<`, `>`, 정렬 |
| `Hash` | `HashMap`의 키로 사용 |
| `Default` | `T::default()` |

## 정리

- `struct`는 여러 값을 묶는 AND, `enum`은 여러 경우 중 하나인 OR
- 메서드와 연관 함수는 `impl` 블록에 정의, 생성자는 관례상 `new`
- `&self` / `&mut self` / `self`로 메서드가 값을 어떻게 다루는지 표현
- enum variant는 각기 다른 데이터를 가질 수 있고 `match`는 모든 경우를 강제
- `null` 대신 `Option<T>`, 예외 대신 `Result<T, E>`
- `#[derive(...)]`로 흔한 트레이트를 자동 구현
