# 트레이트 (Trait) - 공통 동작 정의하기

## 들어가며

트레이트는 **"어떤 타입이 할 수 있는 동작의 묶음"**입니다. 다른 언어의 인터페이스와 비슷하지만 더 강력합니다.

```
TypeScript interface          Rust trait
- 구조적 타이핑               - 명시적으로 impl Trait for Type 해야 함
  (모양만 맞으면 구현한 것)
- 기본 구현 불가              - 기본 메서드 구현 가능
- 이미 있는 타입에 추가 불가    - 남이 만든 타입(i32, Vec 등)에도 내 트레이트 구현 가능
                              - 연산자 오버로딩, 복사, 출력, 반복 등이 모두 트레이트
```

Rust에는 상속이 없습니다. 코드 재사용과 다형성은 **트레이트 + 제네릭 + 컴포지션**으로 해결합니다.

# 1. 트레이트 정의와 구현

```rust
pub trait Summary {
    // 구현해야 하는 메서드 (시그니처만)
    fn summarize_author(&self) -> String;

    // 기본 구현이 있는 메서드 (재정의 가능)
    fn summarize(&self) -> String {
        format!("({}님의 글 더 보기...)", self.summarize_author())
    }
}

pub struct NewsArticle {
    pub headline: String,
    pub author: String,
}

pub struct Tweet {
    pub username: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize_author(&self) -> String {
        self.author.clone()
    }
    // summarize 는 재정의
    fn summarize(&self) -> String {
        format!("{} - {}", self.headline, self.author)
    }
}

impl Summary for Tweet {
    fn summarize_author(&self) -> String {
        format!("@{}", self.username)
    }
    // summarize 는 기본 구현 사용
}

fn main() {
    let article = NewsArticle { headline: "러스트 1.98 출시".into(), author: "Rust Team".into() };
    let tweet = Tweet { username: "ferris".into(), content: "hello".into() };

    println!("{}", article.summarize());
    println!("{}", tweet.summarize());
    let _ = &tweet.content;
}
```

## 고아 규칙 (Orphan Rule)

`impl 트레이트 for 타입`은 **트레이트 또는 타입 중 하나는 내 크레이트에 정의된 것**이어야 합니다.

```
impl Summary for Vec<i32>      ✅ Summary 가 내 것
impl Display for Tweet         ✅ Tweet 이 내 것
impl Display for Vec<i32>      ❌ 둘 다 외부 (std) 것
```

이 규칙이 없으면 두 크레이트가 같은 타입에 같은 트레이트를 서로 다르게 구현해서 충돌할 수 있습니다. 외부 타입에 외부 트레이트를 구현하고 싶으면 **뉴타입**으로 감쌉니다.

```rust
use std::fmt;

struct Wrapper(Vec<String>);

impl fmt::Display for Wrapper {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "[{}]", self.0.join(", "))
    }
}

fn main() {
    let w = Wrapper(vec!["hello".into(), "world".into()]);
    println!("{w}");
}
```

# 2. 트레이트를 매개변수로 - 정적 디스패치

```rust
use std::fmt::Display;

trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> String {
        "도형".to_string()
    }
}

struct Circle(f64);
struct Square(f64);

impl Shape for Circle {
    fn area(&self) -> f64 { std::f64::consts::PI * self.0 * self.0 }
    fn name(&self) -> String { "원".into() }
}
impl Shape for Square {
    fn area(&self) -> f64 { self.0 * self.0 }
}

// 아래 세 함수는 사실상 같은 의미
fn print_area(s: &impl Shape) {
    println!("{}: {:.2}", s.name(), s.area());
}
fn print_area2<T: Shape>(s: &T) {
    println!("{}: {:.2}", s.name(), s.area());
}
fn print_area3<T>(s: &T)
where
    T: Shape,
{
    println!("{}: {:.2}", s.name(), s.area());
}

// 여러 트레이트 요구
fn describe<T: Shape + Display>(s: &T) {
    println!("{s} 넓이 {:.1}", s.area());
}

impl Display for Square {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "한 변 {}인 정사각형", self.0)
    }
}

fn main() {
    print_area(&Circle(1.0));
    print_area2(&Square(2.0));
    print_area3(&Circle(2.0));
    describe(&Square(3.0));
    // describe(&Circle(1.0)); // ❌ Circle 은 Display 를 구현하지 않음
}
```

제네릭으로 받으면 컴파일 타임에 타입별로 코드가 생성됩니다(**정적 디스패치**). 가장 빠르지만 `Vec`에 서로 다른 타입을 섞어 담을 수는 없습니다.

# 3. 트레이트 객체 dyn Trait - 동적 디스패치

서로 다른 타입을 **하나의 컬렉션에 담아** 다형적으로 다루려면 트레이트 객체를 씁니다.

```rust
trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> &str;
}

struct Circle { r: f64 }
struct Rect { w: f64, h: f64 }

impl Shape for Circle {
    fn area(&self) -> f64 { 3.14159 * self.r * self.r }
    fn name(&self) -> &str { "원" }
}
impl Shape for Rect {
    fn area(&self) -> f64 { self.w * self.h }
    fn name(&self) -> &str { "사각형" }
}

fn total_area(shapes: &[Box<dyn Shape>]) -> f64 {
    shapes.iter().map(|s| s.area()).sum()
}

fn make_shape(kind: &str) -> Box<dyn Shape> {
    // 런타임 값에 따라 다른 타입을 반환 (impl Trait 로는 불가능)
    match kind {
        "circle" => Box::new(Circle { r: 1.0 }),
        _ => Box::new(Rect { w: 2.0, h: 3.0 }),
    }
}

fn main() {
    let shapes: Vec<Box<dyn Shape>> = vec![
        Box::new(Circle { r: 2.0 }),
        Box::new(Rect { w: 3.0, h: 4.0 }),
        make_shape("circle"),
    ];

    for s in &shapes {
        println!("{} {:.2}", s.name(), s.area());
    }
    println!("합계 {:.2}", total_area(&shapes));

    // 참조로도 트레이트 객체를 만들 수 있음
    let c = Circle { r: 1.0 };
    let r: &dyn Shape = &c;
    println!("{}", r.name());
}
```

```
Box<dyn Shape> 의 메모리 구조 (fat pointer, 포인터 2개 크기)

┌──────────────┐      ┌──────────────┐
│ data ptr  ───┼─────▶│ Circle { r } │
│ vtable ptr ──┼──┐   └──────────────┘
└──────────────┘  │   ┌─────────────────────────┐
                  └──▶│ drop, size, align       │
                      │ area  → Circle::area    │
                      │ name  → Circle::name    │
                      └─────────────────────────┘
```

| | 제네릭 / impl Trait | dyn Trait |
|---|---|---|
| 디스패치 | 정적 (컴파일 타임) | 동적 (vtable 통한 런타임 호출) |
| 성능 | 인라인 가능, 가장 빠름 | 간접 호출 비용 (보통 미미함) |
| 이종 컬렉션 | 불가 | 가능 |
| 바이너리 크기 | 타입마다 코드 생성 | 한 벌 |
| 제약 | 없음 | dyn 호환(dyn compatible) 트레이트만 가능 |

## dyn 호환성 (예전 이름: object safety)

모든 트레이트를 `dyn`으로 쓸 수 있는 건 아닙니다. 대표적으로 다음 메서드가 있으면 트레이트 객체로 못 씁니다.

```
- 제네릭 메서드 fn foo<T>(&self, t: T)       → vtable 에 모든 T 버전을 넣을 수 없음
- Self 를 반환하는 메서드 fn clone(&self) -> Self → 크기를 알 수 없음
  (where Self: Sized 를 붙이면 그 메서드만 제외하고 dyn 사용 가능)
```

# 4. 표준 라이브러리의 핵심 트레이트

## 자주 구현하는 트레이트

```rust
use std::fmt;
use std::ops::Add;

#[derive(Debug, Clone, Copy, PartialEq, Default)]
struct Vec2 {
    x: f64,
    y: f64,
}

// 연산자 오버로딩: + 는 Add 트레이트
impl Add for Vec2 {
    type Output = Vec2;
    fn add(self, other: Vec2) -> Vec2 {
        Vec2 { x: self.x + other.x, y: self.y + other.y }
    }
}

// {} 출력
impl fmt::Display for Vec2 {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "({:.1}, {:.1})", self.x, self.y)
    }
}

// 변환: From 을 구현하면 Into 는 자동으로 생김
impl From<(f64, f64)> for Vec2 {
    fn from((x, y): (f64, f64)) -> Self {
        Vec2 { x, y }
    }
}

fn main() {
    let a = Vec2 { x: 1.0, y: 2.0 };
    let b: Vec2 = (3.0, 4.0).into(); // Into (From 에서 자동 파생)
    let c = Vec2::from((0.5, 0.5));

    println!("{}", a + b + c);
    println!("{:?}", Vec2::default());
    println!("{}", a == a.clone());
}
```

| 트레이트 | 역할 | 비고 |
|---|---|---|
| `Debug` / `Display` | `{:?}` / `{}` 출력 | Display 구현 시 `.to_string()` 자동 제공 |
| `Clone` / `Copy` | 복제 / 암묵적 복사 | |
| `PartialEq` / `Eq` | `==` | f64 는 NaN 때문에 Eq 불가 |
| `PartialOrd` / `Ord` | `<`, 정렬 | |
| `Hash` | HashMap 키 | Eq 와 일관돼야 함 |
| `Default` | 기본값 | `..Default::default()` 패턴 |
| `From` / `Into` | 값 변환 | `?` 의 에러 변환에 사용 |
| `TryFrom` / `TryInto` | 실패 가능한 변환 | |
| `AsRef` / `Borrow` | 저렴한 참조 변환 | |
| `Deref` | `*` 역참조, 메서드 자동 위임 | 스마트 포인터용 |
| `Drop` | 소멸자 | |
| `Iterator` | `for` 순회 | `next()` 하나만 구현하면 됨 |
| `Add`, `Mul`, `Index`, `Neg`... | 연산자 오버로딩 | `std::ops` |
| `Send` / `Sync` | 스레드 간 이동/공유 가능 | 자동 구현 (마커 트레이트) |
| `Sized` | 컴파일 타임 크기 확정 | 제네릭 T 에 암묵적으로 붙음 |

## Into를 매개변수에 활용하기

```rust
struct User {
    name: String,
}

impl User {
    // &str, String 둘 다 받기
    fn new(name: impl Into<String>) -> Self {
        Self { name: name.into() }
    }
}

fn main() {
    let a = User::new("literal");
    let b = User::new(String::from("owned"));
    println!("{} {}", a.name, b.name);
}
```

# 5. 연관 타입과 제네릭 트레이트

```rust
// 연관 타입: 구현마다 "하나"로 정해지는 타입
trait Container {
    type Item;
    fn get(&self, i: usize) -> Option<&Self::Item>;
    fn first(&self) -> Option<&Self::Item> {
        self.get(0)
    }
}

struct Stack {
    items: Vec<String>,
}

impl Container for Stack {
    type Item = String;
    fn get(&self, i: usize) -> Option<&String> {
        self.items.get(i)
    }
}

// 제네릭 트레이트: 한 타입이 여러 T 에 대해 여러 번 구현 가능
trait ConvertTo<T> {
    fn convert(&self) -> T;
}

impl ConvertTo<i64> for i32 {
    fn convert(&self) -> i64 { *self as i64 }
}
impl ConvertTo<String> for i32 {
    fn convert(&self) -> String { self.to_string() }
}

fn main() {
    let s = Stack { items: vec!["a".into(), "b".into()] };
    println!("{:?}", s.first());

    let n = 7_i32;
    let as_i64: i64 = n.convert();
    let as_str: String = n.convert();
    println!("{as_i64} {as_str}");
}
```

```
Iterator 는 연관 타입:   trait Iterator { type Item; ... }   → Vec<i32> 의 iter 는 Item 이 하나로 정해짐
From 은 제네릭 트레이트:  trait From<T> { ... }               → String 은 From<&str>, From<char> ... 여러 개
```

# 6. 블랭킷 구현 (Blanket Impl)

**조건을 만족하는 모든 타입**에 트레이트를 한 번에 구현합니다.

```rust
use std::fmt::Display;

trait Shout {
    fn shout(&self) -> String;
}

// Display 를 구현한 모든 T 에 Shout 구현
impl<T: Display> Shout for T {
    fn shout(&self) -> String {
        format!("{}!!!", self.to_string().to_uppercase())
    }
}

fn main() {
    println!("{}", "hello".shout());
    println!("{}", 42.shout());
    println!("{}", 3.5.shout());
}
```

표준 라이브러리의 `impl<T: Display> ToString for T`가 대표적인 블랭킷 구현이라서 `Display`만 구현하면 `.to_string()`을 쓸 수 있습니다.

# 7. 슈퍼트레이트

트레이트가 다른 트레이트를 전제로 할 때 씁니다. (상속처럼 보이지만 "요구 사항"입니다)

```rust
use std::fmt::Display;

trait Entity: Display {       // Entity 를 구현하려면 Display 도 구현해야 함
    fn id(&self) -> u64;

    fn log(&self) {
        println!("[#{}] {}", self.id(), self); // Display 사용 가능
    }
}

struct Product {
    id: u64,
    name: String,
}

impl Display for Product {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "상품 {}", self.name)
    }
}

impl Entity for Product {
    fn id(&self) -> u64 {
        self.id
    }
}

fn main() {
    Product { id: 1, name: "키보드".into() }.log();
}
```

## 정리

- 트레이트는 공통 동작의 정의, `impl Trait for Type`으로 명시적 구현
- 기본 메서드 구현 가능, 고아 규칙 때문에 외부 타입+외부 트레이트는 뉴타입으로
- `impl Trait` / 제네릭 바운드는 정적 디스패치(빠름), `dyn Trait`는 동적 디스패치(이종 컬렉션)
- `Display`, `From`, `Add`, `Iterator` 같은 std 트레이트를 구현하면 언어 기능과 자연스럽게 통합된다
- 구현마다 하나로 정해지는 타입은 연관 타입, 여러 번 구현하려면 제네릭 트레이트
- 블랭킷 구현으로 조건을 만족하는 모든 타입에 한 번에 구현
