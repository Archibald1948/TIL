# 참조와 빌림 (References & Borrowing) - 소유권을 넘기지 않고 쓰기

## 들어가며

[소유권](./01-소유권.md)만 있으면 함수에 값을 넘길 때마다 소유권이 이동해서 불편합니다. 그래서 Rust는 값을 **빌려주는(borrow)** 방법을 제공합니다. 빌린 값을 가리키는 것이 **참조(reference)**입니다.

```
&T      → 불변 참조 (공유 참조, shared reference)  - 읽기만
&mut T  → 가변 참조 (배타적 참조, exclusive reference) - 읽기 + 쓰기
```

그리고 이 참조를 검사하는 컴파일러 구성 요소가 그 유명한 **빌림 검사기(borrow checker)**입니다.

# 1. 불변 참조 &T

```rust
fn calculate_length(s: &String) -> usize { // s 는 String 을 빌림
    s.len()
} // s 는 참조일 뿐이므로 여기서 아무것도 drop 되지 않음

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // &s1: s1 을 가리키는 참조를 만듦
    println!("'{s1}'의 길이는 {len}"); // s1 여전히 사용 가능
}
```

```
   s (참조)              s1                       힙
┌──────┬───┐      ┌──────────┬───┐         ┌─────────┐
│ ptr  │ ──┼─────▶│ ptr      │ ──┼────────▶│ "hello" │
└──────┴───┘      │ len      │ 5 │         └─────────┘
                  │ capacity │ 5 │
                  └──────────┴───┘
```

참조를 만드는 행위를 **빌림**이라고 부릅니다. 빌린 것은 수정할 수 없습니다.

```rust
fn change(s: &String) {
    // s.push_str(", world"); // ❌ 컴파일 에러: cannot borrow `*s` as mutable, as it is behind a `&` reference
    println!("{s}");
}

fn main() {
    let s = String::from("hello");
    change(&s);
}
```

# 2. 가변 참조 &mut T

```rust
fn change(s: &mut String) {
    s.push_str(", world");
}

fn main() {
    let mut s = String::from("hello"); // 원본도 mut 이어야 함
    change(&mut s);
    println!("{s}");

    let mut n = 10;
    let r = &mut n;
    *r += 5; // 역참조(*)로 값에 접근
    println!("{n}");
}
```

# 3. 빌림 규칙

```
어느 시점이든, 하나의 값에 대해 둘 중 하나만 가능하다:
  (A) 불변 참조 &T 여러 개
  (B) 가변 참조 &mut T 딱 하나

그리고 참조는 항상 유효해야 한다 (댕글링 참조 금지)
```

"여러 명이 읽거나, 한 명만 쓰거나" - 읽기/쓰기 락(RwLock)과 같은 규칙을 **컴파일 타임에** 강제합니다.

## 가변 참조는 동시에 하나만

```rust
// ❌ 컴파일 에러 예제
fn main() {
    let mut s = String::from("hello");

    let r1 = &mut s;
    let r2 = &mut s;

    println!("{r1}, {r2}");
}
```

```
error[E0499]: cannot borrow `s` as mutable more than once at a time
```

## 불변 참조가 살아있으면 가변 참조 불가

```rust
// ❌ 컴파일 에러 예제
fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    let r2 = &s;
    let r3 = &mut s;

    println!("{r1}, {r2}, {r3}");
}
```

```
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
```

## 왜 이런 규칙이 필요한가

이 규칙은 **데이터 경쟁(data race)**을 막습니다. 데이터 경쟁은 다음 세 조건이 모두 만족될 때 발생합니다.

```
1. 두 개 이상의 포인터가 같은 데이터에 동시에 접근
2. 그중 하나 이상이 쓰기
3. 접근을 동기화하는 장치가 없음
```

싱글 스레드에서도 문제가 됩니다. 앞서 본 "Vec의 요소를 참조하는 중에 push해서 재할당" 같은 버그가 대표적입니다. 이 규칙 덕분에 Rust는 멀티스레드 코드에서도 데이터 경쟁이 컴파일 단계에서 막힙니다 ("fearless concurrency").

## NLL: 참조의 수명은 마지막 사용까지

참조의 스코프는 블록 끝이 아니라 **마지막으로 사용된 지점**까지입니다. (Non-Lexical Lifetimes, Rust 2018+)

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    let r2 = &s;
    println!("{r1} and {r2}");
    // r1, r2 는 여기서 마지막으로 사용됨 → 빌림 종료

    let r3 = &mut s; // OK
    r3.push('!');
    println!("{r3}");
}
```

## 스코프로 빌림 구간 나누기

```rust
fn main() {
    let mut v = vec![1, 2, 3];

    {
        let first = &mut v[0];
        *first = 100;
    } // first 빌림 종료

    v.push(4); // OK
    println!("{v:?}");
}
```

# 4. 댕글링 참조 방지

```rust
// ❌ 컴파일 에러 예제
fn dangle() -> &String {
    let s = String::from("hello");
    &s // s 는 함수가 끝나면 drop 되는데 그 참조를 반환하려 함
}

fn main() {
    let r = dangle();
    println!("{r}");
}
```

```
error[E0106]: missing lifetime specifier
```

해결책은 참조가 아니라 **소유한 값을 반환**하는 것입니다.

```rust
fn no_dangle() -> String {
    let s = String::from("hello");
    s // 소유권 이동
}

fn main() {
    println!("{}", no_dangle());
}
```

C/C++에서는 이런 코드가 컴파일되고 런타임에 이상한 값을 읽지만, Rust에서는 컴파일조차 되지 않습니다. 참조의 유효 범위를 표현하는 **라이프타임**은 [심화개념/01-라이프타임](../3-심화개념/01-라이프타임.md)에서 다룹니다.

# 5. 슬라이스 (Slice)

슬라이스는 컬렉션의 **연속된 일부를 가리키는 참조**입니다. 소유권이 없습니다.

## 문자열 슬라이스 &str

```rust
// 첫 단어를 반환하는 함수
fn first_word(s: &str) -> &str {
    for (i, &byte) in s.as_bytes().iter().enumerate() {
        if byte == b' ' {
            return &s[..i];
        }
    }
    s
}

fn main() {
    let s = String::from("hello world");

    let hello = &s[0..5];
    let world = &s[6..11];
    let whole = &s[..];
    println!("{hello} | {world} | {whole}");

    let word = first_word(&s);
    // s.clear(); // ❌ word 가 s 를 빌리고 있으므로 가변 빌림 불가
    println!("첫 단어: {word}");

    println!("{}", first_word("리터럴 도 됩니다"));
}
```

만약 `first_word`가 인덱스(`usize`)만 반환했다면, `s.clear()` 후에도 그 인덱스는 남아 있어서 **데이터와 어긋나는 버그**가 생깁니다. 슬라이스를 반환하면 컴파일러가 이런 상황을 막아줍니다.

```
       s (String)                       힙
┌──────────┬────┐              ┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
│ ptr      │ ───┼─────────────▶│ h │ e │ l │ l │ o │   │ w │ o │ r │ l │ d │
│ len      │ 11 │              └───┴───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
│ capacity │ 11 │                                    ▲
└──────────┴────┘                                    │
       world (&str)                                  │
┌──────────┬────┐                                    │
│ ptr      │ ───┼────────────────────────────────────┘
│ len      │ 5  │
└──────────┴────┘
```

## 배열/Vec 슬라이스 &[T]

```rust
fn sum(nums: &[i32]) -> i32 {
    nums.iter().sum()
}

fn zero_out(nums: &mut [i32]) {
    for n in nums {
        *n = 0;
    }
}

fn main() {
    let arr = [1, 2, 3, 4, 5];
    let mut v = vec![10, 20, 30, 40];

    println!("{}", sum(&arr));        // 배열 전체
    println!("{}", sum(&arr[1..3]));  // 일부
    println!("{}", sum(&v));          // Vec 도 &[T] 로 받을 수 있음

    zero_out(&mut v[2..]);
    println!("{v:?}");                // [10, 20, 0, 0]

    // 하나의 슬라이스를 겹치지 않는 두 가변 슬라이스로 나누기
    let (left, right) = v.split_at_mut(2);
    left[0] = 1;
    right[0] = 2;
    println!("{v:?}");
}
```

**매개변수 타입 선택 규칙**

```
읽기만:      &String 대신 &str,  &Vec<T> 대신 &[T]
수정 필요:   &mut Vec<T> (push 등 길이 변경 필요 시) / &mut [T] (요소만 수정)
소유 필요:   String, Vec<T>
```

# 6. 자주 만나는 빌림 에러와 해결 패턴

## 1) 루프 돌면서 컬렉션 수정

```rust
fn main() {
    let mut v = vec![1, 2, 3];

    // for x in &v { if *x == 2 { v.push(4); } } // ❌ E0502

    // 해결 A: 먼저 판단하고, 나중에 수정
    let need_push = v.iter().any(|&x| x == 2);
    if need_push {
        v.push(4);
    }

    // 해결 B: 인덱스로 순회 (길이만 먼저 읽음)
    for i in 0..v.len() {
        if v[i] == 1 {
            v[i] = 100;
        }
    }

    // 해결 C: retain, iter_mut 같은 전용 메서드
    v.retain(|&x| x != 3);
    println!("{v:?}");
}
```

## 2) 구조체의 서로 다른 필드를 동시에 빌리기

```rust
struct Game {
    players: Vec<String>,
    log: Vec<String>,
}

impl Game {
    // ❌ self 전체를 &mut 로 빌리는 메서드를 루프 안에서 부르면 충돌
    // fn add_log(&mut self, msg: String) { self.log.push(msg); }

    fn announce(&mut self) {
        // 필드 단위로 빌리면 컴파일러가 서로 다른 필드임을 알아서 OK
        for p in &self.players {
            self.log.push(format!("{p} 입장"));
        }
    }
}

fn main() {
    let mut g = Game { players: vec!["a".into(), "b".into()], log: vec![] };
    g.announce();
    println!("{:?}", g.log);
}
```

## 3) HashMap에서 조회 후 삽입

```rust
use std::collections::HashMap;

fn main() {
    let mut cache: HashMap<u32, String> = HashMap::new();

    // entry API 가 빌림 문제를 깔끔하게 해결
    let v = cache.entry(1).or_insert_with(|| "계산된 값".to_string());
    v.push('!');
    println!("{cache:?}");
}
```

# 7. 재빌림 (reborrow)

`&mut T`는 Copy가 아니지만, 함수에 넘길 때 컴파일러가 자동으로 **재빌림**(`&mut *r`)을 해줘서 계속 쓸 수 있습니다.

```rust
fn push_one(v: &mut Vec<i32>) {
    v.push(1);
}

fn main() {
    let mut data = Vec::new();
    let r = &mut data;

    push_one(r); // 암묵적으로 &mut *r 로 재빌림
    push_one(r); // r 은 이동되지 않았으므로 다시 사용 가능
    r.push(2);

    println!("{data:?}");
}
```

## 정리

- `&T`는 읽기 전용 빌림, `&mut T`는 쓰기 가능한 배타적 빌림
- **불변 참조 여러 개 XOR 가변 참조 하나** - 이 규칙이 데이터 경쟁을 막는다
- 참조의 수명은 마지막 사용 지점까지 (NLL)
- 스코프가 끝나는 값의 참조는 반환할 수 없다 (댕글링 방지) → 소유 값 반환
- 슬라이스 `&str`, `&[T]`는 연속된 데이터의 일부를 빌리는 참조
- 함수 매개변수는 가능한 한 `&str`, `&[T]`로 받자
