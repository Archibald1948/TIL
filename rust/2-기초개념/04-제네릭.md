# 제네릭 (Generics) - 타입을 매개변수로

## 들어가며

같은 로직을 `i32`용, `f64`용, `String`용으로 여러 번 작성하지 않으려면 **제네릭**을 씁니다. TypeScript의 제네릭(`function f<T>(x: T)`)과 문법은 비슷하지만 동작 방식이 다릅니다.

```
TypeScript 제네릭
- 타입 검사에만 쓰이고 컴파일 후 JS에서는 사라짐 (type erasure)

Rust 제네릭
- 컴파일 타임에 사용된 구체 타입마다 코드를 따로 생성 (단형성화, monomorphization)
- 런타임 비용 0, 대신 바이너리 크기와 컴파일 시간 증가
- "T로 무엇을 할 수 있는지"를 트레이트 바운드로 명시해야 함
```

# 1. 함수 제네릭

## 중복 제거하기

```rust
// 제네릭 없이: 타입마다 함수를 따로
fn largest_i32(list: &[i32]) -> &i32 {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}

// 제네릭: T 는 비교 가능(PartialOrd)해야 함
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}

fn main() {
    println!("{}", largest_i32(&[34, 50, 25]));
    println!("{}", largest(&[34, 50, 25, 100]));
    println!("{}", largest(&[1.5, 0.2]));
    println!("{}", largest(&['y', 'm', 'a']));
    println!("{}", largest(&["apple", "zebra", "mango"]));
}
```

## 트레이트 바운드가 없으면?

```rust
// ❌ 컴파일 에러 예제
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest { // T 가 비교 가능한지 알 수 없음
            largest = item;
        }
    }
    largest
}

fn main() {
    println!("{}", largest(&[1, 2]));
}
```

```
error[E0369]: binary operation `>` cannot be applied to type `&T`
 --> src/main.rs:5:17
  |
5 |         if item > largest { // T 가 비교 가능한지 알 수 없음
  |            ---- ^ ------- &T
  |            |
  |            &T
  |
help: consider restricting type parameter `T` with trait `PartialOrd`
  |
2 | fn largest<T: std::cmp::PartialOrd>(list: &[T]) -> &T {
  |             ++++++++++++++++++++++
```

C++ 템플릿은 일단 코드를 생성해보고 에러를 내지만, Rust는 **시그니처만 보고** 타입 검사를 합니다. 그래서 에러 메시지가 명확하고, 제네릭 함수 내부를 몰라도 시그니처만으로 사용법을 알 수 있습니다.

# 2. 구조체와 열거형 제네릭

## 구조체

```rust
#[derive(Debug)]
struct Point<T> {
    x: T,
    y: T,
}

#[derive(Debug)]
struct Pair<T, U> {
    first: T,
    second: U,
}

fn main() {
    let int_point = Point { x: 5, y: 10 };
    let float_point = Point { x: 1.0, y: 4.0 };
    // let wrong = Point { x: 5, y: 4.0 }; // ❌ x, y 는 같은 T 여야 함

    let mixed = Pair { first: 5, second: "five" };
    println!("{int_point:?} {float_point:?} {mixed:?}");
}
```

## 열거형 - 이미 써본 것들

```rust
// 표준 라이브러리의 Option 과 Result 가 대표적인 제네릭 enum
// enum Option<T> { Some(T), None }
// enum Result<T, E> { Ok(T), Err(E) }

#[derive(Debug)]
enum Tree<T> {
    Leaf(T),
    Node(Box<Tree<T>>, Box<Tree<T>>),
}

fn main() {
    let t = Tree::Node(Box::new(Tree::Leaf(1)), Box::new(Tree::Leaf(2)));
    println!("{t:?}");
}
```

# 3. 메서드 제네릭

```rust
struct Point<T> {
    x: T,
    y: T,
}

// 모든 T 에 대해 구현
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

// 특정 타입에만 구현 (f64 인 경우에만 distance 메서드 존재)
impl Point<f64> {
    fn distance_from_origin(&self) -> f64 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}

// 조건부 구현: T 가 Display + PartialOrd 일 때만
impl<T: std::fmt::Display + PartialOrd> Point<T> {
    fn print_larger(&self) {
        if self.x >= self.y {
            println!("x가 더 큼: {}", self.x);
        } else {
            println!("y가 더 큼: {}", self.y);
        }
    }
}

// 메서드 자체의 제네릭 매개변수
impl<T> Point<T> {
    fn mixup<U>(self, other: Point<U>) -> Point2<T, U> {
        Point2 { x: self.x, y: other.y }
    }
}

struct Point2<T, U> {
    x: T,
    y: U,
}

fn main() {
    let p = Point { x: 3.0, y: 4.0 };
    println!("{} {}", p.x(), p.distance_from_origin());
    p.print_larger();

    let int_p = Point { x: 1, y: 2 };
    // int_p.distance_from_origin(); // ❌ Point<i32> 에는 없는 메서드
    int_p.print_larger();

    let m = Point { x: 5, y: 10 }.mixup(Point { x: "hi", y: "c" });
    println!("{} {}", m.x, m.y);
}
```

# 4. 트레이트 바운드 문법

트레이트는 [05-트레이트](./05-트레이트.md)에서 자세히 다루고, 여기서는 제네릭과 함께 쓰는 문법만 봅니다.

```rust
use std::fmt::{Debug, Display};

// 1) 인라인 바운드
fn print_twice<T: Display>(item: T) {
    println!("{item} {item}");
}

// 2) 여러 바운드: +
fn show<T: Display + Clone>(item: &T) -> T {
    println!("{item}");
    item.clone()
}

// 3) where 절: 바운드가 길어질 때 가독성
fn complex<T, U>(t: &T, u: &U) -> String
where
    T: Display + Clone,
    U: Clone + Debug,
{
    format!("{t} / {u:?}")
}

// 4) impl Trait (매개변수 위치): 1) 의 축약형
fn notify(item: &impl Display) {
    println!("알림: {item}");
}

// 5) impl Trait (반환 위치): "구체 타입은 숨기고 이 트레이트를 구현한 무언가를 반환"
fn evens(limit: u32) -> impl Iterator<Item = u32> {
    (0..limit).filter(|n| n % 2 == 0)
}

fn main() {
    print_twice(7);
    let s = show(&String::from("복제"));
    println!("{}", complex(&s, &vec![1, 2]));
    notify(&3.14);
    println!("{:?}", evens(10).collect::<Vec<_>>());
}
```

```
impl Trait 매개변수 vs 제네릭
- fn f(a: impl Display, b: impl Display)  → a, b 가 서로 다른 타입이어도 됨
- fn f<T: Display>(a: T, b: T)            → a, b 가 같은 타입이어야 함
- 호출자가 f::<i32>(...) 처럼 타입을 지정하려면 제네릭 문법 필요
```

# 5. 터보피시 ::<>

타입 추론이 안 될 때 제네릭 타입을 직접 지정합니다.

```rust
fn main() {
    let a = "42".parse::<i32>().unwrap();
    let b: i32 = "42".parse().unwrap(); // 변수 타입으로 추론해도 됨

    let v = (1..=5).collect::<Vec<i32>>();
    let s = ["a", "b"].iter().map(|x| x.to_uppercase()).collect::<Vec<_>>(); // _ 는 추론에 맡김
    let joined: String = vec!["x", "y"].concat();

    let size = std::mem::size_of::<u64>();
    println!("{a} {b} {v:?} {s:?} {joined} {size}");
}
```

`::<>` 모양이 물고기 같아서 turbofish라고 부릅니다.

# 6. const 제네릭

타입뿐 아니라 **상수 값**도 제네릭 매개변수로 받을 수 있습니다. 배열 길이를 다룰 때 유용합니다.

```rust
#[derive(Debug)]
struct Matrix<const R: usize, const C: usize> {
    data: [[i32; C]; R],
}

impl<const R: usize, const C: usize> Matrix<R, C> {
    fn transpose(&self) -> Matrix<C, R> {
        let mut data = [[0; R]; C];
        for r in 0..R {
            for c in 0..C {
                data[c][r] = self.data[r][c];
            }
        }
        Matrix { data }
    }
}

fn sum_array<const N: usize>(arr: [i32; N]) -> i32 {
    arr.iter().sum()
}

fn main() {
    let m = Matrix { data: [[1, 2, 3], [4, 5, 6]] }; // Matrix<2, 3>
    let t = m.transpose();                           // Matrix<3, 2>
    println!("{t:?}");

    println!("{}", sum_array([1, 2, 3]));
    println!("{}", sum_array([1; 10]));
}
```

행렬 곱셈에서 차원이 맞지 않으면 **컴파일 타임에** 에러를 낼 수 있습니다.

# 7. 단형성화 (Monomorphization)

```rust
fn identity<T>(x: T) -> T {
    x
}

fn main() {
    let a = identity(5);
    let b = identity("hi");
    println!("{a} {b}");
}

// 컴파일러는 대략 아래와 같은 코드를 생성한다
// fn identity_i32(x: i32) -> i32 { x }
// fn identity_str(x: &str) -> &str { x }
```

```
장점: 가상 함수 호출 없이 인라인 최적화 가능 → 손으로 타입별로 짠 것과 같은 성능
단점: 사용하는 타입 조합이 많을수록 바이너리가 커지고 컴파일이 느려짐

대안: 트레이트 객체 (dyn Trait) → 코드 한 벌 + 런타임 동적 디스패치
      → 05-트레이트 문서에서 비교
```

## 정리

- 제네릭은 타입을 매개변수화해서 중복을 줄인다
- `T`로 무엇을 할 수 있는지는 트레이트 바운드(`T: Display + Clone`)로 명시해야 한다
- 바운드가 길면 `where` 절, 간단하면 `impl Trait`
- `impl<T> Point<T>`는 모든 T, `impl Point<f64>`는 특정 타입에만 메서드 추가
- 타입 추론이 안 되면 터보피시 `::<T>`
- `const N: usize`로 배열 길이 같은 값도 제네릭으로
- 단형성화 덕분에 제네릭은 런타임 비용이 없다
