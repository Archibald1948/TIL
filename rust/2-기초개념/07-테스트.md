# 테스트 - 언어에 내장된 테스트 도구

## 들어가며

JS/TS에서는 Jest, Vitest, Mocha 중 무엇을 쓸지 고르고 설정해야 하지만, Rust는 **테스트 프레임워크가 언어와 Cargo에 내장**되어 있습니다.

```
JS/TS                         Rust
npm i -D vitest               (설치 필요 없음)
describe / it                 mod tests / #[test]
expect(a).toBe(b)             assert_eq!(a, b)
expect(fn).toThrow()          #[should_panic]
*.test.ts 파일                 같은 파일 안의 #[cfg(test)] mod tests
e2e / integration 폴더         tests/ 디렉터리
(없음)                         문서 주석 속 코드가 테스트로 실행 (doctest)
```

타입 시스템이 많은 버그를 잡아주지만, **로직이 의도대로 동작하는지**는 여전히 테스트로 확인해야 합니다.

# 1. 단위 테스트 기본

## 첫 테스트

```bash
cargo new adder --lib
```

```rust
// src/lib.rs
pub fn add(left: u64, right: u64) -> u64 {
    left + right
}

#[cfg(test)]           // cargo test 할 때만 컴파일
mod tests {
    use super::*;      // 부모 모듈의 아이템 가져오기 (비공개 함수도 테스트 가능)

    #[test]
    fn it_works() {
        let result = add(2, 2);
        assert_eq!(result, 4);
    }
}
```

```bash
$ cargo test
running 1 test
test tests::it_works ... ok

test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

- 테스트 함수는 panic하면 실패, panic 없이 끝나면 성공입니다.
- 각 테스트는 **별도 스레드에서 병렬로** 실행됩니다.

## assert 매크로

```rust
#[derive(Debug, PartialEq)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

pub fn greeting(name: &str) -> String {
    format!("안녕하세요 {name}님")
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn larger_can_hold_smaller() {
        let larger = Rectangle { width: 8, height: 7 };
        let smaller = Rectangle { width: 5, height: 1 };
        assert!(larger.can_hold(&smaller));
        assert!(!smaller.can_hold(&larger));
    }

    #[test]
    fn equality() {
        assert_eq!(Rectangle { width: 1, height: 2 }, Rectangle { width: 1, height: 2 });
        assert_ne!(1 + 1, 3);
    }

    #[test]
    fn greeting_contains_name() {
        let result = greeting("철수");
        // 실패 시 출력할 커스텀 메시지
        assert!(result.contains("철수"), "인사말에 이름이 없음: `{result}`");
    }

    #[test]
    fn float_compare() {
        let x = 0.1 + 0.2;
        // 부동소수점은 == 대신 오차 범위로
        assert!((x - 0.3_f64).abs() < f64::EPSILON * 10.0);
    }
}
```

`assert_eq!`/`assert_ne!`로 비교하는 값은 `PartialEq`와 `Debug`를 구현해야 합니다. (실패 시 두 값을 출력하기 때문)

```
---- tests::equality stdout ----
thread 'tests::equality' panicked at src/lib.rs:10:9:
assertion `left == right` failed
  left: 4
 right: 5
```

## panic 테스트

```rust
pub struct Guess {
    value: i32,
}

impl Guess {
    pub fn new(value: i32) -> Guess {
        if !(1..=100).contains(&value) {
            panic!("Guess 값은 1 이상 100 이하여야 합니다. 입력값: {value}");
        }
        Guess { value }
    }

    pub fn value(&self) -> i32 {
        self.value
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    #[should_panic(expected = "1 이상 100 이하")] // panic 메시지에 이 문자열이 포함되어야 통과
    fn greater_than_100() {
        Guess::new(200);
    }

    #[test]
    fn valid_value() {
        assert_eq!(Guess::new(50).value(), 50);
    }
}
```

## Result를 반환하는 테스트

`?`를 쓸 수 있어서 편합니다.

```rust
pub fn parse_pair(s: &str) -> Result<(i32, i32), String> {
    let (a, b) = s.split_once(',').ok_or("쉼표 없음")?;
    let a = a.trim().parse::<i32>().map_err(|e| e.to_string())?;
    let b = b.trim().parse::<i32>().map_err(|e| e.to_string())?;
    Ok((a, b))
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn parses_pair() -> Result<(), String> {
        let (a, b) = parse_pair("3, 4")?;
        assert_eq!(a + b, 7);
        Ok(())
    }

    #[test]
    fn rejects_invalid() {
        assert!(parse_pair("3;4").is_err());
        // 에러 내용까지 검사
        assert!(matches!(parse_pair("x,1"), Err(msg) if msg.contains("invalid digit")));
    }

    #[test]
    #[ignore = "느린 테스트: cargo test -- --ignored 로 실행"]
    fn expensive() {
        std::thread::sleep(std::time::Duration::from_secs(1));
    }
}
```

# 2. cargo test 옵션

```bash
cargo test                          # 전체
cargo test greeting                 # 이름에 greeting 이 포함된 테스트만
cargo test tests::valid_value       # 경로로 지정
cargo test -- --exact tests::valid_value

cargo test -- --nocapture           # 성공한 테스트의 println! 도 출력 (기본은 숨김)
cargo test -- --test-threads=1      # 순차 실행 (파일/전역 상태를 공유하는 테스트)
cargo test -- --ignored             # #[ignore] 테스트만
cargo test -- --include-ignored     # 전부

cargo test --lib                    # 단위 테스트만
cargo test --doc                    # doctest 만
cargo test --test integration       # tests/integration.rs 만
cargo test --release                # 최적화 빌드로
```

`--` 앞은 cargo 옵션, 뒤는 테스트 바이너리 옵션입니다.

# 3. 테스트 구성

## 단위 테스트 vs 통합 테스트

```
단위 테스트 (unit test)
- src/ 안, 테스트 대상과 같은 파일의 #[cfg(test)] mod tests
- 비공개 함수도 테스트 가능
- 작은 단위를 격리해서 검사

통합 테스트 (integration test)
- tests/ 디렉터리 (파일 하나가 별도 크레이트로 컴파일됨)
- 라이브러리의 공개 API 만 사용 가능 (외부 사용자 입장)
- 여러 모듈이 함께 잘 동작하는지 검사
```

```
adder/
├── Cargo.toml
├── src/
│   └── lib.rs
└── tests/
    ├── common/
    │   └── mod.rs        # 공유 헬퍼 (테스트 파일로 인식되지 않게 mod.rs 로)
    └── integration_test.rs
```

```rust
// (컴파일 검증 제외) - tests/ 디렉터리 예시

// tests/common/mod.rs
pub fn setup() -> Vec<u64> {
    vec![1, 2, 3]
}

// tests/integration_test.rs
use adder::add;   // 크레이트 이름으로 가져옴

mod common;

#[test]
fn adds_all() {
    let nums = common::setup();
    let total = nums.iter().fold(0, |acc, &n| add(acc, n));
    assert_eq!(total, 6);
}
```

> 바이너리 크레이트(`src/main.rs`만 있는 경우)는 통합 테스트에서 가져올 수 없습니다. 로직을 `src/lib.rs`로 옮기고 `main.rs`는 얇게 유지하세요.

## 문서 테스트 (doctest)

````rust
/// 두 수를 더합니다.
///
/// # Examples
///
/// ```
/// let sum = adder::add(1, 2);
/// assert_eq!(sum, 3);
/// ```
///
/// # Panics
///
/// 이 함수는 panic 하지 않습니다.
pub fn add(left: u64, right: u64) -> u64 {
    left + right
}
````

`cargo test`가 문서 주석의 코드 블록을 실제로 컴파일하고 실행합니다. **문서가 코드와 어긋나는 것을 막아주는** Rust의 좋은 문화입니다.

````
```ignore         → 실행하지 않음
```no_run         → 컴파일만 하고 실행 안 함 (네트워크 호출 등)
```should_panic   → panic 해야 통과
```compile_fail   → 컴파일 에러가 나야 통과
# 로 시작하는 줄  → 문서에는 숨기고 테스트에는 포함
````

# 4. 테스트하기 좋은 코드: 트레이트로 의존성 분리

외부 의존성(시간, 네트워크, DB)은 트레이트로 추상화하면 테스트에서 가짜 구현을 넣을 수 있습니다.

```rust
pub trait Clock {
    fn now_hour(&self) -> u32;
}

pub struct SystemClock;
impl Clock for SystemClock {
    fn now_hour(&self) -> u32 {
        // 실제 구현 (예시로 고정값)
        12
    }
}

pub fn greeting_by_time(clock: &impl Clock) -> &'static str {
    match clock.now_hour() {
        5..=11 => "좋은 아침",
        12..=17 => "좋은 오후",
        _ => "좋은 저녁",
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    struct FakeClock(u32);
    impl Clock for FakeClock {
        fn now_hour(&self) -> u32 {
            self.0
        }
    }

    #[test]
    fn morning() {
        assert_eq!(greeting_by_time(&FakeClock(9)), "좋은 아침");
    }

    #[test]
    fn evening() {
        assert_eq!(greeting_by_time(&FakeClock(22)), "좋은 저녁");
    }

    #[test]
    fn real_clock_works() {
        assert!(!greeting_by_time(&SystemClock).is_empty());
    }
}
```

# 5. 비동기 테스트와 생태계 도구

```rust
// (컴파일 검증: 외부 크레이트) tokio 필요
async fn fetch_number() -> u32 {
    42
}

#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn async_works() {
        assert_eq!(fetch_number().await, 42);
    }
}
```

| 도구 | 용도 |
|---|---|
| `cargo-nextest` | 더 빠르고 출력이 깔끔한 테스트 러너 |
| `pretty_assertions` | `assert_eq!` 실패 시 컬러 diff |
| `insta` | 스냅샷 테스트 (Jest snapshot 과 유사) |
| `proptest` / `quickcheck` | 속성 기반 테스트 (무작위 입력 생성) |
| `mockall` | 트레이트 기반 목(mock) 자동 생성 |
| `criterion` | 통계적 벤치마크 |
| `cargo-llvm-cov` / `cargo-tarpaulin` | 코드 커버리지 |
| `miri` | unsafe 코드의 정의되지 않은 동작(UB) 검출 |

## 정리

- `#[test]` 함수가 panic하지 않으면 통과, `assert!`/`assert_eq!`/`assert_ne!`로 검사
- `#[should_panic(expected = "...")]`, `Result` 반환 테스트, `#[ignore]` 지원
- 단위 테스트는 같은 파일의 `#[cfg(test)] mod tests`, 통합 테스트는 `tests/`
- 문서 주석의 예제 코드는 doctest로 실행되어 문서와 코드가 어긋나지 않게 해준다
- 외부 의존성은 트레이트로 분리하면 가짜 구현으로 쉽게 테스트할 수 있다
- `cargo test 이름`으로 필터링, `-- --nocapture`로 출력 보기
