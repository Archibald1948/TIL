# 소유권 (Ownership) - GC 없이 메모리를 안전하게

## 들어가며

소유권은 Rust의 **가장 핵심적이고 독특한 개념**입니다. 이것만 이해하면 Rust의 절반은 이해한 셈입니다.

프로그래밍 언어가 메모리를 관리하는 방식은 크게 세 가지입니다.

```
1. 가비지 컬렉터(GC)   → JS, Java, Go, Python
   - 런타임이 안 쓰는 메모리를 주기적으로 찾아 해제
   - 편하지만 GC 일시정지, 메모리 오버헤드 발생

2. 수동 관리           → C, C++
   - malloc/free, new/delete 를 개발자가 직접
   - 빠르지만 해제 누락(누수), 이중 해제, 해제 후 사용(use-after-free) 버그

3. 소유권 시스템        → Rust
   - 컴파일러가 규칙을 검사해서 "언제 해제할지"를 컴파일 타임에 결정
   - 런타임 비용 0 + 메모리 안전성
```

# 1. 스택과 힙

소유권을 이해하려면 먼저 데이터가 어디에 저장되는지 알아야 합니다.

```
스택 (Stack)
- 크기가 컴파일 타임에 고정된 데이터 (i32, bool, [i32; 3], 튜플 등)
- 함수 호출 시 쌓이고 반환 시 자동으로 사라짐
- 매우 빠름

힙 (Heap)
- 크기가 실행 중에 정해지거나 변하는 데이터 (String, Vec, Box 등)
- 할당자에게 공간을 요청하고 포인터를 받음
- 누군가 해제해야 함 ← 이걸 누가 언제 하느냐가 문제
```

`String`은 이렇게 생겼습니다.

```
let s1 = String::from("hello");

      스택 (s1)                      힙
┌──────────┬───────┐         ┌───────┬───────┐
│ ptr      │ ──────┼────────▶│ index │ value │
│ len      │ 5     │         │ 0     │ h     │
│ capacity │ 5     │         │ 1     │ e     │
└──────────┴───────┘         │ 2     │ l     │
                             │ 3     │ l     │
                             │ 4     │ o     │
                             └───────┴───────┘
```

# 2. 소유권 규칙 세 가지

```
1. Rust의 각 값은 소유자(owner)라는 변수를 가진다
2. 한 번에 소유자는 딱 하나다
3. 소유자가 스코프를 벗어나면 값은 버려진다(drop)
```

## 스코프와 drop

```rust
fn main() {
    {
        let s = String::from("hello"); // s 가 유효해짐, 힙 할당
        println!("{s}");
    } // 스코프 끝 → Rust가 자동으로 drop(s) 호출 → 힙 메모리 해제

    // println!("{s}"); // ❌ s 는 이미 스코프 밖
}
```

C++의 RAII와 같은 패턴입니다. 파일 핸들, 락, 소켓 같은 자원도 같은 방식으로 자동 정리됩니다.

# 3. 이동 (Move)

## 대입하면 소유권이 넘어간다

```rust
// ❌ 컴파일 에러 예제
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;          // s1 의 소유권이 s2 로 "이동"

    println!("{s1}");     // s1 은 더 이상 유효하지 않음
    println!("{s2}");
}
```

```
error[E0382]: borrow of moved value: `s1`
 --> src/main.rs:6:16
  |
3 |     let s1 = String::from("hello");
  |         -- move occurs because `s1` has type `String`, which does not implement the `Copy` trait
4 |     let s2 = s1;          // s1 의 소유권이 s2 로 "이동"
  |              -- value moved here
5 |
6 |     println!("{s1}");     // s1 은 더 이상 유효하지 않음
  |                ^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
```

왜 이렇게 할까요? `let s2 = s1;`은 스택의 (ptr, len, capacity)만 복사합니다. 만약 둘 다 유효하다면 스코프가 끝날 때 **같은 힙 메모리를 두 번 해제(double free)**하게 됩니다. Rust는 s1을 무효화해서 이 문제를 원천 차단합니다.

```
let s2 = s1;

 s1 (무효)                          힙
┌──────────┬───┐              ┌─────────┐
│ ptr      │ ╳ │        ┌────▶│ "hello" │
│ len      │ 5 │        │     └─────────┘
│ capacity │ 5 │        │
└──────────┴───┘        │
 s2                     │
┌──────────┬───┐        │
│ ptr      │ ──┼────────┘
│ len      │ 5 │
│ capacity │ 5 │
└──────────┴───┘
```

JS와 비교:

```js
// JS: 둘 다 같은 객체를 가리키고 둘 다 사용 가능 (GC가 나중에 정리)
const a = { name: "hello" };
const b = a;
console.log(a, b);
```

## 함수 호출도 이동

```rust
fn takes_ownership(s: String) {
    println!("받음: {s}");
} // 여기서 s drop

fn gives_ownership() -> String {
    String::from("새 문자열") // 호출자에게 소유권 이동
}

fn takes_and_gives_back(s: String) -> String {
    s
}

fn main() {
    let s = String::from("hello");
    takes_ownership(s);
    // println!("{s}"); // ❌ s 는 함수로 이동됨

    let s1 = gives_ownership();
    let s2 = String::from("world");
    let s3 = takes_and_gives_back(s2); // s2 이동 → s3 로 돌려받음
    println!("{s1} {s3}");
}
```

매번 소유권을 넘겼다 돌려받는 건 번거롭습니다. 그래서 **참조(빌림)**가 있습니다. → [02-참조와-빌림](./02-참조와-빌림.md)

# 4. 복사 (Copy)와 복제 (Clone)

## Copy 타입은 이동하지 않고 복사된다

```rust
fn main() {
    let x = 5;
    let y = x;           // 정수는 스택에만 있으므로 그냥 비트 복사
    println!("{x} {y}"); // 둘 다 사용 가능

    let t = (1, 2.0, 'a');
    let u = t;
    println!("{t:?} {u:?}");
}
```

`Copy` 트레이트를 구현한 타입:
- 모든 정수, 부동소수점, `bool`, `char`
- `Copy` 타입으로만 이루어진 튜플, 배열
- 불변 참조 `&T`
- 직접 만든 타입도 모든 필드가 Copy면 `#[derive(Clone, Copy)]` 가능

`String`, `Vec`, `Box` 처럼 **힙 자원을 소유하거나 `Drop`을 구현한 타입은 Copy가 될 수 없습니다.**

## clone - 명시적 깊은 복사

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone(); // 힙 데이터까지 복사 (비용이 드는 작업임이 코드에 드러남)
    println!("{s1} {s2}");

    let v1 = vec![1, 2, 3];
    let mut v2 = v1.clone();
    v2.push(4);
    println!("{v1:?} {v2:?}");
}
```

```
Copy  → 암묵적, 비트 단위 복사, 항상 저렴
Clone → 명시적 .clone(), 임의의 복사 로직, 비쌀 수 있음
```

> 초보 때 컴파일 에러를 피하려고 `.clone()`을 남발하게 되는데, 처음엔 괜찮습니다. 익숙해지면 참조로 바꾸면 됩니다.

# 5. 부분 이동과 이동 후 재할당

```rust
#[derive(Debug)]
struct Person {
    name: String,
    age: u32,
}

fn main() {
    let p = Person { name: String::from("Kim"), age: 30 };

    let name = p.name;     // name 필드만 이동 (부분 이동)
    let age = p.age;       // u32 는 Copy
    println!("{name} {age} {}", p.age); // p.age 는 여전히 사용 가능
    // println!("{p:?}");  // ❌ p 전체는 사용 불가

    let mut s = String::from("a");
    let t = s;             // 이동
    s = String::from("b"); // 이동된 변수에 새 값을 넣으면 다시 사용 가능
    println!("{s} {t}");
}
```

## 컬렉션에서 꺼낼 때

```rust
fn main() {
    let v = vec![String::from("a"), String::from("b")];

    // let first = v[0]; // ❌ cannot move out of index of `Vec<String>`

    let first = &v[0];               // 1) 빌리기
    let cloned = v[0].clone();       // 2) 복제
    println!("{first} {cloned}");

    let mut v = v;
    let taken = std::mem::take(&mut v[1]); // 3) 기본값("")과 바꿔치기
    let removed = v.remove(0);             // 4) Vec 에서 제거하며 소유권 획득
    println!("{taken} {removed} {v:?}");
}
```

# 6. Drop 순서 확인하기

```rust
struct Noisy(&'static str);

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("drop: {}", self.0);
    }
}

fn main() {
    let _a = Noisy("a");
    let _b = Noisy("b");
    {
        let _c = Noisy("c");
        println!("안쪽 스코프 끝");
    }
    let d = Noisy("d");
    drop(d); // 명시적으로 일찍 drop (std::mem::drop)
    println!("main 끝");
}
// 출력:
// 안쪽 스코프 끝
// drop: c
// drop: d
// main 끝
// drop: b   ← 변수는 선언의 역순으로 drop
// drop: a
```

## 정리

- 값마다 소유자는 하나, 소유자가 스코프를 벗어나면 자동 해제(drop)
- 힙 데이터를 가진 값은 대입/함수 인자 전달 시 **이동**하고 원래 변수는 무효화
- 스택에만 있는 `Copy` 타입은 이동 대신 복사
- 깊은 복사는 `.clone()`으로 명시적으로
- 이 규칙 덕분에 GC 없이도 double free, use-after-free가 컴파일 단계에서 막힌다
